# Changelog

All notable changes to `broadcast-dash` will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]
### Added
- The model now carries the elements it used to keep only as `MpdFeatures` flags, and `Mpd::to_xml` writes them in XSD order, so parse -> write -> parse keeps their content (#2404): `EventStream` and its `StreamEvent` children (`Period::event_streams`, ISO/IEC 23009-1 5.10.2: `schemeIdUri`, `value`, `timescale`, `presentationTimeOffset`, `xlink`, and per Event `presentationTime`, `duration`, `id`, `status`, `messageData`, text body and descriptor/`ServiceDescription` children), `ProducerReferenceTime` (`producer_reference_times` on AdaptationSet and Representation, 5.12, with its `UTCTiming` child), `Resync` (`resyncs`, 5.3.13), `PatchLocation` (`Mpd::patch_locations`, 5.15), `Preselection` (`Period::preselections`, 5.3.11) and `ContentSteering` (`Mpd::content_steering`). `Mpd::has_event_streams`, `has_preselections` and `has_patch_location` replace the removed flags.
- `Unsupported::EventXmlPayload` and `StreamEvent::unsupported`: an `Event` whose content is XML (`SelectionInfo`, `InsertPresentation`, `ReplacePresentation`, a foreign-namespace payload such as an SCTE 35 `Signal`) still parses, but `Mpd::to_xml` returns that typed error instead of writing the Event without its payload.
- `Mpd::to_xml`: the MPD writer, the exact inverse of the parser (quick-xml events, no hand-built XML). Every real MPD in the corpus round-trips parse -> write -> parse, a model with every field set round-trips, and the writer reproduces every current `transmux` MPD golden byte-identical; the model gained `cenc:pssh`, `InbandEventStream`, `codingDependency` and `ServiceDescription` (`Latency`, `PlaybackRate`), and `ByteRange` implements `Display` (#2355).
- Two runnable examples (`parse_mpd`, `build_mpd`) under `examples/`, plus a `broadcast_dash_round_trip` fuzz target covering parse -> `to_xml` -> re-parse.
- The MPD read side, extracted from `dash-runtime` so a consumer that only needs manifest syntax does not pull in a client: the `Mpd`/`Period`/`AdaptationSet`/`Representation` model with its three Segment addressing layers, `Mpd::parse`/`parse_with` over the shared bounded `broadcast_common::xml` reader under `limits::Limits`, the descriptor scheme vocabulary and `Role`, the attribute-inheritance rules (`inherit`), the `SegmentTemplate` grammar (`template`), the `UTCTiming` scheme identity (`utc_timing`), the `xs:duration` reader moved out of `transmux` (`duration`) and the `xs:dateTime`/NTP readers (`xs_datetime`) (#2355).

### Removed
- `MpdFeatures::patch_location`, `event_stream`, `preselection`, `producer_reference_time`, `content_steering`, `resync` and `MpdFeatures::written` (breaking): the elements are modelled, so the flags are redundant and a parse -> write -> parse round trip no longer clears anything.

### Fixed
- `EventStream` dropped its `RequestParam` children on `parse -> to_xml`. They are now modelled (`EventStream::request_params`, `RequestParam`: the `UrlQueryInfoType` attributes plus `includeInRequests`, `headerParamSource`, `sameOriginOnly`, `header` and `xlink`) and written in XSD order.
- `Preselection` kept only `@id`, `@preselectionComponents`, `@lang`, `@order` and the descriptor children, so `parse -> to_xml` silently dropped the rest of the XSD `RepresentationBaseType` (the earlier "keeps their content" entry overstated this). It now carries `tag`, `selection_priority`, `start_with_sap`, `scan_type`, `segment_profiles`, `container_profiles`, `maximum_sap_period`, `frame_packings`, `content_protections`, `output_protection`, `inband_event_streams`, `group_labels`, `labels`, `producer_reference_times` and `resyncs`; the four children without a model (`Switching`, `RandomAccess`, `ContentPopularityRate`, `SegmentSequenceProperties`) set `Preselection::unsupported` and `Mpd::to_xml` refuses with the new `Unsupported::RepresentationBaseChild` instead of dropping them.
- `Mpd::to_xml` wrote child elements in orders the ISO/IEC 23009-1 ed6 schema forbids (`ServiceDescription` before `BaseURL`, `EssentialProperty` before `Period`, `SegmentBase` before `BaseURL`/`ContentProtection` in a Representation, `AudioChannelConfiguration` after `Role`), so a parsed real MPD was not valid on the way out. Children now follow the XSD sequence for `MPD`, `Period`, `AdaptationSet` and `Representation`, and a new test validates every corpus MPD (parse -> write) with `xmllint --schema`.
- `Mpd::to_xml` no longer writes empty `PatchLocation`, `EventStream`, `Preselection`, `ProducerReferenceTime`, `ContentSteering` and `Resync` elements at the end of `<MPD>` for the matching `features` flags; those elements were fabricated and invalid where they appeared. The six flags are documented as read-only (the model keeps no element for them), so a parse -> write -> parse clears them.
- `Mpd::to_xml` wrote `availabilityTimeOffset="inf"` for an infinite value on `SegmentBase`/`SegmentList`/`SegmentTemplate`, which neither the parser nor xs:double accepts, and routed finite values through a saturating `as i64`; one formatter now writes `INF`/`-INF`/the decimal everywhere, `BaseURL` included.
