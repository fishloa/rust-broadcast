# Changelog

All notable changes to `broadcast-client` will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]
### Changed
- BREAKING: `ErrorKind::TrackIdReserved`, `ErrorKind::TrackDropped` and `ErrorKind::UnknownRenderedTrack` carry their id as `transmux::TrackId` (was `u32`), the type `Session::set_rendered_tracks` and the rest of the crate already take, so an event consumer no longer converts and `0` is a documented `TrackId::new(0)` (the unnamed fMP4 track), not a bare sentinel. Migration: wrap a construction with `TrackId::new(id)` and read a matched id back with `.value()`; compare against `TrackId::new(..)` rather than an integer (#2651).
- BREAKING: `Action::UdpBind` is split into `UdpBind { conn, addr: SocketAddr, options }` (a literal local/multicast receive address) and `UdpConnect { conn, host: url::Host, port, options }` (an SRT peer the host resolves first), so the session never resolves a name and a receive bind always carries a `SocketAddr`; the `mode` field is gone (the variant names the mode). A UDP/RTP URL whose host is a name rather than a literal IP is the new typed `Error::DatagramHostNotIp { scheme, host }` at open (was a stringly `InvalidUrl`). Migration: match `UdpBind` for a receive bind (`addr.ip()`/`addr.port()` in place of `host`/`port`, drop the `mode` arm) and `UdpConnect` for the SRT caller (its `host` is a `url::Host`), and a host that read `mode` reads the variant instead. `UdpConfig::validate` no longer rejects a zero receive buffer: `UdpOptions::recv_buffer_bytes` is now `Option<NonZeroU32>` (see `broadcast-common`), so the zero request is unrepresentable (#2654 B5).
- BREAKING: `Action::HttpRequest::byte_range` is `Option<broadcast_common::range::ByteSpan>` (offset + non-zero length; `range_header()` is the `Range` field value) instead of `Option<(u64, u64)>` documented as (offset, length) (#2655 C1). The DASH and HLS sources follow the HLS/DASH client action changes (`url::Url` URLs, `ByteSpan` ranges).
- BREAKING: `Session::open` and `Session::open_with_memory` take `url: url::Url` (was `&str`): the session no longer parses the URL, so `Error::InvalidUrl` now only ever carries a validation failure from a part it trusted the caller to parse. `Error::UnsupportedScheme(String)` is `Error::UnsupportedScheme { scheme }` (a named field). Migration: `Session::open(url, ..)` becomes `Session::open(Url::parse(url)?, ..)` (or an already-parsed `Url`), and `UnsupportedScheme(s)` becomes `UnsupportedScheme { scheme: s }` (#2654).
- BREAKING: `Action::HttpRequest` carries `method: http::Method`, `url: url::Url` and `headers: http::HeaderMap` (was `String`, `String` and a `Vec<(String, String)>`). Migration: `Action::HttpRequest { method, url, headers, .. }` now binds `method.as_str()`, a `Url` (use `.to_string()`/`.path()`/…) and a `HeaderMap` (iterate `.iter()`; a value reads via `v.to_str()`); a host constructing the action uses `http::Method::GET`, an existing `Url`, and a `HeaderMap` (#2654).
- BREAKING: `ConnId` is a `#[repr(transparent)]` newtype over `u32` (was `pub type ConnId = u32`), with `new`/`get`/`Display`. Every action `conn`, and `Session::on_response`/`on_data`/`on_closed`/`on_connected``conn`, now takes `ConnId`, so a connection id cannot be passed where a track id or another `u32` belongs. Migration: wrap a host-side id with `ConnId::new(id)` and read it back with `.0`/`get()` (#2654).
- BREAKING: `TransportError` is an enum (`Refused`, `Reset`, `TimedOut`, `Dns { host }`, `Tls { reason }`, `Eof`, `Other { reason }`, `#[non_exhaustive]`, `name()`/`reason()`/`Display`) instead of `String`, so `Session::on_closed`'s error and the host's metrics can tell a TLS failure from a reset without matching on text. Migration: `session.on_closed(conn, Some(e.to_string()), now)` becomes `session.on_closed(conn, Some(TransportError::from(e.to_string())), now)` (or `TransportError::Reset` for a known kind); a `None` is unchanged. The session itself only asks whether an error is present, so behaviour is unchanged (#2654).
### Removed
- BREAKING: the `tshttp` module (with `TsHttpClient`, `TsHttpPolicy`, `Action`, `Event` and `ConfigError`) and `TsHttpSource` are no longer public: TS over HTTP has one public entry point, `Session`. Its configuration stays nameable because `Config::ts_http` is that type; it is re-exported as `broadcast_client::TsHttpConfig`, and `StarveKind` (carried by `Event::Starved`) stays re-exported at the crate root. Migration: drive TS over HTTP through `Session` with `Config { kind: SourceKind::TsHttp, .. }`, and type the stall policy as `TsHttpConfig`. The internal engine's integration tests moved into the crate's own test modules (same assertions), the two `tshttp` examples, which exercised the engine directly, are deleted, and the `tshttp_runtime` fuzz target's loop now drives a `Session` (the former target would have had to call crate-private types) (#2665).
- The TS-over-HTTP engine's internal `Event::NotFound { status }` is `Event::NotFound`: nothing read its status (the session reports the public `Status::NotFound`), so the field went with the type. Not a public change now that the engine is crate-private (#2665).
- BREAKING: the `Hint` alias for `buffering_runtime::Hint`; the one name is `BufferHint`, matching `BufferInput`, `BufferEvent` and `BufferStats`. Migration: rename every `Hint` import and match to `BufferHint` (#2665).
- BREAKING: the SRT caller's two millisecond timeout fields, `SrtConfig::handshake_timeout_ms` and `SrtConfig::peer_idle_timeout_ms`, and the `SrtConfig::timeouts()`/`with_timeouts` converters that translated them to and from `broadcast_common::timeouts::Timeouts`. One `timeouts: Timeouts` field now holds both bounds (`handshake` the handshake, `read_idle` the peer idle), as `srt_runtime::io::SocketConfig` does, so the value has one representation and one unit. Migration: `c.srt.handshake_timeout_ms = 1_000` -> `c.srt.timeouts = c.srt.timeouts.with_handshake(Duration::from_secs(1))` (likewise `read_idle` for the peer idle), and the `DEFAULT_HANDSHAKE_TIMEOUT_MS`/`DEFAULT_PEER_IDLE_TIMEOUT_MS` constants are `DEFAULT_HANDSHAKE_TIMEOUT`/`DEFAULT_PEER_IDLE_TIMEOUT`, now `Duration`s. A zero bound used to be raised to one millisecond; it is now `Error::InvalidConfig { field: "srt.timeouts.handshake" }` (or `srt.timeouts.read_idle`), the same for every other zero timeout in `Config` (#2660).
### Fixed
- A deadline that does not fit the clock is no deadline, not the last representable instant: RTSP, SRT, UDP/RTP and TS-over-HTTP source timers and the session's TS wake are computed with `Timestamp::checked_add`, so a session started near the end of its clock goes idle instead of waking on every poll forever (#2653).
### Changed
- BREAKING: `playout::PlayoutConfig` and `tshttp::Config` are now `#[non_exhaustive]`; build them with `Default::default()` + `with_*` (e.g. `with_vod_start_lead_us`, `with_stall_reconnect_ms`, `with_backoff_ms`) instead of struct literals (#2664).
- BREAKING: every "now" the session takes is a `broadcast_common::stage::Timestamp` (monotonic microseconds from the host's own epoch, the type `media-plane` and `smooth-runtime` already take) instead of `now_us: u64` microseconds: `Session::open`, `open_with_memory`, `poll`, `on_response`, `on_data`, `on_closed`, `reconnect`, `on_playback_position`, `set_rendered_tracks` and `set_wall_clock`, and the TS-over-HTTP `TsHttpClient`/`TsHttpPolicy` entry points (whose own clock is milliseconds, so `next_deadline` returns a `Timestamp` too). Migration: `Session::open(url, config, now_us)` becomes `Session::open(url, config, Timestamp::from_micros(now_us))` (or `Timestamp::from_nanos`/`from_millis` if that is what the host has: `from_nanos` truncates to the microsecond); one clock now drives HLS, DASH, Smooth, RTSP and TS-over-HTTP.
- BREAKING: `Action::WakeAt(u64)` carries a `Timestamp`: compare it with the host's clock directly instead of a `u64` of microseconds.
- BREAKING: `Config::request_timeout_us`, `segment_timeout_us`, `segment_inactivity_timeout_us` and `hls_key_timeout_us` are `Duration` fields (`request_timeout`, `segment_timeout`, `segment_inactivity_timeout`, `hls_key_timeout`), as are the `DEFAULT_*_TIMEOUT_US` constants (`DEFAULT_REQUEST_TIMEOUT` etc.).
- BREAKING: `Config::backoff_ms: Vec<u64>` and `Config::backoff_cap_ms: u64` are one `broadcast_common::backoff::BackoffSteps` (`steps: Vec<Duration>`, `cap: Duration`) field, `Config::backoff`; `DEFAULT_BACKOFF_MS`/`DEFAULT_BACKOFF_CAP_MS` become `DEFAULT_BACKOFF_STEPS`/`DEFAULT_BACKOFF_CAP`. An empty step table is the cap from the first attempt, and an entry of zero is no longer raised to one millisecond (a zero step is a zero delay, as `RetrySchedule::from_steps` has always documented).
- `tshttp::Config` fields are `Duration` too (`start_timeout`, `stall_notice`, `stall_reconnect`, `backoff: BackoffSteps`, `min_reconnect_interval`), replacing the `_ms` fields.
- Dev-dependency `rtsp-types` 0.1 to 0.2, following `rtsp-runtime`.
- BREAKING: `broadcast_client::SrtConfig` is `broadcast_client::SrtCallerConfig`: it configures the sans-IO SRT caller only (what it sends and how long it waits), and it no longer shares a name with `srt_runtime::io::SrtSocketConfig` (the tokio adapter's socket settings), which `multimux` imports alongside it. Migration: every `SrtConfig` becomes `SrtCallerConfig`, including `Config::srt`'s type (#2660).
- BREAKING: `Config::with_timeouts` stores SRT's `Timeouts` verbatim instead of flooring each bound at one millisecond; a zero bound is rejected by `Config::validate`/`Session::open`.
- BREAKING: `UdpConfig`'s `interface`, `interface_index`, `source` and `recv_buffer_bytes` fields are replaced by one `options: broadcast_common::net::UdpOptions`, and `MulticastJoin` is now the shared `broadcast_common::net::MulticastJoin` (`group`, `interface: MulticastInterface`, `source`). The session fills the join's group from the URL, so `interface` + `interface_index` "never set together" is unrepresentable. Migration: `cfg.udp.interface = Some(ip); cfg.udp.source = Some(src);` becomes `cfg.udp.options = cfg.udp.options.with_join(MulticastJoin::new(group).with_interface(MulticastInterface::V4(ip)).with_source(src));`, `cfg.udp.interface_index = Some(i)` becomes `.with_interface(MulticastInterface::V6Index(i))` (set on `options.join`), and `cfg.udp.recv_buffer_bytes = Some(n)` becomes `cfg.udp.options = cfg.udp.options.with_recv_buffer_bytes(n)`. `broadcast_client::MulticastJoin` is no longer re-exported from the crate root.
- BREAKING: `Action::UdpBind` carries `options: broadcast_common::net::UdpOptions` (the `multicast` and `recv_buffer_bytes` fields are gone): a host applies `options` as one unit, so `SO_REUSEADDR`/`SO_REUSEPORT` ride along with the join (multimux now does).
- The config-error fields name the new shape: a join interface of the wrong family is `udp.options.join.interface`, a bad source is `udp.options.join.source`, a join on a unicast URL is `udp.options.join` (#2663).
### Fixed
- Every deadline the TS-over-HTTP source arms is `Timestamp::checked_add`, never a saturating one, and its policy now runs on `Timestamp`/`Duration` end to end (it kept a private millisecond clock under the migrated public API). An in-flight request's `WakeAt` and its bookkeeping deadline come from one computation (they were two, one saturating and one checked); a reconnect, a stall notice, a start timeout and a session wake whose instant does not fit the clock arm nothing, because a saturated deadline reads as due now on every poll forever, and a reconnect whose backoff would end past the end of the clock is not acted on at all (`TsHttpClient::action_ready`), so the source stays in its backoff instead of reopening forever. BREAKING: the crate-private `tshttp::Action::Reconnect` carries `after: Duration` (`after_ms: u64` before); `broadcast_client::fetch::{retry_after_us, HEALTHY_CONNECTION_US, ReconnectTimer}` are unchanged (#2685).
- The crate's 27 MHz arithmetic reads `broadcast_common::clock33::PCR_HZ`/`PCR_TIMESCALE` instead of a private copy of the constants (a `core::unreachable!()` const fallback in the buffer's clock and a `27_000_000` in the join lead), so there is one 27 MHz clock rate in the workspace and no panic site for a constant that cannot fail (#2700).
- A malformed multicast join (an interface of the other family, a source that is not a unicast address of the group's family) is a typed config error at `Session::open` rather than reaching the host (#2663).
- `Config::with_timeouts` maps SRT exactly as `SrtConfig::with_timeouts` does (`handshake` to the handshake bound, `read_idle` to the peer-idle bound; it used `connect` for the handshake), and under the default `SourceKind::Auto` applies every protocol's mapping so the one the URL resolves to takes effect, instead of only the TS-over-HTTP stall policy (#2639).


### Removed
- Removed the unused `cookie`, `cookie_store` and `percent-encoding` dependencies; the cookie jar lives in `broadcast-auth`.

## [0.5.0] - 2026-11-14
### Removed
- BREAKING: `Session` is no longer `UnwindSafe` or `RefUnwindSafe`, and `tshttp::{TsHttpClient, TsHttpPolicy, TsHttpSource}` are no longer `RefUnwindSafe` (they now hold state that is not unwind-safe, such as the shared `RetrySchedule`'s jitter `Cell`); code that moves them across `std::panic::catch_unwind` must wrap them in `AssertUnwindSafe`.
- BREAKING: `broadcast_client::auth`'s own `AuthState`, `AuthDecision`, `AuthEvent` and `carries_credentials` definitions — they live in `broadcast-auth` now, and this module re-exports them, so the paths keep working but the types are `broadcast_auth`'s.

### Changed
- Smooth sessions jitter their fragment and manifest retries like every other source: the session passes its jitter seed to the engine (`SmoothConfig::jitter_seed`); the first retry still waits exactly its step (#2589).
- URL userinfo is read with `broadcast_auth::credentials_from_url` and removed with `strip_userinfo`; the private duplicate (`take_userinfo`) is deleted. Behaviour is unchanged for `user:pass@`; the control-character check still applies (#2587).
- `Session::payload_bytes()` also counts every response body byte of an HLS, DASH or Smooth session.
- An RTSP session announces its `Event::Tracks` (from the DESCRIBE SDP) when PLAY is answered instead of with the first access unit, so a host sees the programme before any media arrives.
- `SrtConfig::latency_ms` accepts any value: a latency below 120 ms is no longer an `InvalidConfig` (the negotiated latency is the larger of the two peers' values).
- `Retry-After` HTTP-date parsing now uses `broadcast-common::http_date::parse_http_date`.
- `AuthState` now comes from `broadcast-auth`; `broadcast-client` keeps no copy.
- RTSP keepalive now uses `rtsp_runtime::ClientSession`'s schedule (half the declared `Session;timeout=`, the RFC 2326 §12.37 60 s default when none is declared) instead of a local timer with its own default and ceiling, and its method is the one the server advertises.
- RTP sequence validity now uses `rtp_packet::SeqValidity` instead of a local delta/resync heuristic.
- `source::fetch::wall::WallClock` is `broadcast_common::time::WallClock` (the shared `time::MonoUtc` anchor mapping) rather than a second copy of the same arithmetic; `Session::set_wall_clock` and the `Retry-After` reading are unchanged.
- RTSP pull uses rtsp-runtime's `MAX_TRACKS` cap instead of a local constant.
- RTSP pull skips an SDP media section whose `m=` format is not a numeric RTP payload type (RFC 4566 §5.14) instead of playing it, matching multimux; the skip is reported in `skipped`.
- Timeline-jump detection now uses the detector moved to `transmux` (re-exported). `Config::timeline_jump` is now `Option<transmux::TimelineJumpConfig>`; the `broadcast_client::TimelineJumpConfig` re-export remains, but the type path changed (breaking for users naming `broadcast_client::timeline::TimelineJumpConfig`). `timeline::DEFAULT_JUMP_BACKWARD_US` and `DEFAULT_JUMP_FORWARD_SLACK_US` are removed from broadcast-client; they are `transmux::timeline::DEFAULT_JUMP_BACKWARD_US` / `DEFAULT_JUMP_FORWARD_SLACK_US` (#2469).
- The RTSP source reads each DESCRIBE media section through `transmux::sdp_track`; its own `parse_tracks`/`supported_payload` interpreter is deleted (output unchanged, pinned by `fixtures/golden/sdp-tracks/broadcast-client.txt`).
- The Smooth source builds `smooth_runtime::FetchFailure` with its new `retry_after_us` field left at `0` (#2393).
- The RTSP track aligner (Sender Report / `RTP-Info` / provisional placement) is `transmux::TrackAligner`, shared with multimux's RTSP pull; `AvSync` is now `transmux::AvSync`, re-exported unchanged from `broadcast_client` (#2380).
- BREAKING: the Smooth source is an adapter over the new `smooth-runtime` engine (#2370); the chunk planner, refresh, retry and track logic it carried are gone. Visible changes: the audio track is announced with its own id (`Event::Tracks` is `[1, 2]`, not `[1, 1]`, and audio samples carry track 2); a live manifest refresh no longer re-fetches the last fragment; a fragment that fails to demux is retried like any failed fetch instead of being dropped silently; the live refresh wait is half the last fragment's duration in microseconds, clamped to 0.5 s-5 s.
- The RTSP source plans its `SETUP`/`PLAY` through `rtsp_runtime::PlayPlan` (control resolution against `Content-Base`, channel pairs, the RTP/RTCP collision check) instead of its own copy; the wire behaviour is unchanged (#2372).
- BREAKING: the Smooth source parses the client Manifest with `broadcast-smooth`'s `SmoothManifest` instead of `transmux`'s removed `smooth_parse` module (#2356); `transmux::track_spec_from_quality_level` still builds the track spec.
- The test-only feature is renamed `__test-seams` -> `test-seams`, the one spelling the workspace uses for test seams (c6 C6-09).

### Added
- `skills/broadcast-client-basics/SKILL.md`: a Symposium agent skill shipped in the published package, so an AI coding agent working in a project that depends on `broadcast-client` gets usage guidance covering the host loop over `Session`, `Config`, source selection, auth/cookies/retry, the event queue limits, features and the common pitfalls.
- `Config::with_timeouts(Timeouts)` and `tshttp::Config::with_timeouts`: one `Timeouts` mapped onto the session's bounds by `Config::kind`, with the per-protocol meaning documented once (HLS: `read_idle` bounds playlist/segment/key requests; DASH and Smooth: manifest and segment requests; SRT: `connect` is the handshake bound; every other kind: `connect` is the stall policy's start timeout and `read_idle` its reconnect threshold). Every bound is floored at 1 ms (#2590).
- `fetch::ReconnectTimer` (`new(steps_ms, cap_ms, seed)`, `on_connected`, `on_disconnected`, `attempts`, `reset`) and `fetch::HEALTHY_CONNECTION_US` (30 s): the sans-IO reconnect timer, driven by the caller's clock, that broadcast-client and multimux share; the backoff and attempt counter restart only after a connection lasted at least `HEALTHY_CONNECTION_US` (#2471, #2474).
- `SrtConfig::timeouts` and `SrtConfig::with_timeouts`: the SRT handshake and peer-idle bounds read and set as `broadcast_common::timeouts::Timeouts` (`handshake`, `read_idle`), so a host maps its own timeouts once instead of converting to the `_ms` fields (#2514).
- `Config::max_queued_bytes` (default 256 MiB, `DEFAULT_MAX_QUEUED_BYTES`; `0` is `InvalidConfig`): a byte budget on the queued `Event::Sample` payloads next to `max_queued_events`. A host that does not drain loses the oldest samples (counted by `dropped_events`, each burst leaving one `Event::Discontinuity`) once either bound is exceeded.
- `Config::utc_timing_credentials` (on by default): whether a DASH session sends its credentials to a `UTCTiming` server on the session origin; a relay turns it off.
- `Config::preemptive_basic` (off by default): send `Basic` credentials on the first request to the session origin instead of waiting for a `401` (RFC 7617).
- `ErrorKind::refusal_status()` (the HTTP status behind a failed key, init or segment request) and `ErrorKind::is_permanent()` (content or codec errors a retry cannot fix).
- `UdpConfig::sdp`: an out-of-band SDP (RFC 4566) that switches an `rtp://` session from MPEG-2 TS (payload type 33) to the H.264 (RFC 6184) and AAC (RFC 3640) streams it declares, routed by RTP payload type and depayloaded with `transmux`'s depacketisers. The tracks are announced when the socket is bound, before any packet; a reconnect flushes the access units still held. `datagram_stats()` counts the datagrams and the ones that were not RTP, and `payload_bytes()` the packets routed to a declared stream.
- `ErrorKind::RequestRefused { method, status }` (non-fatal, also `ends_connection()`): an RTSP server's DESCRIBE, SETUP or PLAY answer the session cannot proceed on, with the method and the status as the server sent it.
- `Session::payload_bytes()`: transport-stream payload bytes accepted from the source, excluding control traffic and dropped datagrams, for hosts that measure stalls.
- `ErrorKind::SrtPeerIdle` (non-fatal) when the SRT peer goes silent past `peer_idle_timeout_ms`, and `ErrorKind::ends_connection()` naming the errors that end the connection the session was reading.
- `UdpConfig::interface_index` and `MulticastJoin::interface_index`: join an IPv6 multicast group on an interface named by index (valid only for an IPv6 group, not together with `interface`).
- `Config::relay()`: a preset for a host that forwards samples instead of playing them (no start-pending wait, no timeline-jump screening; the initial-tracks hold stays); `Event::Tracks` specs keep their `program_number`, which a relay uses to split a multi-programme stream.
- `broadcast_client::auth` is public: `AuthState` (origin-scoped credentials, challenge handling, `Clone`, `credentials()`) with `AuthDecision`, and `AuthState::preauthorize_basic` to send Basic on the first request (RFC 7617) instead of after a `401`.
- `broadcast_client::fetch::retry_after_us` is public sans-IO retry/backoff policy (RFC 9110 §10.2.3), for use by other pull hosts.

### Fixed
- RTMP URLs are parsed by `rtmp_runtime::target::RtmpTarget` (the second parser in `source/rtmp.rs` and the duplicated default-port constants are deleted); behaviour follows rtmp-runtime's grammar: `rtmps` default port 443, percent-decoded path (#2588).
- A `206` `Content-Range` is parsed by one RFC 9110 §14.4 parser (`broadcast_common::content_range`) instead of three: `bytes 5-20/10` is refused for a ranged fetch (it was accepted), `bytes 0-9/*` is a finite ts/http body of 10 bytes (it was not), and stray whitespace inside the value is invalid (ts/http accepted it) (#2586).
- A redirect `Location` (HTTP and RTSP) carrying a control character or space is no longer followed: it resolves through `broadcast_common::url_ref::resolve` instead of the raw `Url::join`, which deleted a TAB/CR/LF and followed a different URL than the header names (RFC 3986 §2) (#2585).
- A Smooth quality switch to a level with a different SPS/PPS or resolution now succeeds (it was refused as `NoSuchVariant`): the engine's `Output::TracksChanged` surfaces as a new `Event::Tracks`, the event DASH variant switches already use.
- `Session::rtcp_rejected_count`: the RTSP source's Sender Reports that were unusable (NTP time zero, or a set refused for tracks more than an hour apart in wallclock), which were previously counted nowhere a caller could read.
- The RTSP source flushes its track aligner when a connection ends, drops or is reconnected, so samples held back while waiting for the video anchor are delivered instead of lost (audit 7 A7-4).
- `Session::select_variant` on a Smooth source switches the video `QualityLevel` of the fragments requested afterwards; it used to validate the index and return `Ok` without changing anything.
- A DASH source whose MPD is `MPD@type="list"` (ISO/IEC 23009-1 6th edition) fails with the typed unsupported-addressing error instead of a generic playback-timeline failure (#2340).
- The join-point screen compares audio ends with the video join point wrap-safely (`clock33::pcr_signed_distance`). transmux unrolls each PID's PTS from its own first value, so a 2^33 wrap between the first audio and the first video PES put audio a whole wrap above video, every pre-join audio end passed, and `Start` came up to the audio-behind-video skew early.
- Every sample handed to the host has its end reported to the buffer controller in the same call. Samples released by `on_closed` (the TS demux tail, the RTSP depacketiser flush), `poll` (RTSP/RTMP timers, the TS track hold), `reconnect` and `next_event` used to be reported only at the next `on_data` chunk, so the controller judged the lead short of what the host held.
- An RTSP or RTMP connection loss is hinted to the buffer controller as `SourceEnded` / `SourceError`, as the TS path already did; a starvation right after the close was charged to the stall memory as `DataArriving`, ratcheting the target. The hint is sent only when the source will announce a `Discontinuity` (and so `Reconnected`) before the next connection's media.
- A live connection after a finite (VOD) one starts under the same rules as the first: the new controller keeps the previous controller's stall memory (aged by the time in between) and the pending-track placeholder and the explicit-rendered-set start hold apply again (the session's "started" flag stayed set, and the seed was lost).
- An RTSP connection lost to a protocol error inside `on_data` (no `on_closed` follows) is hinted to the buffer controller as `SourceError`, like a close; it sent no hint, so a starvation right after was charged to the stall memory as `DataArriving`.
- `Session::buffer_input_log_seed` reports the seed the session's current controller was built with (a live connection after a finite one starts from the dropped controller's aged stall memory), not the seed the session was opened with; a log of the later connection replays from the right memory.
- The live video media end reported to the buffer controller is the end of the contiguous presentation-order run, not the highest PTS seen plus a frame: with B-frames the latter ran up to the reorder depth (5 frames on the TF1 capture) ahead of the pictures delivered, so a start or resume was judged on media that had not arrived. A hole in the run is skipped once no later sample can fill it (`pts >= dts` for every picture still to come). The finite (VOD/HLS) path keeps the highest-PTS end.

## [0.4.0] - 2026-11-08
### Added
- Opt-in buffering input log for offline replay: `Config::record_buffer_inputs` (default off; nothing is recorded or allocated when off) and `Config::max_recorded_buffer_inputs` (default 1 000 000, must be non-zero), `Session::drain_buffer_inputs()`, `Session::dropped_buffer_inputs()`, `Session::buffer_input_log_config()`, `Session::buffer_input_log_seed()` and `Config::controller_config()` (the exact `ControllerConfig` the session's controller is built from). ## [0.1.0] - 2026-11-01
### Added

When the first response was a `200` with `Accept-Ranges: bytes` or a `206`, with a strong validator (a strong `ETag`, else a `Last-Modified` at least a second older than `Date`) and no `Content-Encoding`, the retry sends `Range` and `If-Range` for the missing bytes (inside the original range for a DASH `mediaRange` or HLS `BYTERANGE`) and a `206` whose `Content-Range` continues the prefix extends it; a `200` replaces the prefix, any other answer falls back to one immediate full request. ### Known limits

- RTSP carries H.264 video and AAC audio only; H.265 over RTP needs an RFC 7798 depayloader in `transmux` (not present), so an SDP whose only media is H.265 fails with one fatal `ErrorKind::UnsupportedCodec`. UDP RTP is not supported.
- SRT, Smooth Streaming and RTMP pull sources are not included. DASH plays fMP4/CMAF only, at segment granularity (no chunk-level low-latency delivery), without seeking or automatic bitrate adaptation; see the README table.
- HLS subtitle renditions are listed in `Event::Variants` but never fetched; CENC/CBCS and SAMPLE-AES are never decrypted (`ErrorKind::UnsupportedEncryption`).
- A `Retry-After` HTTP-date with neither a `set_wall_clock` anchor nor a response `Date` header is ignored.
- Live TS-over-HTTP: a declared audio stream that resolves later than the effective pending-track wait (the larger of `start_pending_track_wait_us` and `start_pending_track_hard_cap_us`, default 4 s, measured from the first media) still produces a `Start` on video followed by a `Pause`. While the first `Start` is held `Status::AwaitingTracks` is emitted once, and when the wait expires with audio still unresolved a one-shot `ErrorKind::PendingTrackUnresolved { kind: StreamKind::Audio }` is emitted. The controller's `track_silence_timeout_us` is raised to at least that wait plus 500 ms (a registered track silent for 3 s to 4.5 s is now dropped from the lead computation later than before).
- An HLS audio rendition is a separate client, so audio and video are aligned by the player on PTS, not at the transport level.
