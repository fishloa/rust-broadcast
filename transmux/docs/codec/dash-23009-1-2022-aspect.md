# ISO/IEC 23009-1:2022(E) — `@sar`, `@par`, `@width`, `@height`

Primary-source transcription for display geometry Phase 4c (DASH `@sar`/`@par`).

- Source: `private/specs/iso_iec_23009-1_dash_2022_ed5.pdf` (ISO/IEC 23009-1:2022(E), **5th edition**,
  330 pages, ISO "Publicly Available Standards" download; the owner accepted ISO's licence
  2026-10-19), markdown `private/specs-md/iso_iec_23009-1_dash_2022_ed5.md` (pdf2md `textlayer`; only
  the Bibliography p. 328 is flagged unverifiable).

  printed + 8).

## Table 5 — Semantics of AdaptationSet element (printed p. 42)

`@par` (use O), verbatim:

> specifies the picture aspect ratio of the video media component type, in the form of a string
> consisting of two integers separated by ':', e.g. "16:9". When this attribute is present, and the
> attributes @width and @height for the set of Representations are also present, the picture aspect
> ratio as specified by this attribute shall be the same as indicated by the values of @width,
> @height, and @sar, i.e. it shall express the same ratio as (@width * sarx) : (@height * sary), with
> sarx the first number in @sar and sary the second number.
>
> If not present, the picture aspect ratio may be defined for each media component or it may be
> unknown.

The same text appears for the Initialization Set `@par` (printed p. 101).

`@minWidth`/`@maxWidth`/`@minHeight`/`@maxHeight` (same table): the minimum/maximum `@width`/`@height`
over all Representations in the Adaptation Set, "the same units as the @width attribute"; "If not
present, the value is unknown."

## Table 14 — Common Adaptation Set, Representation and Sub-Representation attributes (printed p. 64)

(§5.3.7.2; these attributes may appear on the AdaptationSet, Representation and SubRepresentation.)

`@width` (use O), verbatim:

> specifies the horizontal visual presentation size of the video media type on a grid determined by
> the @sar attribute.
>
> In the absence of @sar width and height are specified as if the value of @sar were "1:1"
>
> NOTE The visual presentation size of the video is equal to the number of horizontal and vertical
> samples used for presentation after encoded samples are cropped in response to encoded cropping
> parameters, "overscan" signalling, or "pan/scan" display parameters, e.g. SEI messages.
>
> If not present on any level, the value is unknown.

`@height` (use O), verbatim:

> specifies the vertical visual presentation size of the video media type, on a grid determined by
> the @sar attribute.
>
> If not present on any level, the value is unknown.

`@sar` (use O), verbatim:

> specifies the sample aspect ratio of the video media component type, in the form of a string
> consisting of two integers separated by ':', e.g. "10:11". The first number specifies the
> horizontal size of the encoded video pixels (samples) in arbitrary units. The second number
> specifies the vertical size of the encoded video pixels (samples) in the same units as the
> horizontal size.
>
> If not present on any level, the value is unknown.

`@sar` type (XML schema, `RatioType`, shared with `@par`): `xs:string` with pattern `[0-9]*:[0-9]*`
(text-layer transcription of the schema annex, line ~2866 of the md).

## What this settles

1. `@par` **is** `(@width × sarx) : (@height × sary)` — the arithmetic `transmux::dash` uses
   (`par_of`), and it is a *shall* when `@par`, `@width`, `@height` are all present. (Not stated: that
   the written value must be gcd-reduced; both `"16:9"` examples are reduced. We write it reduced.)
2. `@width`/`@height` are counts of samples **after cropping** on a grid "determined by `@sar`" —
   i.e. **not** square-pixel-corrected; the pixel shape is carried by `@sar`. So a 720x576 SAR 64:45
   Representation is `@width=720 @height=576 @sar="64:45"` (not 1024x576).
3. Absent `@sar` with `@width`/`@height` present means "as if 1:1" for the size grid, but `@sar`
   *itself* "if not present on any level, the value is unknown". An unknown SAR therefore must not be
   advertised as `1:1`; omitting the attribute is correct.
4. The three attributes inherit: present on the AdaptationSet they apply to every Representation
   unless overridden ("present on any level").

Together with ETSI TS 103 285 §4.4 (`isobmff-tkhd.md` §3: `@sar` "should be present", `@par` "should be
present" on the video Adaptation Set, one of them "shall" be present when the picture aspect ratio is
not 16:9), these are the full normative statements the DASH packagers rely on.
