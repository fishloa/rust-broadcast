# Changelog

## [Unreleased]

### Changed
- MSRV raised to **1.95.0** (issue #949). This removes the workspace's MSRV
  split: `webrtc-runtime`'s optional `media` feature needed rustc 1.88 (via
  `rcgen`), which had grown a dedicated CI job, six `--exclude` lanes and a
  guard script to contain. Adopting let-chains and `is_multiple_of` where the
  1.95 lints require them; no functional or API change.
### Fixed

- Doc accuracy (#940): `Cargo.toml` `description`, the crate-root doc
  comment, and the README no longer claim ST 2022-7 seamless protection
  switching / hitless failover support — this crate implements only the
  ST 2022-6 HBRMT payload header. Aspirational scope moved to a README
  "Planned" section.
- Removed two dead validation branches in `PayloadHeader::validate` (#941
  row 9): the `FrameStructure::Reserved`/`FrameRate::Reserved` range checks
  compared a `u8` against an 8-bit mask (`0xFF`), which can never be true.
- The 0.1.0 entry below claimed a golden-bytes test "with real HBRMT payload".
  It is synthetic, hand-derived from the spec's field tables. Corrected in
  place rather than silently — **this crate has no real-capture fixture**
  (#926).

### Known limitation — no real fixture

Every test in this crate runs on hand-derived bytes. Two independent searches
found **no ST 2022-6/HBRMT capture available under a licence compatible with
this workspace's MIT OR Apache-2.0**; the only public capture is GPL-2.0, and
the one other candidate shipping genuine HBRMT bytes states no licence at all.

Nor can one be generated here: no FOSS tool implements real ST 2022-6 payload
semantics. TSDuck and ffmpeg speak MPEG-TS, which is architecturally unrelated
— HBRMT carries raw SDI in RTP, never a transport stream — and the one project
that mentions ST 2022-6 (Intel's Media-Transport-Library) treats it as opaque
RTP passthrough rather than constructing real `MAP`/`FRAME`/`FRATE`/`SAMPLE`
semantics. Tool-generated bytes would be the same hand-picked field values with
extra steps, and would not clear the project's real-fixture bar.

So this crate sits where A/321 bootstrap does in #943: a documented
spec-vector-tested exception with the blocker recorded, rather than fabricated
or improperly-licensed data. It must not be published while this stands.

### Added

Not yet released — this crate has never been published to crates.io (see the
"no real fixture" blocker above).

- `PayloadHeader` parse/serialize for the 4/8/12+-byte HBRMT payload header
  (SMPTE ST 2022-6:2012 §6.4).
- `VideoSourceFormat` with MAP/FRAME/FRATE/SAMPLE field accessors.
- Typed field enums: `ClockFrequency`, `FecUsage`, `FrameRate`,
  `FrameStructure`, `MapStructure`, `SampleStructure`, `Scrambling`,
  `TimestampRef`, `VideoSourceId`.
- Golden-bytes round-trip test with a **synthetic** HBRMT payload, hand-derived
  from the §6.4 field tables (marker `0xDEADBEEF`). This line previously said
  "real HBRMT payload", which was untrue — see the `[Unreleased]` correction.
- `#[non_exhaustive]` + `name()` + `impl_spec_display!` on all spec enums.
- `no_std` + `alloc`, optional `serde`.
