## Conventions used in these files

- **Verbatim.** Text is reproduced as printed, including typos, odd spacing and mismatched quotes; anything that looks wrong is left
  unchanged and flagged in a `> **Spec note:**` block ("Transcription notes" at the end of the file). Spec values are never corrected.
- **Semantics tables** keep the original columns (`Element or Attribute Name | Use | Description`); elements are bold, attributes are
  `` `@code` ``. Use codes are the spec's: `M` mandatory, `O` optional, `OD` optional with default (default value given in the cell),
  `CM` conditionally mandatory, `F` fixed; element rows carry `<minOccurs>...<maxOccurs>` (`N` = unbounded) exactly as printed
  (`0...N`, `0 ... N` and `0…N` are the same cardinality printed three ways). Paragraphs inside one cell are joined with `<br>`.
- **XML syntax blocks** are in ```` ```xml ```` fences with the printed element/attribute content; line breaking and indentation are normalised
  (the text layer flattens the PDF's whitespace). Entity references such as `&URN;` are kept as printed.
- **Page markers.** `<!--PB printed N-->` marks the end of printed page N (add 8 for the PDF page). Inside tables the marker sits in the
  first cell of the first row that starts after the break (or the row that straddles it); after an XML block it follows the block.
- **Cross-references** to clauses transcribed here are relative links; references to other clauses/annexes are left as text.
- **Figures 1-3** (system, client model, data model) are described by an ASCII redraw marked with the PDF page.
- **Emphasis.** Bold term names (clause 3), bold element names and defined-term emphasis are reproduced where cheap; italic
  cross-referenced terms in clause 3 are not marked up. Formatting never changes the words.
