# ISO/IEC 23009-1:2022(E) — `AdaptationSet@id`, `@group`, `Representation@id` (and the 2026 schema types)

Why this exists: running `xmllint --noout --schema DASH-MPD.xsd` (the ISO/IEC 23009-1:2026 6th-edition schema,
`private/specs/iso_iec_23009-1_dash_2026_ed6_schema/`) over every `transmux/tests/golden/*.mpd` fails with
`attribute 'id': 't0' is not a valid value of the atomic type 'xs:unsignedInt'` — our `AdaptationSet@id` values
(`t0`, `t1`, ...) are not unsigned integers. This file records the normative text so the fix is grounded.

Source: `private/specs/iso_iec_23009-1_dash_2022_ed5.pdf` (5th edition), rows checked on the rendered pages
(printed page = PDF page - 8); schema: `private/specs/iso_iec_23009-1_dash_2026_ed6_schema/DASH-MPD.xsd`
(electronic insert of the 6th edition; its prose is paywalled and unchecked).

## Source rows (authoritative text lives in the clause transcriptions)

- `AdaptationSet@id` and `@group` - Table 5 (printed p. 41) in [`05-3-3-adaptation-set.md`](05-3-3-adaptation-set.md#c5-3-3-2);
  the sentence "If the AdaptationSet@group attribute is not present, then all Representations in this Adaptation Set are
  assigned to a non-zero group specific to this Adaptation Set." is in clause 5.3.3.1 (printed p. 41) of the same file.
- `Representation@id`, `@dependencyId`, `@associationId` - Table 9 (printed p. 53) in
  [`05-3-5-representation.md`](05-3-5-representation.md#c5-3-5-2).

Summary of the rows, for the analysis below: `AdaptationSet@id` is "a unique unsigned integer value in the scope of the
containing Period", not present in a remote element entity; `@group` is "an unsigned integer"; `Representation@id` is
mandatory, unique within a Period unless functionally identical, with no whitespace, and (when used in template
URLs) restricted to RFC 3986 HTTP-URL characters. The 2026-10-24 re-verification ([`VERIFICATION.md`](VERIFICATION.md))
found no disagreement with the earlier transcription.

| `RepresentationType` (complexType, line 521) | `StringNoWhitespaceType` | **required** | 536 |
| `PeriodType` (line 158) | `xs:string` | optional | — |
| `MPD` | `xs:string` | optional | 113 |

`@group` on `AdaptationSetType` is `xs:unsignedInt` as well. (Line numbers refer to the vendored file.)

## What this settles

1. `AdaptationSet@id`, when present, **must be an unsigned integer** (decimal digits), unique within the Period.
   Free-form strings such as `t0` or `main-0` are not conformant; an `xmllint --schema` run rejects them.
2. `Representation@id` is a whitespace-free string, required, unique within the Period (except for functionally
   identical Representations); strings like `1` or `video-1` are fine.
3. Anything that *references* an Adaptation Set id (e.g. the DASH-IF trick-mode `SupplementalProperty@value`, see
   `specs/rules/dash-mpd-rules.md` (historical, 2012 edition)) therefore references an unsigned integer.
