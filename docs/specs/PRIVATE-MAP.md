# Private map: old public path to private path

The verbatim spec transcriptions that used to live under `<crate>/docs/`, `docs/specs/transmux/`, `st2110/docs/`,
`cpix/docs/` and `specs/` now live **only** in the private companion repository `rust-broadcast-private`
(the `private/` submodule), under `private/specs-verified/<family>/<owner>/`. The standards are (c) their
publishers; the public tree keeps data (`*.toml` registries, `allocations.tsv`), free-licence text (IETF, W3C,
id3v2) and own-words notes. Moved files are byte-identical to their former public copy.

## How to cite

- New code and docs cite the private path directly: `private/specs-verified/<family>/<owner>/<file>.md` plus the
  clause/table number (never a bare public `docs/...` path for a file that is private).
- Existing `//!` / `//` citations keep their old crate-relative path (`docs/<kind>/<spec>/<file>.md`); this table
  decodes them. `tools/check-private-map.py` (run by `pytest tools/tests` and the `lint` job) fails when a Markdown
  link targets a moved path, when a map row's old path exists again, and (with `private/` checked out) when a
  private target is missing.
- Never copy standards text into a public file to make a citation resolvable; write an own-words note instead.

own-words part. Pages whose old path is `dvb-si/docs/tables/en_300_743/...` share one private copy with
`dvb-subtitle`.
