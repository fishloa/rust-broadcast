## `dvb-conformance` — T-STD buffer model (#737)

TR 101 290 indicators 3.3, 3.9, and 3.10 are now emitted. The partial T-STD model in `src/tstd.rs` tracks per-PID TBn (transport buffer, 512 bytes) and global TBsys (system buffer, 512 bytes at 1 Mbit/s), producing:

- **`BufferError`** (indicator 3.3): TBsys overflow when a completed PSI section exceeds its capacity with insufficient drain time. TBn overflow is **deferred** (the spec requires the 1.2× bitrate rule in §2.4.2.2, which is only observable at a higher level than stream processing).
- **`EmptyBufferError`** (indicator 3.9): TBn or TBsys empty at least once per second — a side-channel sign of underflow causing a decoder stall.
- **`DataDelayError`** (indicator 3.10): data delay exceeding 1 second through the transport buffers.

**Indicator 2.4 (PCR accuracy) is deliberately not emitted.** It requires ±500 ns hardware-timing precision at the RF/demodulator level and cannot be inferred from the transport stream alone.

All buffer sizes and rates have named spec-cited constants. `Indicator` gained four new `#[non_exhaustive]` variants — additive, no breaking change.

## `transmux` 0.21.0 — BREAKING

### `EncryptConfig` gains `constant_iv_senc` (breaking)

`EncryptConfig` gains a `constant_iv_senc: ConstantIvSenc` field (issue #783). `ConstantIvSenc::Emit` (the default) causes a `cbcs` + `IvGen::Constant` track to emit a `senc` box with the constant IV replicated per sample, for interop with Bento4 `mp4decrypt` and other tools that require an explicit `senc`. `ConstantIvSenc::Omit` preserves the old spec-minimal `tenc`-only shape.

This is a breaking change because `EncryptConfig` is not `#[non_exhaustive]` — every struct-literal construction must add the field. `TrackEncryption::new` also gains a fourth argument.

### Input degradation events (additive)

`StreamingTsDemux` now emits `DemuxEvent::InputDegraded` when the MPEG-2 TS `transport_error_indicator` is set or a genuine continuity-counter gap is detected (excluding legal duplicates and signalled discontinuities, per ISO/IEC 13818-1 §2.4.3.3). A consumer repackaging lossy UDP multicast can now distinguish a clean stream from one losing packets (issue #778).

### `#[non_exhaustive]` sweep (breaking)

All remaining un-annotated public enums now carry `#[non_exhaustive]` (issue #806). Downstream `match` blocks on any of these enums now need a wildcard arm.

### Defensive `StreamType` filtering

The smooth-pull path's own `StreamType` gained `#[non_exhaustive]`, exposing that `ll-hls-runtime`/`multimux`'s smooth-pull ingest matched `Video`/`Audio`/`Text` exhaustively and would have panicked on any future stream type. That is fixed in `multimux` 0.5.1.

## `multimux` 0.5.1 — DASH/LL-DASH 503 fix + defensive matching

**DASH and LL-DASH manifests returned 503 forever on every driver-backed route** (shipped in 0.5.0). `RouteHandle::set_track_specs` had no production call site. `report_driver_progress` now syncs track specs from each published program's `Trunk` into the route on every poll, using `track_generation()` to avoid redundant syncs (issue #831).

Also: smooth-pull ingest now skips any `StreamType` other than `Video`/`Audio` at parse time (surfaced by `transmux`'s `StreamType` gaining `#[non_exhaustive]`), and `output::llhls`/`origin::resource` handle a future `LlHlsBody` variant defensively.

## `ll-hls-runtime` 0.3.0 — BREAKING

`LlHlsRequest` and `LlHlsBody` (`server::engine`) now carry `#[non_exhaustive]` (issue #806). A downstream `match` on either needs a wildcard arm. The client's part-prefetch now ignores future `PreloadHintType` variants defensively.

## `rtmp-runtime` 0.3.0 — BREAKING

`LimitType`, `Fmt`, and `MessageHeader` now carry `#[non_exhaustive]` (issue #806). A downstream `match` on any of them now needs a wildcard arm.

## `media-doctor` 0.6.0

- **BREAKING**: `cli::Cli` now carries `#[non_exhaustive]` (issue #806). Unlikely to affect consumers.
- **Additive**: HLS manifest validator `check_hls_playlist()` (issue #756) — structured M3U8 parse via `transmux::MediaPlaylist::parse`, plus 5 LL-HLS rules. DASH MPD validator `check_dash_manifest()` — structured MPD parse with 9 rules. Both are new `check-hls` and `check-dash` CLI subcommands.
- Now depends on `transmux` 0.21.

## `ttml-subtitle` 0.1.0 — new crate

W3C TTML2 / IMSC 1.1 timed-text subtitle parser. Full TTML2 element tree (26 element types, 56 style properties), exhaustive `<time-expression>` grammar, IMSC 1.1 profile validation (159-row feature disposition table), and a parse/validate split. Semantic round-trip with enumerated divergence. From-scratch authoring via `Default` on all element types. Real-fixture tested against 11 W3C IMSC conformance suite documents. `no_std` + `alloc`.

## The transmux 0.21 cascade

`transmux` 0.21 is a breaking release. Every crate that depends on it must be republished requiring the new minor so a consumer's graph doesn't pull two versions. The four violations caught by `tools/check-published-dep-consistency.py` — `ll-hls-runtime`, `media-doctor`, `media-plane`, `multimux` all still at `transmux ^0.20` — are the four that must be bumped here.

## Bump all of these together

`transmux` 0.21 is a **minor** under 0.x, which is a breaking caret bucket (`^0.20` → `^0.21`). A graph mixing 0.20 and 0.21 has two copies of every transmux type and trait. If you depend on more than one crate from this family, move them all in the same commit.
