# st2022 0.5.0

_Released 2026-11-15._

Minor-class release (0.4 -> 0.5). The HBRMT video timestamp names what it is: a count of ticks of the media clock `ClockFrequency` declares, carried as a typed `VideoTimestamp` instead of a bare `u32`. The wire bytes are unchanged.

Version: 0.4.0 -> 0.5.0.

## Breaking changes and migration

### `video_timestamp` is `Option<VideoTimestamp>`

`PayloadHeader::video_timestamp` is an `Option<VideoTimestamp>` (was a bare `u32`). `VideoTimestamp` has `from_ticks`/`ticks`/`Display`, and `video_timestamp_ticks()` returns the 32-bit wire count unchanged.

```rust
// before
let ticks: u32 = header.video_timestamp;
// after
let ticks: Option<u32> = header.video_timestamp_ticks();
let typed: Option<VideoTimestamp> = header.video_timestamp;
let built = VideoTimestamp::from_ticks(27_000_000);
```
