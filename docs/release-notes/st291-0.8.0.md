# st291 0.8.0

_Released 2026-11-15._

Minor-class release (0.7 -> 0.8). An ANC packet's `Data_Count` and `Checksum_Word` are derived from the words they describe instead of stored, so an edited packet can no longer be serialized with a stale count or checksum. The descriptor loop is typed, the ANC PES header is built by `mpeg-pes` instead of a second copy of the timestamp coding, and the RTP payload's extended sequence number names the position it holds.

Version: 0.7.0 -> 0.8.0.

## Breaking changes and migration

### `AncPacket` derives `Data_Count` and `Checksum_Word`

The `data_count` and `checksum` fields are gone: ST 291-1:2011 §6.5/§6.7 derive both from `DID`/`SDID`/`User_Data_Words`, so they are computed on serialize. `data_count()`, `checksum()` and `udw_loop_count()` are fallible methods (`Error::FieldOverflow` past 255 user data words), and `build(c_not_y_channel_flag, line_number, horizontal_offset, did8, sdid8, udw8s)` builds a packet with parity filled in. Parsing rejects a packet whose stored `Data_Count` or `Checksum_Word` disagrees with its fields (`Error::DataCountMismatch`, existing `Error::ChecksumMismatch`) instead of silently rewriting them on serialization.

```rust
// before
let packet = AncPacket { did, sdid, data_count, checksum, user_data_words, .. };
let count = packet.data_count;
// after
let packet = AncPacket::build(false, line, offset, did, sdid, &words)?;
let count = packet.data_count()?;    // Error::FieldOverflow past 255 words
let report = packet.validate()?;     // Result<ValidationReport>
```

### The PES header goes through `mpeg-pes`

`Error::Pes(mpeg_pes::Error)` replaces `BadPtsDtsFlags` and `BadHeaderDataLength`: a malformed PES header (bad start code, bad `PES_header_data_length`, a payload shorter than `PES_packet_length`) is now `Error::Pes(..)`, the last case as `mpeg_pes`'s own `BufferTooShort`. `Error::PesLengthOverflow` is removed (the check moved into `mpeg-pes`); `Error::BadStreamId` and `Error::ReservedBits` stay. PTS construction goes through `mpeg_pes::Pts::try_new`, and `PES_scrambling_control` is checked against `mpeg_pes::ScramblingControl::NotScrambled`.

```rust
// before
match err {
    st291::Error::BadPtsDtsFlags => { /* .. */ }
    st291::Error::BadHeaderDataLength => { /* .. */ }
    _ => {}
}
// after
match err {
    st291::Error::Pes(mpeg_pes::Error::ForbiddenPtsDtsFlags) => { /* PTS/DTS present in a PTS-only header */ }
    st291::Error::Pes(mpeg_pes::Error::BufferTooShort { need, have, .. }) => { /* short PES packet */ }
    _ => {}
}
```

### `AncDataDescriptor` walks a typed descriptor loop

`AncDataDescriptor::inner_descriptors: &[u8]` is `descriptors: Vec<Descriptor>`: the `descriptor_length` body is an ISO/IEC 13818-1 §2.6 `descriptor()` loop, so each entry is a typed `Descriptor` with `tag()`/`body()` accessors. ST 2038 §4.1.2.1 defines no descriptors for the loop, so every entry is `Descriptor::Other { tag, body }`, kept verbatim for a lossless round-trip; a truncated entry is reported as `Error::BufferTooShort` instead of being retained as opaque bytes.

```rust
// before
let body = descriptor.inner_descriptors;   // &[u8]
// after
let body = descriptor.descriptors;         // Vec<Descriptor>
let first = body.first().map(|d| (d.tag(), d.body()));
```

### `AncRtpPayload::extended_sequence_number` is typed

It is an `ExtendedSequenceNumber` instead of a bare `u16`: the field holds the high-order bits of RFC 4175's extended 32-bit sequence number, so it now names that position (`high_half()`, `extended(rtp_sequence_number)`) rather than leaving the shift to the caller. The two wire bytes are unchanged.

```rust
// before
let ext = payload.extended_sequence_number;
// after
let ext = payload.extended_sequence_number.high_half();
let full = payload.extended_sequence_number.extended(rtp_sequence_number);
```

## Fixes

- `AncPacket` can no longer be serialized with a stale `Data_Count` or `Checksum_Word`: editing a user data word used to write bytes whose declared count or checksum contradicted the words themselves.
- The ANC PES header is parsed and written by `mpeg-pes`'s `PesPacket` instead of a second copy of the PES timestamp/BER coding; ST 2038 Table 2's pinned fields are still enforced on top.

## Dependencies

- `broadcast-common` 12 -> 13 (published first, from tag `broadcast-common-v13.0.0`).
- `mpeg-pes` 0.8 -> 0.9 (new dependency: the PES header codec).
- `rtp-packet` 0.7 -> 0.8.
