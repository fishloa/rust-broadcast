# st2022 0.1.0

_Released 2026-10-05._

First release of `st2022`, a parser and serializer for the SMPTE ST 2022-6:2012 HBRMT (High Bit Rate Media Transport, SDI-over-IP) RTP payload header. It is `no_std` + `alloc`, depends only on `broadcast-common` (and `thiserror`), and was tested against a real HBRMT capture before release. It implements the payload header only: it does not implement ST 2022-7 seamless protection switching, and an earlier draft of the crate description, crate-root docs and README that claimed such support was corrected (#940).

## What is covered

- `PayloadHeader<'a>`: parse and serialize the 4, 8, 12 or more byte HBRMT payload header that precedes the media payload in each RTP datagram (ST 2022-6:2012 section 6.4). Fields: `vsid`, `fr_count`, `timestamp_ref`, `scrambling`, `fec_usage`, `clock_frequency`, `reserve`, optional `video_source_format`, optional `video_timestamp`, and optional `extension`. `F` and `Ext` are derived from the presence of the optional fields rather than stored, and the constructor enforces the `clock_frequency` to `video_timestamp` invariant.
- `VideoSourceFormat`: the MAP / FRAME / FRATE / SAMPLE fields describing the SDI signal structure.
- Typed field enums, each with `name()` and `Display` (via `impl_spec_display!`) and a reserved arm that preserves the raw value: `ClockFrequency`, `FecUsage`, `FrameRate`, `FrameStructure`, `MapStructure`, `SampleStructure`, `Scrambling`, `TimestampRef`, `VideoSourceId`.
- `reserve` is preserved verbatim on round trip rather than forced to zero.
- Features: `std` (default) and optional `serde` (serialize only). MSRV 1.95.0, the workspace-wide value (issue #949). Two examples, `build_hbrmt` and `parse_hbrmt`.

```toml
st2022 = "0.1"
```

## Verified against a real capture

Earlier drafts were tested only against a synthetic, hand-derived payload (marker `0xDEADBEEF`), and publication was held back for that reason: no ST 2022-6 capture existed under a licence compatible with the workspace's MIT OR Apache-2.0. That blocker is gone. A genuine HBRMT/RTP/UDP capture from `cisco/herisson` (`ip2vf`), licensed BSD-3-Clause (licence text and provenance in `fixtures/st2022/PROVENANCE.md`), is committed as `fixtures/st2022/st2022-6-hbrmt-1080i5994-single-frame-loopback.pcap` and exercised by `tests/hbrmt_fixture_pcap.rs`. That test parses and byte-exact round-trips every payload header in one full 1080i59.94 frame (4,497 RTP packets, captured on Linux loopback), and checks the `RESERVE` field width against real data. The synthetic golden-bytes test is kept and labelled as synthetic.

## Limits

- Payload header only. The media payload (the SDI data itself) is not decoded, and the Header Extension is kept as opaque bytes (`extension: Option<&[u8]>`): its Tag/Length/Value chain is not walked.
- No ST 2022-7. The crate parses the `VSID` field that a 2022-7 merge needs but implements no merge; the workspace has no hitless merge yet (see the crate-root docs, issue #752).
- The real capture covers one format only: 1080i59.94, one frame, a single sender. Other SDI formats (SD, 3G, other frame rates) are exercised only by synthetic bytes derived from the spec tables.
