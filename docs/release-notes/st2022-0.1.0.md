# st2022 0.1.0

First release. st2022 implements the SMPTE ST 2022-6:2012 HBRMT (SDI-over-IP)
RTP payload header only — parse and serialize for the 4/8/12+-byte header, the
`VideoSourceFormat` MAP/FRAME/FRATE/SAMPLE fields, and the associated typed
enums. It does not implement ST 2022-7 seamless protection switching; an
earlier draft of the crate description, doc comment, and README claimed that
support and has been corrected.

## What's in it

- `PayloadHeader` parse/serialize for the HBRMT payload header (SMPTE
  ST 2022-6:2012 §6.4).
- `VideoSourceFormat` with MAP/FRAME/FRATE/SAMPLE field accessors.
- Typed field enums: `ClockFrequency`, `FecUsage`, `FrameRate`,
  `FrameStructure`, `MapStructure`, `SampleStructure`, `Scrambling`,
  `TimestampRef`, `VideoSourceId` — each with `#[non_exhaustive]`, `name()`,
  and `impl_spec_display!`.
- `no_std` + `alloc`, optional `serde`.
- MSRV 1.95.0 (workspace-wide, issue #949).

## Verified against a real capture

Earlier drafts of this crate were tested only against a synthetic,
hand-derived payload (marker `0xDEADBEEF`), and were held back from publishing
for that reason. That blocker is gone: a genuine HBRMT/RTP/UDP capture from
`cisco/herisson` (`ip2vf`), licensed BSD-3-Clause (see
`fixtures/st2022/PROVENANCE.md` in the repository), is committed and exercised
by `tests/hbrmt_fixture_pcap.rs`. That test parses and byte-exact round-trips
every payload header in one full 1080i59.94 frame (4,497 RTP packets) and
checks the `RESERVE` field width against real data. The synthetic golden-bytes
test is kept as well, and is labelled as synthetic.
