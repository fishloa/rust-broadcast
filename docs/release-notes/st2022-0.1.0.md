# st2022 0.1.0

**Status: NOT PUBLISHED.** This note describes the content staged for a future
0.1.0, not a release that has happened. `st2022` must not be tagged or
published to crates.io until it has a real, licensable ST 2022-6/HBRMT
capture — see "Blocker" below. Do not treat any date on this document as a
release date.

st2022 implements the SMPTE ST 2022-6:2012 HBRMT (SDI-over-IP) RTP payload
header only — parse and serialize for the 4/8/12+-byte header, the
`VideoSourceFormat` MAP/FRAME/FRATE/SAMPLE fields, and the associated typed
enums. It does not implement ST 2022-7 seamless protection switching; an
earlier draft of the crate description, doc comment, and README claimed that
support and has been corrected.

## What's staged

- `PayloadHeader` parse/serialize for the HBRMT payload header (SMPTE
  ST 2022-6:2012 §6.4).
- `VideoSourceFormat` with MAP/FRAME/FRATE/SAMPLE field accessors.
- Typed field enums: `ClockFrequency`, `FecUsage`, `FrameRate`,
  `FrameStructure`, `MapStructure`, `SampleStructure`, `Scrambling`,
  `TimestampRef`, `VideoSourceId` — each with `#[non_exhaustive]`, `name()`,
  and `impl_spec_display!`.
- `no_std` + `alloc`, optional `serde`.
- MSRV 1.95.0 (workspace-wide, issue #949).

## Blocker — no real fixture, do not publish

Every test in this crate runs on a synthetic, hand-derived HBRMT payload
(marker `0xDEADBEEF`) built from the §6.4 field tables — not a real capture.
An earlier changelog entry claimed the golden-bytes test used "real HBRMT
payload"; that was untrue and has been corrected in place.

Two independent searches found no ST 2022-6/HBRMT capture available under a
licence compatible with this workspace (MIT OR Apache-2.0): the only public
capture is GPL-2.0, and the one other candidate carries no licence at all.
None can be generated either — no FOSS tool implements real ST 2022-6 payload
semantics (TSDuck/ffmpeg speak MPEG-TS, which HBRMT does not use; the one
project that touches ST 2022-6, Intel's Media-Transport-Library, treats the
payload as opaque RTP passthrough rather than constructing real
`MAP`/`FRAME`/`FRATE`/`SAMPLE` fields).

This is a documented spec-vector-tested exception, the same shape as the
ATSC A/331 bootstrap gap: real code, hand-derived test bytes, and a recorded
reason it stops short of a real-fixture release. It stays unpublished until
that changes.
