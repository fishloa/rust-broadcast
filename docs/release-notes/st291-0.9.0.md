# st291 0.9.0

_Released 2026-11-22._

Minor for a 0.x crate. One real fix (a cleared `data_alignment_indicator` reported the wrong expected value in its error), the rest is the epoch move and a test pass. The crate builds against `broadcast-common` 14, `mpeg-pes` 0.10 and `rtp-packet` 0.9.

## Breaking changes

- Builds against new caret epochs of workspace siblings (`broadcast-common` 13 -> 14, `mpeg-pes` 0.9 -> 0.10, `rtp-packet` 0.8 -> 0.9). A caret-epoch change is major-class under the epoch-purity rule (`docs/RELEASE-AUDIT.md` §2) whatever this crate's own API diff; consumers must resolve a single copy of each at the jiff 1.0 epoch.

## Fixed

- `Error::ReservedBits` for a cleared `data_alignment_indicator` reported `expected: 0`, the position bit masked by `& 1`, instead of the spec value `1` (#3210).

## Tests

The ANC packet round trip, the DID/SDID and user-data payload boundaries, the ST 2038 PES/descriptor layouts and the RTP (ST 2110-40 / RFC 8331) payload header are covered by the crate's suites against the committed fixtures.

## Pre-release audit

This crate carries no crate-specific finding; it takes the workspace-wide release-documentation issues #4004 (release note) and #4008 (epoch entry).
