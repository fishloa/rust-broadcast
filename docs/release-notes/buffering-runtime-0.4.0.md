# buffering-runtime 0.4.0

_Released 2026-11-15._

### Changed
- BREAKING: `time::duration_micros` (which rounded every span *up*) is split by what the span is, so a reading and a difference of two are truncated to the microsecond they are in and only a configured window still rounds up: `time::instant_micros` (a clock instant or a difference, floored, the `time::duration_sub` `ceil(a) - ceil(b)` replaced by a real `ceil`-free `duration_between`) and `time::window_micros` (a configured window, rounded up so a sub-microsecond setting is one microsecond, never a zero-length window). A logged "now" is now the microsecond it is in, so a replayed log no longer runs a microsecond in the future; the rule is documented once in the `time` module and the maximum a difference of two floorings can understate it is the new `time::MAX_DIFFERENCE_ERROR` (999 ns). `time::duration_sub` is gone (`duration_between` is the one difference). Node tags and the C-ABI record fields are unchanged plain integers; only their rounding moves (#2728).
- BREAKING: the public time surface is the workspace's shared types, not the crate's own: every span (config field, `on_chunk`/`on_media`/`on_track_media`/`on_tick`/`on_hint` argument, `Event`/`Stats`/`JitterEstimate`/`StallMemorySnapshot`/`Input` field, and the `Policy`/`MinWindow`/`DeliveryJitter` parameters) is `core::time::Duration`, and every playback (PTS) position is `broadcast_common::clock33::Clock27`, the validated 27 MHz clock value. The `Micros` and `Ticks27` newtypes are gone, and the `_us` / `_27mhz` suffixes went with them where the type already says it: `policy.initial_us` is `policy.initial`, `Event::StartPlaying::lead_us` is `lead`, `Pause::depth_us`/`resume_target_us` are `depth`/`resume_target`, `TargetChanged::old_us`/`new_us` are `old`/`new`, `OverMax::need_us`/`max_us` are `need`/`max`, `StallMemorySnapshot::peak_us`/`age_us` are `peak`/`age`, and `ControllerConfig::starve_threshold_us`/`nodata_after_us`/`track_silence_timeout_us`/`granularity_hold_us`/`granularity_decay_us` are `starve_threshold`/`nodata_after`/`track_silence_timeout`/`granularity_hold`/`granularity_decay` (the `jitter`/`policy` spans keep their names minus the suffix: `min_window`, `interval`, `outlier`, `bucket`, `hold`, `decay`, `discontinuity`, `min`, `initial`, `max`, `margin`, `max_step_down_per_s`, `reprime_floor`, `reprime_hold`). `Controller::target_us()` is `target()`, `Policy::target_us`/`start_us`/`resume_us`/`max_us` are `target`/`start`/`resume`/`max`, `JitterEstimate::{pdv_last_us,baseline_us,stall_peak_us,rfc3550_jitter_us}` are `{pdv_last,baseline,stall_peak,rfc3550_jitter}`, `DeliveryJitter::baseline_us`/`stall_peak_at(now)` take and return spans, and `InputLog::replay` returns `(Duration, Event)`. `pts90k_to_27mhz(pts)` is `pts90k_to_clock27(pts) -> Result<Clock27, ClockOutOfRange>`. Migration: build a span with `Duration::from_micros(n)` and a position with `Clock27::from_27mhz(ticks)?` (a reduced tick count is always on the clock), read a position back with `.ticks()`. New `time` module (`duration_micros`, `micros_as_duration`, `duration_add`, `duration_sub`, `duration_between`, re-exporting `Clock27`) for the boundary between a span and the whole microseconds the engine computes in. A sub-microsecond span rounds up to one microsecond, so a caller cannot set a zero-length window by accident. `Clock27` now serializes as its 27 MHz tick count (it carried no `Serialize` before).
- BREAKING: the input-log `config` row token for a span drops the unit suffix (`jitter.min_window`, `policy.initial`, `starve_threshold`, `policy.max_step_down_per_s`, ...). A log recorded with the old `_us` tokens still parses: `ConfigKey::from_name_or_legacy` accepts both, so an archived log replays unchanged.
- BREAKING: `EventRecord` is now `#[non_exhaustive]`; it is built by `Event::to_record` and field-assigned, never by an external struct literal (#2664).
- `Micros` and `Ticks27` (0.3.0, removed above) were `#[repr(transparent)]` newtypes over `u64` instead of type aliases, so a microsecond "now" and a 27 MHz media position could no longer be swapped at a call site (`on_chunk(now, bytes, pcr)`, `on_media(now, media_end)`). That distinction now comes from `Duration` vs `Clock27`. Migration: build with `Micros(n)`/`Ticks27(n)` (or `::new`/`From<u64>`), read with `.0`/`get()`, and compare/print against the same newtype (`target_us() == Micros(300_000)`). Still plain data (`#[repr(transparent)]`, `serde` transparent, one `u64` per field on the C ABI); `Micros` has `saturating_add`/`saturating_sub`, `+=`/`-=` and `Ord`, and `Display`/`FromStr` on both for the input-log text format.
