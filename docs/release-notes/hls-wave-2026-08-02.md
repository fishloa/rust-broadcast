# HLS wave — 2026-08-02

A new crate, two breaking bumps, and the completion of RFC 8216bis-22 coverage.
Nine crates ship together; publish order matters and is given below.

## What changed, in one line

HLS support went from "an LL-HLS origin" to a complete, independently-validated
implementation: all 32 playlist tags, spec-derived `EXT-X-VERSION`, classic
MPEG-TS output alongside fMP4, and Apple's own conformance validator wired in
as a CI oracle.

## Breaking changes

**`transmux` 0.22.0** — M3U8 playlist syntax moved to the new `broadcast-hls`
crate. `transmux::MediaPlaylist`, `MasterPlaylist`, `MediaSegment`,
`LowLatencyConfig` and friends are gone; import them from `broadcast_hls`
instead. **No re-export shim** — two names for one type hides which crate owns
it, and the deprecation window never closes in practice.

**`ll-hls-runtime` → `hls-runtime` 0.4.0** — the crate gained a non-low-latency
mode, so the name was wrong. Types drop the `Ll` prefix (`LlHlsOrigin` →
`HlsOrigin`). `HlsOrigin::new()` is replaced by `HlsOrigin::builder(trunk)`,
because the old four-positional-argument constructor could not express
"classic HLS, no low latency" at all. `ll-hls-runtime` stays on crates.io at
0.3.1, frozen.

## Why a new crate

Four things parse M3U8 — `transmux`, `media-doctor`, `hls-runtime` and the fuzz
sub-workspace — and only one wants an origin engine. Before this, `media-doctor`
pulled an entire any-to-any container muxing hub in order to parse text.

Folding syntax into `hls-runtime` instead was tested and is impossible: the
origin is `Trunk`-backed, so `transmux → hls-runtime → media-plane → transmux`
is a dependency cycle the moment the runtime feature is enabled.

## Defects fixed

Each was live in published code. None was caught by existing tests.

- **CMAF-HLS emitted zero `#EXT-X-MAP` tags** — an unconditional §3.1.2 MUST.
  Found by Apple's `mediastreamvalidator` on its first run; `media-doctor` had
  passed the same output every time, because a validator and a renderer written
  by the same hand share their blind spots.
- **`#EXTINF` was rounded to three decimals** — Apple's `9.9766` became `9.977`,
  corrupting timings on every repackage. Only the real-stream fixtures could
  catch this; every hand-made fixture was authored at exactly the precision the
  bug preserved.
- **`EXT-X-VERSION` was hard-coded to 9**, over-declaring every playlist. §7 says
  a client MUST NOT attempt playback above its supported version, so this told
  every client on 6/7/8 to refuse a stream it could play. Now derived from the
  features actually emitted, and cross-checked against the versions the RFC
  authors declared on their own §9 examples.
- **Integral durations rendered as `4.000` with no version tag** — §4.4.4.1
  requires integer durations below version 3. Now rendered `4`.
- Five further conformance findings from an adversarial audit: missing
  `CAN-SKIP-DATERANGES` and `HOLD-BACK`, an unvalidated 85% partial-segment
  duration floor, `EXT-X-SESSION-KEY` accepting `METHOD=NONE` (a MUST NOT), and
  a `_HLS_msn` bound looser than the spec's.

## New capability

- **Classic MPEG-TS HLS** end to end: `Container::MpegTs` in the origin, and
  `OutputKind::TsHls` in `multimux`. Segments carry PAT+PMT in-band, so no
  `EXT-X-MAP` is emitted — omitted by default, not forbidden, since §3.1.1 makes
  it a disjunction rather than a container restriction.
- **Runtime admin API** (`multimux`) — add, remove and reload routes without
  restarting. Previously a new camera meant dropping every viewer on every other
  channel. Separate listener, auth mandatory by construction.
- **Signed-URL egress auth** — HMAC-SHA256, path-bound, constant-time compare,
  key rotation.
- **Apple `mediastreamvalidator`** wired into CI as an independent oracle,
  calibrated against the RFC's own example playlists first.

## Publish order

Dependencies first — `cargo publish` requires each to be on the index already:

```
1. broadcast-common   2. broadcast-hls   3. transmux      4. media-plane
5. hls-runtime        6. broadcast-auth  7. media-doctor  8. multimux
9. multimux-cli
```

## Known gaps

Documented in `docs/HLS-SUPPORT.md`, each pinned by a test: multivariant tag
re-ordering on re-emit (formatting, not data loss), and §9.10/§9.11 not usable
as fixtures because the RFC abridges them with a literal `...` line.
