# st12-1 0.4.0

_Released 2026-10-16._

**Epoch-forced major-class release; no API break of its own.** Adds `FrameRate::max_frame` and `LtcFrame::validate_for_rate` (rate-aware frame-number bound 29/24/23) and rebuilds against `broadcast-common` 10, which is what makes the version `0.4.0`. The README and crate-root docs are restructured (what it does and does not do, a standards-supported table: ST 12-1:2014 LTC codeword supported, ST 12-2/12-3 not implemented).

## Why this version

- **Proposed version:** 0.3.1 -> **0.4.0** (major-class: 0.x minor-epoch bump).
- **Own API/behaviour change class:** minor (FrameRate::max_frame, validate_for_rate (additive)).
- **cargo-semver-checks vs live 0.3.1 (all features):** none flagged. (Lint-based: it misses type changes of existing fields/arguments, so the CHANGELOG BREAKING list is the primary evidence.)
- **Epoch cascade:** epoch cascade from broadcast-common. Siblings it depends on that move epoch in this wave: broadcast-common.
- **Caret epoch:** 0.3 -> 0.4; every workspace dependent must move with it.

## Dependency changes

```toml
-broadcast-common = "9.4"
+broadcast-common = "10.0"
```

## Breaking changes and migration

No API break of its own; the major-class bump is the `broadcast-common` epoch cascade (9 -> 10), which the epoch-purity rule treats as breaking for this crate whatever its API diff.

What to do: move every `broadcast-common` requirement in your tree to `10` so a single copy resolves; `st12-1` 0.4 and a `broadcast-common` 9.x type cannot be mixed in one `Parse`/`Serialize` bound. `Serialize::to_bytes` was removed from `broadcast-common` 10 (it could panic); use the fallible form:

```rust
// before (broadcast-common 9)
let bytes = frame.to_bytes();
// after (broadcast-common 10)
let bytes = frame.try_to_bytes()?;
```

## What changed (from CHANGELOG `[Unreleased]`)

#### Documentation
- README and crate-root docs restructured: what it does / does not, standards-supported table (ST 12-1:2014 LTC codeword; ST 12-2/12-3 not implemented), feature table, design notes.

#### Changed (BREAKING: epoch — requires broadcast-common 10)
- Builds against new caret epochs of workspace siblings (`broadcast-common` 9 -> 10). A caret-epoch change is major-class for this crate under the epoch-purity rule (`docs/RELEASE-AUDIT.md` §2), whatever its own API diff. `Serialize::to_bytes` was removed (use `try_to_bytes`); consumers must resolve a single `broadcast-common` 10.

#### Added
- `FrameRate::max_frame` and `LtcFrame::validate_for_rate`: rate-aware frame-number
  bound (29/24/23) for callers that know the stream's counting mode (r13-S12-W1, #1117).
