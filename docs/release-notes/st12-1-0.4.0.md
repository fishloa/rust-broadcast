# st12-1 0.4.0

_Released 2026-10-16._

**Epoch-forced major-class release.** Adds `FrameRate::max_frame` and `LtcFrame::validate_for_rate` (rate-aware frame-number bound 29/24/23).

## Why this version

- **Proposed version:** 0.3.1 -> **0.4.0** (major-class: 0.x minor-epoch bump).
- **Own API/behaviour change class:** minor (FrameRate::max_frame, validate_for_rate (additive)).
- **cargo-semver-checks vs live 0.3.1 (all features):** none flagged. (Lint-based: it misses type changes of existing fields/arguments, so the CHANGELOG BREAKING list is the primary evidence.)
- **Epoch cascade:** epoch cascade from broadcast-common. Siblings it depends on that move epoch in this wave: broadcast-common.
- **Caret epoch:** 0.3 -> 0.4; every workspace dependent must move with it.

## Dependency changes

```toml
-broadcast-common = "9.4"
+broadcast-common = "10.0"
```

## Breaking changes and migration

No API break of its own; the major is the `broadcast-common` epoch cascade.

## What changed (from CHANGELOG `[Unreleased]`)

#### Added
- `FrameRate::max_frame` and `LtcFrame::validate_for_rate`: rate-aware frame-number
  bound (29/24/23) for callers that know the stream's counting mode (r13-S12-W1, #1117).
