# transmux 0.32.0

_Released 2026-11-15._

- `scte35-splice` 6 -> 7: `SpliceTime::pts_time` is a validated `broadcast_common::clock33::Clock33`, and `SpliceInsert` carries its flags and times in one `SpliceMode` (see that crate's changelog).

### Changed
- BREAKING: the segmenters and packagers take and expose their durations as `core::time::Duration` instead of bare `f64` seconds, `u32` milliseconds or `u64` nanoseconds (part of #2731). `Segmenter::new`, `ll_hls::LlHlsSegmenter::with_part_target`/`with_part_target_at`, `ll_dash::LlSegmenter::new`, `repackage::Repackage::new` and `ll_dash::LlDashPackager::new` take their target/segment/chunk duration as a `Duration`; `ll_hls::PartInfo::duration` and `ll_hls::SegmentInfo::duration` and `ts_hls::TsSegment::duration` are `Duration`s; `LlHlsSegmenter::part_target_secs()`/`part_target_ms()` become one `part_target() -> Duration`; `LlDashPackager::segment_duration_secs`/`chunk_duration_secs` are `segment_duration`/`chunk_duration: Duration` and `availability_time_offset()` returns that `Duration`; `SmoothPackager::target_duration_secs: u32` is `target_duration: Duration`; and `LlHlsSegmenter::set_start_time_ns`/`StreamingTsHlsSegmenter::set_start_time_ns` are removed in favour of the existing `set_start_time(Duration)`. Wire formats are unchanged (a `Duration` renders the same decimal seconds at the encode edge). Migration: `Segmenter::new(t, ts, 2.0)` -> `Segmenter::new(t, ts, Duration::from_secs(2))`, `with_part_target(t, ts, 1.0, 334)` -> `with_part_target(t, ts, Duration::from_secs(1), Duration::from_millis(334))`, `part_target_ms()` -> `part_target()`, `set_start_time_ns(ns)` -> `set_start_time(Duration::from_nanos(ns))`.
- `validate_media_segment` reports a timed sample with no stated span on a segment this crate wrote as `media.sample.timing`, the same finding `validate_cmaf_track` makes, without needing the init segment: a segment does not type its tracks, so every `traf` of a segment validated on its own is untyped and a zero `trun` duration there is an unstated span, not a declared zero length. A segment that carries no video-typed track at all keeps `media.sample.zero-duration` (`SegmentOrigin::External` zero spans, or a video-typed fragment in `FromIr`) (#2788).
- BREAKING: `Error::TimestampSpanOverflow` (a sample's `pts - dts` exceeds `i64`) and `Error::CompositionOffsetRange { offset }` (the offset does not fit the signed 32-bit `trun` field) replace the two `Error::InvalidInput("...")` strings from `Sample::composition_offset`, so a caller branches on the typed variant rather than the message text (#2734).
- BREAKING: the decoded codec records `AvcSpsInfo`, `HevcSpsInfo`, `VvcSpsInfo`, `AudioSpecificConfig`, `Ac3SyncframeInfo`, `Ec3SyncframeInfo`, `DtsCoreFrameInfo`, `NclxColourInfo`, `AvcFieldInfo` and `DecoderSpecificInfo` are `#[non_exhaustive]`, so a field the decoder learns to report later is an additive change for a consumer that holds one. A decoder or parser is the only producer: migrate to reading or parsing the record instead of building it by struct literal, and `AvcFieldInfo::new(bottom, frame_num, is_reference, idr)` and `NclxColourInfo::new(colour_primaries, transfer_characteristics, matrix_coefficients, full_range_flag)` (padding `reserved` = 0) build the two a caller composes itself (#2736).
- BREAKING: `DemuxEvent::ClockReference` carries the parsed `Pcr` itself (`pcr: Option<mpeg_ts::Pcr>`, and `clock_reference(ticks, pcr, ..)` takes it), so every observation keeps its 33-bit base and 9-bit extension (ISO/IEC 13818-1 §2.4.3.5) instead of only the first one. The side queue behind the batch fold grew by one entry per PCR for the life of a streaming demux and compared only its head against each event's 27 MHz `ticks`, so every later off-clock extension was lost and a failed rebuild dropped the sample silently; the queue is gone and `TsDemux` reads the wire value from the event (#2719).
- BREAKING: `FlvError` gains `TimestampBackwards { previous, next }` and `SampleDurationTooLarge { ticks }`. `StreamingFlvDemux` now reports a publish whose tag timestamps step backwards on a track as `TimestampBackwards` (it used to emit the previous sample with a silently zero-length span) and a forward delta too large for a span as `SampleDurationTooLarge`, instead of an unchecked `i64` subtract that panicked a debug build (#2720).
- BREAKING: a sample span is never invented, and the helpers that used to invent or swallow one are typed: `SampleTiming::with_duration` and `Sample::rescale_timescale` cannot fail (`with_duration` now returns `Self`, a positive span is exactly what it sets; `rescale_timescale` returns `Result<Self>` and refuses a span that no longer fits 32 bits instead of clamping it to one tick or `u32::MAX`). `Sample::new`/`from_annexb`/`from_raw` return `Result<Self>`: a PTS with no DTS is refused rather than fabricating `dts = pts`, and a zero span with no timestamps is refused rather than swallowed. A caller that has both timestamps uses the new infallible `Sample::timed`/`Sample::timed_annexb`/`Sample::timed_raw`; `Sample::from_duration` takes a `NonZeroU32`. The fragment validator gained `SegmentOrigin`: a zero span on a video track of a segment this crate wrote means the IR never stated one and is `media.sample.timing` (WARNING), while any other track's zero stays `media.sample.zero-duration` (ERROR); `validate_media_segment` and `validate_cmaf_track` take the origin (#2721).
- BREAKING: `SampleTiming` is now an enum instead of a struct. A sample with a clock carries `SampleTiming::Timed { dts, pts, duration: Option<NonZeroU32> }` (the span is stated where the source had one, `None` where it did not); a sample with only a span carries `SampleTiming::DurationOnly { duration: NonZeroU32 }`; and a section-carried track stays `timing: None`. `SampleTiming::from_options` is removed (use `SampleTiming::timed`, `SampleTiming::timed_with_duration` or `SampleTiming::duration_only`), and `Sample::composition_offset` now returns `Result<Option<i32>>` via `checked_sub` + `i32::try_from` instead of silently clamping an over-range offset (#2688).
- BREAKING: `PcrSample::pcr_27mhz: u64` is `PcrSample::pcr: mpeg_ts::Pcr` and `PcrSample::new` takes that `Pcr`. A PCR is a 33-bit base plus a 9-bit extension (ISO/IEC 13818-1 §2.4.3.5), so a capture's off-clock extension in `300..=511` now survives into the IR instead of being lost to a 27 MHz integer; the previous reading is `PcrSample::pcr_27mhz()`, which is `None` for such a value. Migration: `PcrSample::new(pcr.as_27mhz(), pid, index, discontinuity)` becomes `PcrSample::new(pcr, pid, index, discontinuity)` with the parsed `Pcr`, and `sample.pcr_27mhz` becomes `sample.pcr_27mhz()` (#2652).
- BREAKING: `smooth_fragment::fragment_track_id` returns the IR's `TrackId` instead of a raw `u32`, so a wire `tfhd@track_ID` never leaves the typed-id boundary. Migration: `fragment_track_id(x)?` now yields a `TrackId`; compare against `TrackId::new(1)` or call `.value()` for the integer (#2647).
- BREAKING: durations and positions are typed instead of bare integers: `TimelineJumpConfig::backward`/`forward_slack` and `with_backward`/`with_forward_slack` are `Duration`s (were `backward_us`/`forward_slack_us` and the `_us` setters; `DEFAULT_JUMP_BACKWARD`/`DEFAULT_JUMP_FORWARD_SLACK` replace the `_US` constants), `TsMux::with_psi_interval`/`psi_interval` and `StreamingTsMux::with_psi_interval`/`psi_interval` take and return `Option<Duration>` (`DEFAULT_PSI_INTERVAL`; `None` or a zero span writes the PSI once, was `Option<u32>` milliseconds), and `ll_dash::LlDashPackager::latency_target` is a `Duration` (was `latency_target_ms: u32`, still written as whole milliseconds). Migration: `with_psi_interval_ms(Some(100))` -> `with_psi_interval(Some(Duration::from_millis(100)))`, `with_backward_us(u)` -> `with_backward(Duration::from_micros(u))`, `LlDashPackager::new(s, c, 3000, t)` -> `new(s, c, Duration::from_secs(3), t)` (#2693).
- BREAKING: the HLS packagers' sequence numbers are the playlist's own types: `HlsPackager::media_sequence: u64` and `TsHlsPackager::media_sequence: u64` are `msn: broadcast_hls::MediaSequence`, `ll_hls::PartCutReady::msn` is a `MediaSequence` and its `part_index` a `broadcast_hls::PartIndex`, `PartInfo::part_index`, `PartCut::part_index` and `LlHlsSegmenter::follow_part`'s `segment_seq`/`part_index` are those types too, so the number a segmenter emits is the one a playlist and a client read with no lossy cast. Migration: wrap a literal with `MediaSequence::new(..)`/`PartIndex::new(..)`, read a number back with `.value()`; `follow_part`'s `u32` arguments become those types (#2699).
- BREAKING: `EncryptConfig`, `TimelineJumpConfig`, `ll_hls::PartInfo` and `ll_hls::SegmentInfo` are now `#[non_exhaustive]`; build them with `EncryptConfig::new(scheme, kid, subsample)` + `with_*`, `TimelineJumpConfig::default()` + `with_*`, and `PartInfo::new(bytes, duration, segment_seq, part_index)`/`SegmentInfo::new(bytes, duration, segment_seq)` + `with_*` instead of struct literals (#2664).
- BREAKING: every timescale is a `Timescale` end to end; none is a raw integer a consumer decides the meaning of zero for. `SegmentIndexBox::timescale`, `rtp::RtpStreamTrack::{clock_rate, new}`, `SdpTrack::clock_rate`, `TrackAligner::new` (its `(TrackId, bool, Timescale)` tuples, no longer reading a zero rate as 1 Hz), `DemuxEvent::ClockReference::clock_hz` and `clock_reference`, `IR_TIMESCALE`, `track_spec_from_quality_level`, `dash::TrickModeRepr::timescale` and `LlHlsSegmenter::with_part_target_at` take or hold `Timescale`; a zero `sidx.timescale` is `Error::InvalidValue`, and `CencDecryptor::demux` refuses a zero or missing `mvhd`/`mdhd` timescale (typed error) instead of falling back to 1000 Hz / the movie timescale. Added `VIDEO_CLOCK_TIMESCALE` and `SMOOTH_DEFAULT_TIMESCALE`. Migration: `90_000` -> `Timescale::from_nonzero(90_000)`; a runtime `u32` -> `Timescale::try_new(v)?` (#2657).
- The RTMP spokes match `rtmp_runtime::message::MessageTypeId` instead of the `msg_type` byte constants for the message types they dispatch on (`SetChunkSize`, `Audio`, `Video`, `DataAmf0`); no public transmux type changes (#2666).
- PTS/DTS demux reads go through `mpeg_pes`'s checked `Pts`/`Dts::ticks()` and the TS muxer writes the PTS-only field with its own `encode_timestamp` (the same `pack_marked` codec) instead of `mpeg_pes::Pts(u64)`; demux output and mux bytes are unchanged (#2747).

#### Changed
- PSI parsing/building in `ts_demux`/`ts_mux` now uses `dvb_si::tables::pat::PatSection` and `dvb_si::tables::pmt::PmtSection` instead of hand-rolled copies; behaviour and goldens unchanged (#2667).

- BREAKING: `Sample` timing is now a single optional `SampleTiming { dts, pts, duration }` (`Sample.timing`) instead of separate `dts`/`pts`/`duration` fields; `TrackSpec.timescale` and `Track.timescale()` are now `broadcast_common::timescale::Timescale` (non-zero) instead of `u32`. Call sites that read `sample.dts`/`sample.pts`/`sample.duration` must go through `sample.timing.map(|t| t.dts)` etc., and timescale values through `.get()` (#2657).

- BREAKING: uses `rtsp_runtime`'s typed `InterleavedFrame` payload (`Bytes`) and `ChunkSize` newtype (#2659).
