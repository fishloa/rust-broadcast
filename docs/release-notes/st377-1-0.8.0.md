# st377-1 0.8.0

_Released 2026-11-15._

Minor-class release (0.7 -> 0.8). The MXF local sets now reproduce the encoder's own Batch/Array header when written back, so a real OP1a file parses and serializes byte-identically; counts and lengths are range-checked before they are written, and the UL/Strong-Reference/AUID identities are distinct types instead of three aliases of the same array.

Version: 0.7.0 -> 0.8.0.

## Breaking changes and migration

### `UlBytes`, `StrongRef` and `Auid` are distinct newtypes

They were type aliases over `[u8; 16]` (ST 377-1 §4.2/§5.4.4). A UL key, a Strong Reference and an `Auid` share one wire form, so as aliases the compiler could not tell a reference target from a key it was passed for. Every typed field keeps the same bytes on the wire (`From<[u8; 16]>` / `From<UlBytes> for [u8; 16]`, `as_bytes()` convert), and `Auid` is transparent over `UlBytes`.

```rust
// before
let key: UlBytes = [0u8; 16];       // an alias, so any [u8; 16] fit anywhere
let target: StrongRef = key;        // compiled: both were the same type
// after
let key: UlBytes = UlBytes([0u8; 16]);
let target: StrongRef = StrongRef::NULL;   // or StrongRef(other_bytes)
```

### `PrimerPack::entries` is a `Vec<LocalTagEntry>`

The anonymous `(u16, UlBytes)` tuple is the named `LocalTagEntry { tag, uid }` (ST 377-1 Table 15), so an entry's fields are named instead of positional.

```rust
// before
for (tag, uid) in &primer.entries { .. }
// after
for LocalTagEntry { tag, uid } in &primer.entries { .. }
```

### `serialize_uid_batch` is fallible and `parse_uid_batch` is `UidBatch::parse`

`serialize_uid_batch` returns `Result<Vec<u8>>`: a Batch/Array whose count exceeds `u32::MAX` is reported as `Error::FieldOverflow` rather than written with a wrapped count. `parse_uid_batch` is replaced by `UidBatch::parse`, which returns the parsed Batch with its header rather than only its elements. `Error` gains `FieldOverflow(broadcast_common::len::FieldOverflow)`.

```rust
// before
let items = parse_uid_batch(&bytes)?;
let out = serialize_uid_batch(&items);
// after
let batch = UidBatch::parse(&bytes)?;
let items = batch.items();
let out = serialize_uid_batch(items)?;
```

### The typed Sets carry the Batch headers they parsed

`PartitionPack`, `Preface`, `ContentStorage`, `MaterialPackage`, `SourcePackage` and `Sequence` gain one `*_batch: Option<UidBatch>` field per UL Batch property (`essence_containers_batch`, `identifications_batch`, `dm_schemes_batch`, `packages_batch`, `essence_container_data_batch`, `tracks_batch`, `structural_components_batch`). Fill it with `None` for a freshly built value; `PartialEq` compares a Batch header only when both sides retain one, so a freshly built Set still equals the same Set parsed from a file.

```rust
// before
let preface = Preface { identifications, .. };
// after
let preface = Preface { identifications_batch: None, essence_containers_batch: None, ..parsed };
```

## Fixes

- A typed Set parsed from a real file reproduces that encoder's own 8-byte Batch/Array header on serialize instead of this crate's canonical one. Measured on the real OP1a fixture, an empty `EssenceContainers` Batch carries `item_len = 0` (inside both the Partition Pack value and the typed `Preface`), which the old serializer rewrote as `item_len = 16`, so parse -> serialize was not byte-identical.
- Counts and lengths are range-checked before they are written instead of being narrowed with `as u32`: the Random Index Pack's trailing overall Length and the Primer Pack's entry count go through `broadcast_common::len::fit_u32` and report `Error::FieldOverflow` when over range, rather than silently writing a different on-wire length.
- A Primer Pack's duplicate-tag/duplicate-UL check sorts each dimension instead of running a nested loop over the untrusted entry count: a crafted ~1.2 MB Primer (65 536 distinct tags, duplicate last) cost ~2e9 comparisons before the duplicate was reported.

## Added

- `UidBatch` (re-exported at the crate root): a Batch/Array of 16-byte ULs with the header it was parsed with, `items()`, `header()`, `with_header()`, `parse()` and `serialize()`.

## Dependencies

- `broadcast-common` 12 -> 13 (published first, from tag `broadcast-common-v13.0.0`).
