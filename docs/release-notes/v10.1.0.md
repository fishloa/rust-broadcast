# v10.1.0 — 2026-09-26

Lockstep minor carrying a **security fix for the `dvb-si` DSM-CC object carousel**. **Upgrade if
you decompress carousel modules from broadcasts or captures you do not control.** It is a drop-in
update for 10.0.x. The version is a minor only because two public items were added.

`dvb-t2mi`, `dvb-bbframe`, `dvb-conformance` and `dvb-tools` move to 10.1.0 to stay in lockstep.
None of them changed.

## Security (dvb-si)

- **GHSA-hxv4-gqm8-whw6:** `carousel::biop::message::decompress_zlib` read a
  `compressed_module_descriptor` zlib stream to completion with no output limit. About 1 MiB of
  compressed zeros inflated to about 1 GiB.
- **GHSA-h6j8-r8j3-36xg:** the BIOP message and IOR parsers added 32-bit wire lengths to a
  position with plain `+`. On 32-bit targets an oversized length wrapped, so the bounds check
  that followed was bypassed and the slice index panicked. 64-bit targets were not affected.

## Added (dvb-si)

- `MAX_DECOMPRESSED_MODULE_SIZE` (64 MiB), the ceiling `decompress_zlib` now enforces.
- `decompress_zlib_bounded(data, max_len)` takes an explicit limit, for callers with a tighter,
  descriptor-declared size.

## Behaviour changes (dvb-si)

- **Decompression limit:** `decompress_zlib` returns an error once decompressed output would
  exceed `MAX_DECOMPRESSED_MODULE_SIZE`. Carousel delivery is bandwidth-bound, so real modules
  are far smaller than that.
- **32-bit length arithmetic:** every wire-declared 32-bit length in `carousel/biop` goes through
  one checked helper. An oversized length is now `Error::SectionLengthOverflow` on every target.

## Testing

- **`dvb-si/tests/decompression_size_bounds.rs`** runs under a per-thread capped allocator. It
  inflates a stream past the limit and checks the result is `Err`, and it checks exact-boundary
  behaviour: `max` bytes gives `Ok`, `max + 1` gives `Err`, and `usize::MAX` means no limit.
  The out-of-range case fails against 10.0.1.
- **Per-parser tests** set each 32-bit length field to `0xFFFF_FFFF`.
- **Direct test of the checked helper:** `span(usize::MAX - 1, 4, usize::MAX)` returns `Err`.
- The crate also builds for a 32-bit `usize` target (`thumbv7em-none-eabi`).
