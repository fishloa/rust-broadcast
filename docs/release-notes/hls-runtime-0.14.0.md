# hls-runtime 0.14.0

_Released 2026-11-15._

### Changed
- BREAKING: `client::VariantInfo::url: String` is `uri: Option<url::Url>`: the absolute URL the manifest declares (`Some` for an HLS master's media playlist or a DASH Representation's Initialization Segment), and `None` for a protocol whose variant has none of its own (Smooth, whose fragments live under the manifest's URL). No empty string stands in for "no URI". `client::VariantInfo::new` takes the `Option<url::Url>`, and `HlsClient::select_variant` reads the stored URL instead of re-resolving text. Also `bandwidth: u32` is `bandwidth: u64`, so a DASH `@bandwidth` above the `u32` range is carried as parsed rather than saturated to `u32::MAX`. Migration: read `v.uri` as an `Option<&Url>` (`v.uri.as_ref().map(Url::as_str)` for the text), pass `Some(url)`/`None` to `VariantInfo::new`, and compare or collect `v.bandwidth` as a `u64` (`u64::from(..)` where a `u32` is wanted) (#2702).
- BREAKING: `server::ClosedSegment::start` is a `timed_metadata::MediaTime` (was `start_ns: u64`) and `ClosedSegment::new` takes one, so a closed segment's position travels with the timebase the `Trunk` assigned it (#2693).
- BREAKING: `server::ClosedSegment::duration_secs: f64` is `duration: core::time::Duration` (the `Trunk`'s own segment duration, carried with no float round-trip), and `ClosedSegment::new` takes a `Duration`. Migration: read `segment.duration.as_secs_f64()` where a seconds value is wanted (#2713).
- BREAKING: `HlsOriginConfig::new`'s target duration is a `core::time::Duration` (was `target_duration_secs: f64`), the crate-wide span type; a zero target is still `HlsOriginBuildError::InvalidTargetDuration`, and a non-finite or negative value is now unrepresentable rather than a build error. The rendered `EXT-X-TARGETDURATION` is unchanged (rounded up to whole seconds at the encode edge). Migration: `HlsOriginConfig::new(trunk, 4.0, w)` becomes `HlsOriginConfig::new(trunk, Duration::from_secs(4), w)` (#2731).
- BREAKING: HLS sequence numbers are typed end to end. `client::ResourceId::Part { msn, part }` and `ResourceId::Segment { msn }` carry a `broadcast_hls::MediaSequence` and a `broadcast_hls::PartIndex` (was `u64`), `client::BlockingReload` too, and `Error::MediaSequenceOverflow`/`Error::DeltaNotMergeable` carry a `MediaSequence`; `HlsOrigin::current_live_edge` returns `(MediaSequence, Option<PartIndex>)` and `HlsOrigin::next_media_sequence` a `MediaSequence`. `Debug` still renders the bare numbers, so a log line and the client golden are unchanged. The server's wire query (`BlockingQuery::hls_msn: Option<u64>`, `hls_part: Option<u32>`) stays numeric — parsing the query is the adapter's job. Migration: wrap a literal with `MediaSequence::new(..)`/`PartIndex::new(..)`, read a number back with `.value()` (#2699).
- `serde` implies `broadcast-hls/serde`, so the sequence numbers serde-encode as the bare numbers the fields used to be.
- BREAKING: `HlsClientConfig::new(url)` takes a `url::Url` (not `impl Into<String>`), `HlsClientConfig::playlist_url`/`playlist_base` are `url::Url`, and every `Action` URL is a `url::Url`; `Action::FetchPlaylist` carries a `PlaylistRequest { url, blocking, skip }` (`PlaylistRequest::request_url()` returns the query-augmented `Url`); `HlsClient::set_playlist_base` is removed (use `HlsClientConfig::with_playlist_base`) (#2655, #2661).
- BREAKING: `Action::FetchResource::byte_range` is `Option<broadcast_common::range::ByteSpan>` (offset + non-zero length) instead of `Option<(u64, u64)>` (#2655).
- BREAKING: `HlsOriginBuilder` and `HlsOrigin::builder` are replaced by `HlsOriginConfig` and `HlsOrigin::new` (the `SmoothOrigin` shape): the required `target_duration_secs` and `window_segments` are `HlsOriginConfig::new(trunk, target_duration_secs, window_segments)` arguments, the optional settings stay `with_*`, and `HlsOrigin::new(config)` builds it. `HlsOriginBuildError::MissingTargetDurationSecs`/`MissingWindowSegments` are gone (the required values cannot be missing). Migration: `HlsOrigin::builder(trunk).with_target_duration_secs(t).with_window_segments(w)…build()` becomes `HlsOrigin::new(HlsOriginConfig::new(trunk, t, w)… )` (#2661).
- BREAKING: `client::VariantPolicy`, `client::VariantInfo` and `client::RenditionInfo` are now `#[non_exhaustive]`; build them with `Default::default()`/`VariantInfo::new`/`RenditionInfo::new` + `with_*` instead of struct literals (#2664).
- `PART-TARGET`, `PART-HOLD-BACK`, every `EXTINF`/part `DURATION` and the closed-segment duration come from `DecimalSeconds::from_duration`/`from_duration_scaled` instead of a fallible construction whose invariant the caller had to prove with an `expect`; an origin no longer has a panicking path in its playlist rendering. The window keeps each segment's `Duration` and halves it once, for rendering, rather than storing rounded seconds.
- BREAKING: `HlsOriginBuilder::with_low_latency` takes the part target as a `Duration` instead of milliseconds (`with_low_latency(Duration::from_millis(500))`), and `HlsOrigin::set_part_target_ms(u32)` is `HlsOrigin::set_part_target(Duration)`: the origin keeps the target as a `Duration` and renders `PART-TARGET`/`PART-HOLD-BACK` from it. A zero target is still `HlsOriginBuildError::ZeroPartTarget`.
- BREAKING: the non-blocking-reload hint is `Action::Wait(Duration)` instead of `Action::WaitMs(u64)`, so every span in the API is one type.
- BREAKING: `HlsClient::poll_timeout` takes and returns `broadcast_common::stage::Timestamp` instead of `std::time::Instant`, so the client is driven from the same caller-supplied clock as `broadcast-client`'s sources (and from a recorded clock in a test); it is no longer `std`-only.

### Removed
- Removed the unused `axum` dev-dependency.
