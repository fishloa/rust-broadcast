# st377-1 0.5.0

_Released 2026-10-16._

**Epoch-forced major-class release; no API change.** st377-1 rebuilds against `broadcast-common` 10, and the workspace epoch-purity rule makes that a `0.4` -> `0.5` bump. The README and crate-root docs are restructured (what it does and does not do, standards-supported table, explicit lists of typed Sets versus identified-only Sets, feature table) and the README quick start now includes the `len_size` field so it matches the compiled doctest.

## Why this version

- **Proposed version:** 0.4.0 -> **0.5.0** (major-class: 0.x minor-epoch bump).
- **Own API/behaviour change class:** patch (documentation and internal test/doc adaptation only).
- **cargo-semver-checks vs live 0.4.0 (all features):** none flagged. (Lint-based: it misses type changes of existing fields/arguments, so the CHANGELOG BREAKING list is the primary evidence.)
- **Epoch cascade:** epoch cascade from broadcast-common. Siblings it depends on that move epoch in this wave: broadcast-common.
- **Caret epoch:** 0.4 -> 0.5; every workspace dependent must move with it.

## Dependency changes

```toml
-broadcast-common = "9.4"
+broadcast-common = "10.0"
```

## Breaking changes and migration

No source change is needed for this crate's own API. Move every `broadcast-common` requirement in your tree to `10` so a single copy resolves (a `broadcast-common` 9.x type cannot satisfy this crate's `Parse`/`Serialize` bounds). `Serialize::to_bytes` was removed in `broadcast-common` 10 because it could panic; use the fallible form:

```rust
// before (broadcast-common 9)
let bytes = value.to_bytes();
// after (broadcast-common 10)
let bytes = value.try_to_bytes()?;
```
