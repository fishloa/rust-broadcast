# scte104 0.6.0

_Released 2026-10-16._

**Breaking release.** `insert_audio_descriptor`, `insert_audio_provisioning` and `insert_alternate_break_duration` are typed from Tables 9-33..9-36 (re-transcribed into `docs/ansi_scte_104/audio-and-alternate-break.md`) instead of raw passthrough structs, and none carries a lifetime any more. The derived length fields `message_size` and `scte35_command_length` are no longer stored (they could disagree with the data), and an operation body must be exactly the length the typed structure re-serializes to. It also fixes a `MultipleOperationMessage::parse` size check that accepted a 64 KiB+ buffer whose size matched modulo 65,536, and `InsertTimeDescriptor` now rejects a `TAI_seconds` above 48 bits instead of masking it. On top of that it moves to the `broadcast-common` 9 -> 10 epoch.

## Why this version

- **Proposed version:** 0.5.0 -> **0.6.0** (major-class: 0.x minor-epoch bump).
- **Own API/behaviour change class:** major (audio/alternate-break operations typed, message_size no longer a field).
- **cargo-semver-checks vs live 0.5.0 (all features):** MAJOR (4 major, 0 minor lint failures). (Lint-based: it misses type changes of existing fields/arguments, so the CHANGELOG BREAKING list is the primary evidence.)
- **Epoch cascade:** in addition to its own breaks, builds against `broadcast-common` 9 -> 10. Siblings it depends on that move epoch in this wave: broadcast-common.
- **Caret epoch:** 0.5 -> 0.6; every workspace dependent must move with it.

## Dependency changes

```toml
-broadcast-common = "9.4"
+broadcast-common = "10.0"
```

## Breaking changes and migration

### 1. Typed audio and alternate-break operations

```rust
// before: raw passthrough, lifetime-carrying
InsertAudioDescriptor { raw: &bytes }
// after
InsertAudioDescriptor { entries }                              // Vec of audio entries, Table 9-33/9-34
InsertAudioProvisioning { entries }                            // + CodecIndex (Table 9-35)
InsertAlternateBreakDuration { alternate_break_duration }      // milliseconds
```

### 2. Derived length fields

`SingleOperationMessage::message_size`, `MultipleOperationMessage::message_size` and `InjectSectionData::scte35_command_length` are no longer fields:

```rust
// before
let m = SingleOperationMessage { message_size: n, .. };   let n = m.message_size;
// after
let n = m.message_size();      // derived accessor (usize); the command length is derived on serialize
```

Drop the field from struct literals.

### 3. Stricter parsing and serialization

- An operation whose `data_length` has trailing bytes after the typed structure is rejected instead of parsing and silently losing them.
- `MultipleOperationMessage::parse` no longer compares `messageSize` against `pos as u16`.
- `InsertTimeDescriptor` serialize rejects a `TAI_seconds` above 48 bits.
- `UtcTimestamp` docs were corrected: `UTC_seconds` is GPS-epoch (1980-01-06) and `UTC_microseconds` is the top 16 bits of the microsecond offset, not a 0..=999_999 count (documentation only).

### 4. `broadcast-common` 10

`broadcast-common` 10 removed `Serialize::to_bytes()` (the default method that panicked when `serialize_into` failed). Code that serialises any `scte104` type through it must switch to the fallible form:

```rust
// before
let bytes = value.to_bytes();
// after
let bytes = value.try_to_bytes()?;   // Result<Vec<u8>, _>
```

Your dependency graph must resolve a single `broadcast-common` 10 (a second copy on 9.x is a different `Serialize` trait and the types will not satisfy it).

## What changed (from CHANGELOG `[Unreleased]`)

#### Documentation
- README and crate-root docs restructured: scope, standards table (ANSI/SCTE 104 2023), operation coverage by group, feature table; the README quick start now matches the compiled doctest.

#### Changed (BREAKING: epoch — requires broadcast-common 10)
- Builds against new caret epochs of workspace siblings (`broadcast-common` 9 -> 10). A caret-epoch change is major-class for this crate under the epoch-purity rule (`docs/RELEASE-AUDIT.md` §2), whatever its own API diff. `Serialize::to_bytes` was removed (use `try_to_bytes`); consumers must resolve a single `broadcast-common` 10.

#### Changed (BREAKING)
- `insert_audio_descriptor`, `insert_audio_provisioning` and
  `insert_alternate_break_duration` are now typed from Tables 9-33..9-36
  (re-transcribed into `docs/ansi_scte_104/audio-and-alternate-break.md`)
  instead of raw passthrough structs: `InsertAudioDescriptor { entries }`,
  `InsertAudioProvisioning { entries }` (+ `CodecIndex`, Table 9-35) and
  `InsertAlternateBreakDuration { alternate_break_duration }` (milliseconds);
  none carries a lifetime any more (#1103 W5).
- `SingleOperationMessage::message_size`, `MultipleOperationMessage::message_size`
  and `InjectSectionData::scte35_command_length` are no longer stored fields
  (they could disagree with the data); `message_size()` is now a derived
  accessor and the command length is derived on serialize (#1103 W1).
- Operation bodies must now be exactly the length the typed structure
  re-serializes to; a `data_length` with trailing bytes is rejected instead of
  parsing and silently losing them (#1103 W4).

#### Fixed
- `MultipleOperationMessage::parse` compared `messageSize` against
  `pos as u16`, accepting a 64 KiB+ buffer whose size matched modulo 65 536.
- `InsertTimeDescriptor` serialize rejects a `TAI_seconds` above 48 bits
  instead of masking it.
- `UtcTimestamp` docs: `UTC_seconds` is GPS-epoch (1980-01-06), and
  `UTC_microseconds` is the top 16 bits of the microsecond offset, not a
  0..=999_999 count (#1103 O2).
