## `broadcast-common` — `Encrypt::encrypt` takes `&mut self`

```rust
// before
fn encrypt(&self, …)
// after
fn encrypt(&mut self, …)
```

A stateful implementor needs to own a running per-key IV counter and advance it across calls. With `&self` it could not, so `transmux`'s CENC encryptor restarted its sample index for every track sharing one key — producing **duplicate IVs under AES-CTR, i.e. a two-time pad**. On a real two-track fixture 75 of 206 IVs collided. Keystream reuse lets an attacker who knows or guesses one plaintext recover the other, so this is a confidentiality break, not a formatting bug.

The defect had been published since `transmux` 0.16.0. See `transmux` 0.20.0's CHANGELOG for the full incident, including why the first fix was insufficient (the duplicate-IV backstop ran *after* ciphering and checked uniqueness only within a single call).

### What you must change

- Any external `impl Encrypt` changes its method signature to `fn encrypt(&mut self, …)`.
- Any caller holding `&dyn Encrypt` or a generic `E: Encrypt` must hold a mutable reference or binding instead.

Recompiling is not sufficient; both are source changes.

This is why the lockstep six go to 9.0.0 rather than the 8.7.0 the change first landed under. 8.7.0 was never published — crates.io was still at 8.6.0 when the version was corrected.

## `broadcast-common` — the `stage` module (additive)

`Stage`, the incremental-drive trait (`feed`/`poll`/`finish`/`next_deadline`/`on_deadline`/`demand`) that unifies how every streaming stage in the workspace is driven, plus its supporting types:

- **`Timestamp`** — a `no_std`-safe monotonic-nanosecond newtype standing in for `std::time::Instant`, with saturating arithmetic and a `std`-only `from_instant`.
- **`Demand`** — an advisory backpressure hint.
- **`type In<'a>`** — the associated input type, so borrowed packet arrays do not cause lifetime explosion across demux variants.

`Stage` is the foundation the new `media-plane` crate is built on. Additive, with zero cascade to the ~30 workspace dependents pinned on `version = "8"`.

The `mux` module's docs now scope `Package`/`Unpackage`/`Encrypt`/`Decrypt` explicitly as the *batch / whole-file* container contract, distinct from `stage`'s *incremental* one. Documentation only.

## New crate: `media-plane` 0.1.0

The ingress/egress spine a live origin is built on, in four layers:

```text
Dialer|Listener ──► [ByteStage]* ──► IngestSession ──► [IrTransform]* ──► TrunkWriter ──► Trunk
```

A `Trunk` is the per-program hub: bounded sample/segment/event/part rings with cursor subscribers, a `ProgramId`-keyed track set, and `listen()` for bounded wake-ups. Loss is always reported **in band** (`Lagged`, or `Degraded` when a consumer's derived state is now wrong rather than merely gapped) so it cannot be skipped past via a side channel. Three egress shapes — `ServedEgress` (with `EgressResponse::Await` for blocking playlist reload), `PushEgress`, `SegmentEgress` — plus tiered retention with DVR pinning and an explicit `ArchiveOverrun` policy (`Gap` / `StallIngest` / `Terminate`).

One measured fact shapes the API: writer cost is **O(N) in cursor count** (956 ns at one reader, 9.98 µs at sixteen). So a cursor is per *distinct consumer* — a segmenter, a DVR writer, an analysis tap — never one per peer. LL-HLS serving a thousand viewers takes **one** cursor and fans out at the layer that already holds per-viewer state.

Byte layer is `no_std` + `alloc`; `Trunk` and above require `std`.

## `multimux` 0.5.0 — one ingest architecture (issue #805)

`multimux` had two parallel ingest architectures, and only one protocol actually worked. Eight of nine `InputSpec` variants were a single combined match arm that logged an error and spawned a no-op future; only `Rtmp` and `Custom` reached a real supervisor. The crate built clean, clippy was clean, the doc gate was clean, and 5674 tests passed.

It hid because **no test entered through the route dispatch path**. The sources were thoroughly tested in isolation; the dispatch that reaches them was tested by nothing.

All nine inputs — RTSP pull, RTP/UDP, TS/UDP, TS/HTTP, SRT, HLS pull, DASH pull, Smooth pull, RTMP push — now run on `media-plane`'s ingress contracts. `SourceConnector`, the old `supervise`, and the whole `pipeline` module (`SampleSource`/`run_pipeline`/`MockSource`) are **deleted**: there is exactly one path a sample can take from socket to segment.

### Breaking

- `crate::pipeline` is gone, including `SampleSource`, `run_pipeline` and `MockSource`, and with them the `testsupport` feature and the `serve_mock` example.
- `origin::supervisor::{SourceConnector, supervise}` are gone; `supervise_driver` replaces them.
- `RouteHandle` no longer owns a single `Trunk`. Serving state is per program (`ProgramId`), so accessors that returned one origin now resolve one.
- A third-party input scheme implements `media_plane::ingress::{Dialer, IngestSession}` and drives it with `supervise_driver` plus the single `source::advance_route` call. `examples/custom_scheme.rs` is the reference to copy. `InputFactory`'s own signature is unchanged.

### Also fixed

- **RTMP: one stalled publisher no longer wedges an entire route.** The old path awaited `connect()` sequentially against a bind-once listener, so a publisher that handshook then went idle blocked every subsequent one (mitigated only by timeouts). `ListenDriver` admits up to `max_sessions` concurrently.
- **A repeat program announcement no longer strands existing subscribers.** Re-announcing an already-admitted program replaced its `Trunk`; because `Trunk` is a cloneable `Arc` handle, nothing errored — every cursor already issued kept reading the orphan, so the stream silently stopped and the DVR window was dropped.
- **Samples arriving in the same read as a program announcement are no longer skipped** (#808). The segmenter subscribed live-tail *after* that batch had already landed in the ring. For MPEG-TS one packet batch routinely carries the PMT and the first PES samples together, so this risked the **first keyframe**. Fixed by `Trunk::subscribe_from_backlog`, bounded by ring capacity.
- **`multimux_parts_produced_total` / `multimux_segments_produced_total` emit again** (#809). They had no emitter after the port and reported **zero while media flowed perfectly** — a dashboard would read a healthy origin as dead. A metric that lies is worse than one that is missing.
- **DASH/LL-DASH no longer return a permanent 503 when a PMT declares a non-media elementary stream first** (#776).
- **`rtsps://` (RTSP over TLS) ingest works again** (#804). The port that converged the ingest architectures left TLS unwired, so 0.4's working `rtsps://` routes would have been refused outright — a real loss for IP cameras, which commonly use it. `run_rtsp` now performs a genuine TLS handshake, and SNI derivation is restored including IPv6 bracket-stripping (a bracketed literal is an invalid SNI name, and it fails *only* against a literal-address camera). The old code failed safe by refusing rather than opening a plaintext socket to a TLS port; that property is now asserted against the bytes a plain listener actually receives, not assumed.

### Known limitation

An MPTS route segments every program independently, but request-level program *selection* is not implemented — a request with no selector resolves to the single-program default. The options and a recommendation (`?program=2`) are documented in `route.rs`.

## The checks, which are the durable part

Every defect above shares one shape: **the absence of a check was indistinguishable from a passing check.** So this release adds the checks, not just the fixes.

- **Dispatch-path regression net.** A runtime health-transition assertion per `InputSpec` variant, plus a compile-time exhaustive `match`. Because `InputSpec` is `#[non_exhaustive]`, that match is kept *in-crate* — an external test would be forced to carry a wildcard and prove nothing. A new unwired variant is now a **compile error**.
- **End-to-end serving tests** for TS/UDP, TS/HTTP, RTMP and Custom that stream a real captured fixture through the origin and assert `#EXTINF:` in a playlist fetched over real HTTP. `#EXTINF:` specifically: a route with zero segments still emits `#EXT-X-PART-INF:`/`#EXT-X-MAP:`, so asserting on those would pass against a stub.
- **The `no_std` gate covers 37 crates, up from 29.** Eight advertised `no_std` support while ungated, including `broadcast-common`, which everything depends on. Workspace-wide `--no-default-features` does not catch this: feature unification can pull `std` in for a crate that would fail alone.

## Bump all of these together

`broadcast-common` 9 is a **major**, and pre-1.0 caret ranges cannot unify across a minor bump (`^0.2` vs `^0.3`), so a graph containing any crate still on the bc-8 line ends up with **both majors present**. Trait methods then resolve against the wrong one and the error points nowhere near the cause (issue #824):

```
no function `Section::parse` found for … / no method named `to_bytes` found …
= note: there are multiple different versions of crate `broadcast_common` in the dependency graph
```

The compiler names a file inside `dvb-si` — a crate you never edited — rather than the stale pin that caused it. **If you depend on more than one crate from this family, move them all in the same commit.** Every crate that links `broadcast-common`:

### Diagnosing a mixed-major graph

If you hit the phantom-missing-method error, this pinpoints the stray pin immediately:

```console
$ cargo tree -i broadcast-common
```

It prints every path into each version. Any subtree under an 8.x is the crate whose pin still needs raising — check it against the table above. `cargo tree -d` (duplicates) is the shorter version if you only want to know *whether* a split exists.

### The deprecated shims are gone

`dvb-common`, `dvb-scte35`, `dvb-pes`, `dvb-cc`, `dvb-emsg` and `dvb-ule` were re-export shims pinned to superseded majors, which made them a silent source of exactly this split. They are deleted from the repository and will not be released again. Depend on what they forwarded to: `broadcast-common`, `scte35-splice`, `mpeg-pes`, `cc-data`, `mp4-emsg`, `ule`.

## Compatibility

MSRV 1.86, edition 2024. Breaking for `impl Encrypt` implementors and `dyn Encrypt`/`E: Encrypt` callers, and for `multimux` consumers per the list above. The lockstep six are otherwise source-compatible; `ll-hls-runtime` and `media-plane` need only a version bump.

**`transmux` needs only a version bump *coming from 0.19*.** From **0.18 or earlier** there is a real API reshape in between — `Sample` field regrouping with `Option` timestamps, `StreamingTsHlsSegmenter::push`/`finish` returning `Result<()>` with a separate `take_ready()`, `DemuxEvent::Pcr` becoming `ClockReference`, and the new `TrackRemoved`/`TrackAbandoned` variants. Read the 0.19.0 notes as well before bumping.

Five publicly reachable enums in `multimux::source` (`DashResourceId`, `DashAction`, `HlsFetchId`, `SmoothResourceId`, `SmoothAction`) gained `#[non_exhaustive]` in this release. Downstream `match`es on them need a wildcard arm. Attached now deliberately: 0.5.0 is already breaking, so it costs nothing here, whereas adding it later would have required a further breaking release purely to attach an attribute.
