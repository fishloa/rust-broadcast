# rtmp-runtime 0.11.0

_Released 2026-11-15._

### Changed
- BREAKING: the wire identities are typed instead of bare integers (new module `ids`): `chunk::BasicHeader::chunk_stream_id`, `chunk::Message::chunk_stream_id` and `ProtocolControl::Abort`'s field are `ChunkStreamId` (2..=65599, `basic_header_encodable()`); `chunk::Message::message_stream_id` and `chunk::MessageHeader::Type0`'s field are `MessageStreamId`; `chunk::Message::timestamp` and `Type0`/`Type1`/`Type2`'s timestamp fields are `Timestamp` (a span carried as whole milliseconds) and their deltas are `core::time::Duration`; `ProtocolControl::Acknowledgement` wraps `SequenceNumber`; `chunk::ChunkAssembler::abort` takes a `ChunkStreamId`; `message::CONTROL_CHUNK_STREAM_ID`/`CONTROL_MESSAGE_STREAM_ID` are the typed constants. A chunk stream id can no longer be passed where a message stream id belongs. Wire bytes are unchanged. Migration: `Message { chunk_stream_id: 4, timestamp: 0, .. }` -> `Message { chunk_stream_id: ChunkStreamId::new(4), timestamp: Timestamp::ZERO, .. }`, `msg.timestamp` -> `msg.timestamp.millis()` where a raw count is wanted, `abort(4)` -> `abort(ChunkStreamId::new(4))` (#2768).
- BREAKING: `UserControl::SetBufferLength`'s `buffer_ms: u32` is `buffer: core::time::Duration` (wire unchanged: whole milliseconds, a span the 32-bit field cannot hold is `RtmpError::FieldOverflow` instead of a clamped value) (#2768).
- BREAKING: `ClientSession::send_audio`/`send_video` take the message `Timestamp` instead of a `u32` millisecond count; `io::AsyncRtmpClient::send_audio`/`send_video`/`encode_audio`/`encode_video` likewise (#2768).

### Fixed
- `Command::parse` takes each argument's length from the parser that read it instead of re-serializing the parsed value and measuring that. The two agree only while every AMF0 encoding is canonical (any non-zero Boolean byte decodes to `true` but re-serializes to `0x01`), so a non-canonical argument could shift every following boundary and fail the command. `amf0_values` reports a real over-long sequence with its actual length and the addressable maximum instead of a fabricated `u64::MAX`/`u64::MAX` (#2761).

### Changed
- BREAKING: `target::RtmpTarget`'s `tc_url` is a private field now, read with `RtmpTarget::tc_url()`; it is derived from `host`/`port`/`tls`/`app`, so it can never disagree with them. Migration: `target.tc_url` -> `target.tc_url()` (#2771).
- BREAKING: `RtmpError`'s three stringly catch-alls (`Malformed { what }`, `Unsupported { what }`, `UnexpectedState { what }`) are gone for every non-wire failure: a caller can now branch on `ChunkSizeOutOfRange`, `InvalidLimitType`, `UnsupportedUserControlEvent`, `UnsupportedAmf0Marker`, `Amf0DepthExceeded`, `Amf0StringTooLong`, `Amf0DateTimeZone`, `Amf0Utf8`, `CommandNameNotString`, `CommandTransactionIdNotNumber`, `HandshakeVersion`, `TooManyChunkStreams`, `InputBudgetExceeded` and `ChunkStreamState`, each carrying the value/stream id that failed. `Malformed` stays only for "these bytes are not that structure" (`what` names the structure), and `clippy`-friendly code that matched on a `what` literal must match the variant instead. `RtmpError` derives `PartialEq` but no longer `Eq`, because two variants carry an `Amf0Value` (which holds `f64`) (#2767).
- BREAKING: `target::RtmpUrlError::Parse` wraps `url::ParseError` instead of a `String` (`#[from]`), and `RtmpUrlError::Scheme` wraps the new `target::Scheme` (`Rtmp`/`Rtmps`/`Other(String)`, `Display`) instead of a `String`, so an unsupported scheme is recognisable without matching message text (#2767).
- BREAKING: `RtmpClientConfig::play_buffer` is a `core::time::Duration` (was `play_buffer_ms: u32`) and the default constant is `DEFAULT_PLAY_BUFFER` (was `DEFAULT_PLAY_BUFFER_MS`); the value still goes on the wire as whole milliseconds in SetBufferLength (§6.7) (#2693).
- BREAKING: `flv::FlvHeader` no longer stores a `data_offset` field; the `DataOffset` it writes is derived from `FLV_HEADER_LEN + extra.len()` (§E.2) and readable with `FlvHeader::data_offset()`. A header whose field disagreed with its `extra` bytes used to serialize to an offset the parser rejects, so the serializer could emit un-parseable output (#2760). Migration: read `header.data_offset()`; to write a larger offset, set `header.extra` to that many bytes.
- The `panic_idioms` workspace guard now covers this crate. The handshake builders and acknowledgement/user-control emitters no longer `.unwrap()`/`.expect(..)` a fixed-size serialize (`let _ =` on the sized buffer), the reassembler reports a committed-but-missing chunk-stream entry and the fmt/variant mismatch as `RtmpError::ChunkStreamState` instead of `unreachable!()`/`.expect(..)`, and the acknowledgement now propagates the writer's error instead of `.expect(..)` (#2773).

#### Added
- `io::RtmpClientConfig { target, timeouts }` (`new(target)`, `with_timeouts`) and `io::RtmpServerConfig { session, timeouts }` (`Default`, `with_session`, `with_timeouts`): the same config shape as the RTSP and SRT adapters, so a host maps its timeout config once per role (#2660).

#### Removed
- BREAKING: `AsyncRtmpClient::connect(target, timeouts)` and `AsyncRtmpClient::from_stream(stream, target, timeouts)`; both take an `io::RtmpClientConfig`. Migration: `connect(&target, t)` -> `connect(RtmpClientConfig::new(target).with_timeouts(t))`, `from_stream(stream, &target, t)` -> `from_stream(stream, RtmpClientConfig::new(target).with_timeouts(t))`.
- BREAKING: `AsyncRtmpServer::bind(addr, ServerConfig).with_timeouts(t)`; `bind` takes an `io::RtmpServerConfig`. Migration: `bind(addr, RtmpServerConfig::default().with_session(cfg).with_timeouts(t))`. `with_timeouts` on the bound server is gone.
- BREAKING: `RtmpConnection::from_stream(stream, session, timeouts)` (the generic form) and `RtmpConnection::from_stream_erased`: one `RtmpConnection::from_stream(stream, RtmpServerConfig)` erases the stream type, as the server and multimux already used. Migration: `from_stream_erased(s, ServerSession::new(cfg), t)` -> `from_stream(s, RtmpServerConfig::default().with_session(cfg).with_timeouts(t))`. A connection is now always `RtmpConnection` (the erased form), not `RtmpConnection<S>` for a named `S`.

#### Changed
- BREAKING: the message type id is a typed `message::MessageTypeId` (`SetChunkSize`, `Abort`, `Acknowledgement`, `UserControl`, `WindowAckSize`, `SetPeerBandwidth`, `Audio`, `Video`, `DataAmf3`, `CommandAmf3`, `DataAmf0`, `CommandAmf0`, `Aggregate`, `Other(u8)`, `#[non_exhaustive]`, with `from_u8`/`to_u8`, `name()` and `Display`) wherever a raw `u8` stood for one: `Message::message_type_id`, `MessageHeader::Type0`/`Type1`'s field, `ProtocolControl::message_type_id()`/`from_payload()`, `ServerEvent::Unsupported::message_type_id`. The `message::msg_type` constants module is private. Migration: `message_type_id: msg_type::VIDEO` -> `message_type_id: MessageTypeId::Video`, `== msg_type::AUDIO` -> `== MessageTypeId::Audio`, `from_payload(msg_type::SET_CHUNK_SIZE, ..)` -> `from_payload(MessageTypeId::SetChunkSize, ..)`, and a byte from the wire -> `MessageTypeId::from_u8(byte)` (#2666).
- BREAKING: `client::ClientConfig` is `client::RtmpClientConfig` and `server::ServerConfig` is `server::RtmpServerConfig`, matching `RtspClientConfig`/`RtspServerConfig`/`HlsClientConfig`. Two modules can now hold a `RtmpClientConfig` (the sans-IO session's and the tokio adapter's) without a name clash; they configure different layers.
- BREAKING: `ProtocolControl::SetChunkSize` now wraps a validated `ChunkSize` newtype (1..=0x7FFF_FFFF); `to_message` is total and `try_to_message` is removed (#2659).
- BREAKING: `ChunkAssembler`/`ChunkWriter::set_chunk_size` and `ChunkAssembler::with_chunk_size` take a `ChunkSize` instead of a `u32`. A peer's `SetChunkSize` above the engine ceiling (`chunk::MAX_CHUNK_SIZE`, 16 MiB) was accepted with the size silently clamped, so every following chunk boundary was parsed at a size the peer never announced; `ChunkSize::try_new` now rejects it, and the session fails with `RtmpError::Malformed` instead of corrupting the stream (#2741). Migration: `set_chunk_size(n)` -> `set_chunk_size(ChunkSize::new(n)?)`.
- `ChunkAssembler::feed`, `next_message`, `compact`, `pending_len` and `swap_pending` are the incremental interface for a caller that applies a Set Chunk Size between messages, and `chunk::DEFAULT_CHUNK_SIZE` is a `ChunkSize` (the wire value stays as `chunk::DEFAULT_CHUNK_SIZE_VALUE`). `swap_pending` returns the bytes fed but never parsed and installs what the caller has left, so a chunk-size change inside one input buffer re-feeds exactly the unparsed tail at the new size instead of re-parsing consumed bytes.
