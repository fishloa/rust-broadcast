# transmux 0.25.0

_Released 2026-10-05._

Breaking (0.x minor) and security release of the container-muxing hub, and the largest transmux release to date. It is the sum of three things that were never published separately: the **twelve-advisory security patch prepared as 0.24.2** (the last tag on crates.io is 0.24.1, so there is no 0.24.2), the **audit rounds r04 and r05** (#1079, #1080, #1081, #1129, #1140, #1141, #1148), which fixed dozens of demux/mux paths that returned `Ok` with wrong, truncated or reordered data, and the **de-hand-roll** of XML, URL, SDP, date/duration and hex/base64 handling onto `quick-xml`, `url`, `sdp-types`, `jiff`, `hex` and `base64`. **Everyone who parses untrusted input should upgrade.** **Who must act:** anyone building with `--no-default-features` that uses DASH, Smooth or PlayReady (XML now needs `std`); anyone who calls `ESDescriptor::parse`, `Mpd::resolve_segment_url`, `ExtXKey::to_tag`, the RTMP chunk writer, `playready_pro`/`playready_pssh`, or constructs any of the structs listed under "Struct changes"; anyone who stored output made by this crate's H.264 SAMPLE-AES, `cbcs` default-IV, KLV checksum or CLI HLS/DASH writers (those bytes change, see "Output that changes"); and anyone matching on `transmux::Error` exhaustively with `Eq`.

Read together with: [broadcast-hls-0.3.0.md](broadcast-hls-0.3.0.md), [mpeg-ts-0.5.0.md](mpeg-ts-0.5.0.md), [mpeg-pes-0.5.0.md](mpeg-pes-0.5.0.md), [mpeg-ps-0.5.0.md](mpeg-ps-0.5.0.md), [rtcp-packet-0.4.0.md](rtcp-packet-0.4.0.md), [container-probe-0.1.1.md](container-probe-0.1.1.md) (the CLI uses it), [scte35-splice-3.0.0.md](scte35-splice-3.0.0.md) (dev-dependency epoch). Downstream in this wave: [multimux-0.11.0.md](multimux-0.11.0.md), [hls-runtime-0.7.0.md](hls-runtime-0.7.0.md), [media-plane-0.5.0.md](media-plane-0.5.0.md), [media-doctor-0.9.0.md](media-doctor-0.9.0.md). An earlier draft changelog described a hand-written RFC 3986 `uri` module; **it never shipped**, URL resolution is `base_url` over the `url` crate (below).

## Security (the unpublished 0.24.2 fixes, now shipping here)

Twelve advisories, each with a regression test that fails on 0.24.1; `tests/hostile_input_bounds.rs` runs the allocation cases under a per-thread 64 MiB allocator cap.

| Area | Before |
|---|---|
| KLV | a long-form BER length overflowed offset arithmetic and panicked |
| `esds` | an ES_Descriptor size larger than the box, or a size-0 box, panicked the fMP4 demuxer |
| `sinf` | an oversized `frma` or header-only `schm` panicked |
| `pssh` v1 | a body with no `DataSize` panicked |
| progressive demux | one `stts`/`ctts` run could allocate about 17 GB from a roughly 100-byte file |
| `CencDecryptor` progressive path | `stsz`/`stco` counts allocated before their length checks |
| `sgpd` | zero-length entries could be pushed up to 2^32 times |
| H.264/H.265 SPS | `read_ue` returned 0 at end of data, so a roughly 20-byte SPS could loop effectively for ever |
| RTMP chunk reader | a fmt 1/2 header after an incomplete message carried stale bytes into the new one and underflowed its length |
| `CencEncryptor::encrypt` | a sample rejected mid-call left earlier samples encrypted with the IV counter unchanged, so a retry reused IVs |
| `KeyMap`, `CencEncryptor`, `CencDecryptor`, `cli::Args`, `cli::CliError::BadKey` | derived `Debug` printed raw content-key bytes or the raw `<KID>:<key>` argument |
| `progressive_demux` `stsc` | a chunk-run `first_chunk` was iterated to as written (up to `u32::MAX`) instead of clamped to the real chunk count |

Behaviour that follows: `BitReader::read_ue` errors at end of data and past 32 leading zeros, and SPS parsing rejects out-of-range fields (`chroma_format_idc > 3`, `bit_depth_*_minus8` above 6 for H.264 or 8 for H.265, `num_ref_frames_in_pic_order_cnt_cycle > 255`, `num_short_term_ref_pic_sets > 64`); an `esds` box with `size == 0` extends to the end of its container (ISO/IEC 14496-12 §4.2); `CencEncryptor::encrypt` plans every sample before encrypting any, so a rejected call leaves the media byte-identical and the IV counter unchanged; `KeyMap`, `CencEncryptor` and `CencDecryptor` hand-write `Debug` to redact key bytes (KIDs still print), and `cli::Args`/`BadKey` carry only the KID half or the argument length.

## Breaking changes

### XML needs `std`; `quick-xml` replaces the hand-rolled parser and writer

`dash`, `dash_parse`, `smooth`, `smooth_parse`, `ll_dash::LlDashPackager` and `drm::{playready_wrmheader, playready_pro, playready_pssh}` are gated behind `std` (and so are their crate-root re-exports, including `rfc6381_codec_string`'s home module `dash`). A `--no-default-features` build keeps everything else (`LlSegmenter`/`Chunk`, the Widevine/FairPlay `pssh` builders, and so on). The private tokenizer (`xml_parse`) and `xml_writer` are gone.

```toml
# before: DASH/Smooth available no_std + alloc
transmux = { version = "0.24", default-features = false }
# after
transmux = { version = "0.25", default-features = false, features = ["std"] }
```

Rendered MPD, Smooth manifest, LL-DASH MPD and WRMHEADER output is byte-identical for every committed fixture, with these exceptions that follow XML 1.0:

- a value containing `\t`, `\n` or `\r` in an attribute is now written as `&#9;`, `&#10;`, `&#13;` (so `profiles = "a\nb"` renders `profiles="a&#10;b"`) so it survives a re-parse;
- parsers are stricter: a literal newline, tab or CR in an attribute value is normalised to a space (XML 1.0 §3.3.3: `<Period id="a⏎b"/>` parses `id` as `"a b"`; write `&#10;` to keep it), a duplicate attribute is `MalformedAttribute` (the first value used to win silently), an undefined entity, a raw `&` in an attribute or a mismatched end tag anywhere is an error, and a character outside the XML 1.0 `Char` production (`&#x1;`) is a structured error. `<BaseURL>a<x/>b</BaseURL>` (markup inside a text-only element) now yields no base URL instead of `MismatchedEndTag`.
- `DashParseError` and `SmoothParseError` gain `Xml { pos, message }`; `DashParseError::MismatchedEndTag::expected` is now a `String`. `LlDashPackager` rewrites the base MPD with `quick-xml` events instead of line-based text surgery.

### `ESDescriptor::parse` now reads the framed bytes `Serialize` writes (#1148)

`Parse for ESDescriptor` used to read the bare descriptor body; it now reads `ES_DescrTag` (0x03), the expandable-size varint, then the body, so `parse(serialize(x)) == x`. The old contract misread the tag and size bytes as `ES_ID`/flags/`URLlength`, truncating the descriptor chain silently, and failed with a spurious `BufferTooShort` once a `URLstring` over about 100 bytes (up to the 255 its 8-bit `URLlength` allows) pushed the varint wide. **The input contract flipped, and the compiler will not tell you.** A caller that stripped the tag and size prefix itself must pass the framed bytes instead, or parse through `EsdsBox::parse_box` / `EsdsBox::parse_body`, which strip the box and FullBox framing and pass exactly what this impl expects. The only in-workspace caller was `EsdsBox::parse_body`.

```rust
// 0.24: body only (tag + size already stripped by hand)
let es = ESDescriptor::parse(&descriptor_bytes[prefix_len..])?;
// 0.25: the whole descriptor, tag and varint included
let es = ESDescriptor::parse(descriptor_bytes)?;
// or, from an esds box payload
let esds = transmux::mp4esds::EsdsBox::parse_body(body)?;
```

Feeding bare-body bytes now returns `InvalidValue { field: "descriptor_tag", .. }`, or a silently misread result if the first body byte happens to be `0x03`. Also: a non-UTF-8 `URLstring` is `InvalidValue { field: "URLstring" }` instead of a lossy decode (which broke byte-identical round trips and let 765 replacement bytes from a 255-byte input overflow `URLlength`).

### `transmux::Error`: no longer `Eq`, new variants, fallible builders

`Error` now derives only `PartialEq` (it embeds `broadcast_hls::Error`, which carries an `f64`); a bound or derive that needs `Eq` on `transmux::Error` fails to compile. New variants (`Error` is `#[non_exhaustive]`, so additive): `FieldOverflow` (wrapping `broadcast_common::len::FieldOverflow`), `TooManyElementaryStreams { family, max }`, `HlsAttrValue(broadcast_hls::Error)`.

Serializers now return an error instead of silently truncating a length, count or offset that does not fit its wire field (#1129). Builders that were infallible and now return `Result`: `rtmp::write_chunks`, `rtmp::MessageHeader::write_into`, `OutTag::write_into`, the `HevcNalUnit`/`HevcNalArray` serializers, `drm::playready_pro`, `drm::playready_pssh`, and `sample_aes::ExtXKey::to_tag` (#1140). `ExtXKey`'s inherent `Display` impl is removed: `uri`, `keyformat` and `keyformatversions` are caller-supplied and a `"`, CR or LF in any used to terminate the attribute list and inject playlist tags; `to_tag` now builds through `broadcast_hls::AttrValue` and returns `Error::HlsAttrValue` for an invalid value.

```rust
// 0.24
let line: String = key.to_tag();          // or format!("{key}")
let chunks = write_chunks(&msgs, 128);
// 0.25
let line: String = key.to_tag()?;
let chunks = write_chunks(&msgs, 128)?;
```

The PMT `section_length` is bounded to 1021 bytes (§2.4.4.4) and returns `Error::BufferCapExceeded` instead of masking the 12-bit field. Field-range checks were added to `avcC`/`hvcC` arrays, `mhaC`, `vpcC`, `dfLa`, `esds` `URLstring`, RTMP 24-bit lengths, AMF0 counts, CENC `senc`/`saio`/`saiz`/`pssh`/`tenc`, `subs`/`sgpd`/`sbgp`, `sidx` v0 and per-reference fields, `elst` v0, and `trun`/`stsz`/`dref`/`stsc`/`stco`/`co64`/`stss`/`stsd` counts. A previously accepted over-range value is now an error, never a wrapped field.

### URL resolution and the DASH parse model

- `Mpd::resolve_segment_url` takes the MPD's own URL as its first argument and returns `Option<String>`: `resolve_segment_url(mpd_url: Option<&url::Url>, period, adaptation_set, representation, reference: &str)`. `None` means the reference or a `BaseURL` carries a control character or whitespace, or does not parse (a CR/LF in a manifest URL otherwise lets it smuggle a request line into anything that later writes an HTTP request from it). `BaseURL` entries are trimmed before that check. New: `Mpd::base_url_chain`, and the `base_url` module (`std` only): `base_url::{resolve, resolve_chain, first_forbidden_char}` plus crate-root `resolve_url_reference`/`resolve_base_url_chain`.
- Resolution is the `url` crate's WHATWG join, so it differs from a strict RFC 3986 resolver as follows. With no base, a relative input stays relative and cannot climb out: `../../../etc/passwd` resolves to `etc/passwd`, `%2e%2e/x` behaves like `../x`, and only a `/x` the MPD wrote itself comes back absolute. An input naming the internal `transmux-relative:` scheme is `None`. Hosts are lower-cased and default ports dropped (`http://H:80/x` becomes `http://h/x`); non-ASCII is percent-encoded (`é.m4s` becomes `%C3%A9.m4s`); the `//g` network-path row serialises as `http://g/`, and `http:g` against an `http` base resolves relatively (see `tests/base_url.rs`).
- `dash_parse::Mpd`, `Period`, `AdaptationSet` and `Representation` each gain a `base_url: Option<String>` field (`BaseURL`, ISO/IEC 23009-1 §5.3.9.2): a struct literal must add it. `Mpd::parse` now merges `SegmentTemplate` attribute by attribute down the Period, AdaptationSet, Representation chain (§5.3.9.1) instead of replacing whole elements, so the `segment_template` you read is the effective one; code that relied on a child's template replacing its parent's now sees inherited values. `@duration` and `SegmentTimeline` are kept exclusive in both directions.
- **`dash_parse::parse_iso8601_duration`** now checks the XML Schema 1.1 `xs:duration` lexical space and converts with `jiff`. Now rejected, were accepted: a unit with no digits (`PTS`, `PTHS`, `PTMS` used to read as zero), `PT.5S`, a `+` sign (`PT+1S`, `P+1D`), and magnitudes beyond jiff's limits (`PT999999999H`, `P999999999999D` used to saturate; now `InvalidDuration`, never a panic). Unchanged rejections: lower-case designators, weeks, fractions on hours/minutes, the comma separator, calendar units (`P1Y`, `P1M`), negative durations, trailing garbage, mis-ordered units. Seconds fractions longer than nine digits are accepted and truncated to nanoseconds as before.
- **The DASH writer prints `xs:duration` in the shortest ISO 8601 form** (`PT2.0S` becomes `PT2S`, `PT0.0S` `PT0S`, `PT3.0S` `PT3S`, `PT90.0S` `PT1M30S`). Equal durations, different bytes. multimux uses the same rule, see [multimux-0.11.0.md](multimux-0.11.0.md).

### RTP and SDP

- RTP SDP generation is `std`-only: `RtpOutput::sdp` exists only with the `std` feature, and is written by `sdp-types` 0.2 (`Session::write`; `build_sdp_with_connection(IpAddr, Vec<sdp_types::Media>)` is the entry for a caller that transmits somewhere other than the loopback `o=` address, whose default is `LOCAL_CONNECTION_ADDRESS`). The SDP now has a session-level `c=` line (RFC 4566 §5.7; a strict parser had no connection data before). `sdp-types` and `url` types appear in the public API.
- `RtpPacketiser` gives every stream its own dynamic payload type, walking 96 to 127 from the configured bases (video 96, audio 97) and never reusing one, and errors with `Error::InvalidInput` past the 32 available; a third video track used to reuse `video_pt + 2`, colliding with the second track and with `DEFAULT_KLV_PT`. It stamps each access unit's RTP timestamp with the sample's `pts` rather than `dts` (RFC 6184 §5.1; on `fixtures/ts/h264/high.ts` 12 of 15 samples differ) and fragments an AAC access unit larger than the payload budget (RFC 3640 §3.2.3.1) instead of refusing it.
- `rtp::RtpInputStream` is `#[non_exhaustive]` and gains `clock_rate` and `config`; build it with `RtpInputStream::new(kind, packets)` plus `with_clock_rate` / `with_config`, which validate that kind, clock and config agree. An AAC stream with no `config` is `Error::InvalidInput` (RTP carries no codec config; supply the SDP `config=`, RFC 3640 §4.1) and its clock is the config's sample rate. Every depacketised track is now described with its own payload format, clock and config; before, an AAC stream came back as a 90 kHz AVC track and `Media`'s movie timescale was 0.
- `rtp::base64_decode` is stricter: input whose length is 1 mod 4 (`QUJDR`) is an error (the stray character used to be dropped), and `=` anywhere but as the final one or two characters (`Zm9v=YmFy`, `Zg===`) is an error. Padding stays optional and non-zero trailing bits stay tolerated. CLI `--key` hex now rejects a `+`/`-` sign and non-ASCII input (the latter used to panic).
- `RtpDepacketiser` no longer fails the whole input on ordinary loss (a continuation FU-A with no start fragment), uses sequence numbers to detect loss inside a reassembly run, reassembles RFC 3640 fragmented AAC AUs, and reconstructs `dts` from the whole stream, reporting a timeline the wire did not state through the new `poll_timing_warning`, `dropped_timing_warnings`, `MAX_TIMING_WARNINGS` and `RtpTimingWarning`. `rtp_stream::RtpLossEvent` gains `NonMonotonicTimestamp`.

### Struct changes (struct literals and exhaustive patterns break)

- The eight public audio sample-entry structs (`Mp4aSampleEntry`, `Ac3SampleEntry`, `Ec3SampleEntry`, `OpusSampleEntry`, `FlacSampleEntry`, `Ac4SampleEntry`, `MhaSampleEntry`, `DtsSampleEntry`) gain `entry_version: u16`, `reserved_1: [u8; 6]` and `compression_id_and_packet_size: [u8; 4]`, so a parsed sound description re-serializes byte for byte (QuickTime `compression_ID`, `packet_size` survive). `Mp4aSampleEntry` also gains `codec_type: [u8; 4]` (`mp4a` or `enca`; serialize used to hard-code `mp4a`, relabelling a protected track as clear, #1017).
- Box containers record the wire order of their children: `init_segment::ChildOrder` and `pub order: ChildOrder` on `MovieBox`, `TrackBox`, `MediaBox`, `MediaInformationBox`, `DataInformationBox`, `EditBox`, `MovieExtendsBox`, `SampleTableBox`; `movie_fragment::{TrafChild, MoofChild, OpaqueChild}` and `pub order: Vec<..>` on `TrackFragmentBox`/`MovieFragmentBox`; `OpaqueBox`/`OpaqueChild` gain `to_end` and `largesize` (the `size == 0` and `size == 1` wire forms are preserved). Each of those containers also gets a `new(...)` constructor; switch literals to it. `ChildOrder::append_opaque(four_cc)` must accompany an `opaque` push on a parsed container. `Vp9SampleEntry`/`Av1SampleEntry` carry `children: Vec<SampleEntryChild>` (config box position recorded; `pasp`, `btrt`, `colr` no longer dropped, 46 bytes of every real ffmpeg AV1/VP9 file). The `MkvMux` cluster builder returns `Result<Vec<u8>>`.
- `TrunSample::sample_composition_time_offset` is `Option<i64>` and `frag_offsets::FragmentSampleRange::composition_offset` is `i64` (a legal `trun` v0 offset is unsigned and can exceed `i32::MAX`). `SampleGroupDescriptionBox` gains `default_sample_description_index: Option<u32>` (the `sgpd` v2 field), and `sgpd` v2 now round-trips.
- `SampleAuxInfoSizesBox` and `SampleSizeBox` gain `sample_count: u32` (the uniform-size form used to collapse to 0 on every parse and serialize, #1013, #1018). `NclxColourInfo` gains `reserved: u8`. `Ec3SpecificBox` gains `reserved_tail: Vec<u8>` (a Dolby Atmos `dec3` now survives a round trip), and its serializer returns `Error::InvalidValue` when `substreams.len() != num_ind_sub + 1`. `Ec3SyncframeInfo` gains `chanmap: Option<u16>` and `bsmod: u8`; `Ec3SyncframeInfo::into_dec3` and the new `Ec3SpecificBox::from_syncframes` return `Result` and take the syncframes of **one** access unit (`Ec3SyncframeInfo::from_es_first_au`), so a 7.1 DD+ stream is no longer signalled as 5.1 with an inflated substream count. The `chanmap` to `chan_loc` derivation was mirrored (MSB-first, ETSI TS 102 366 §E.1.3.1.8) and is corrected.
- `mp4esds`: `DecoderSpecificInfo`, `SLConfigDescriptor`, `DecoderConfigDescriptor` and `ESDescriptor` gain `size_width: usize`; `DecoderConfigDescriptor` and `ESDescriptor` gain `unknown_descriptors: Vec<UnknownDescriptor>` (new type, with a `position`); constructors `DecoderSpecificInfo::new`, `SLConfigDescriptor::new`/`predefined_two`, `DecoderConfigDescriptor::new`, `ESDescriptor::new`. An `esds` with minimal-width size varints no longer grows on every round trip, unmodelled sub-descriptors survive in place, and a `streamDependenceFlag`/`URL_Flag`/`OCRstreamFlag` that disagrees with its field is `Error::InvalidValue` (it used to misframe the descriptor and return `Ok`).
- VVC: `vvc_config::VvcPtlRecord::general_constraint_info` is `Vec<u8>` (was `u64`), `VvcDecoderConfigurationRecord::dimensions` returns `Option<(u32, u32)>` (was `u16`; `ue(v)` widths wrapped, 65 536 to 0), and `sps::rfc6381_vvc1` takes `&[u8]`: pass `&ptl.general_constraint_info`. SPS with `gci_present_flag == 1` used to be rejected outright and now parse.
- `au::AccessUnitSplitter::push` returns `Result<()>`: a stream whose open NAL or access unit grows past 64 MiB without completing is rejected with `Error::InvalidValue`.
- `klv::crc16_ccitt` is **removed**; use `klv::checksum_bcc16(&[u8]) -> u16`. MISB ST 0601 tag 1 is a running 16-bit sum, not a CRC, so the value deliberately differs: `UasLocalSet::serialize_with_checksum` now writes the correct value, and `verify_checksum` now accepts real ST 0601 streams.
- New public errors and variants: `cli::CliError::UnsupportedContainer(&'static str)` (the CLI's container detection runs `container-probe` and separates "recognised but not demuxable" from "not recognised"), `rtmp::RtmpError::Amf0TooDeep { depth }` (AMF0 nesting is capped at `MAX_AMF0_DEPTH` = 32).

### Demuxer behaviour a consumer can observe

- `StreamingTsDemux` emits `DemuxEvent::TrackUpdated` when a track's in-band codec config changes mid-stream (new SPS/PPS, or a changed AAC `audioObjectType`/`samplingFrequencyIndex`/`channelConfiguration`). A consumer that rebuilds its init segment only on `TrackAdded` will now miss such changes: treat `TrackUpdated` as "reload the init segment". An unchanged repeat emits nothing. `StreamingFlvDemux` now also emits it when a re-sent sequence header actually differs (OBS/ffmpeg change resolution or channel count mid-publish); `TrackUpdated`'s documented "never changes config" no longer holds.
- It **drops, instead of delivering, access units damaged by a continuity-counter gap** (a gap on one of the unit's own packets, or a bounded PES shorter than its header declared), and discards legal §2.4.3.3 duplicate packets before reassembly (they used to add 184 payload bytes to the unit). A stream with real CC gaps yields fewer samples than before. A `discontinuity_indicator` alone is not damage. Documented tradeoff: an unbounded PES (`PES_packet_length == 0`, every video PES) that lost its tail at a counter jump is indistinguishable from one that ended cleanly and is delivered.
- A TS track's decode timeline is rebased at a signalled discontinuity so `dts` stays monotonic across a splice, scoped to the signalling program's `PCR_PID` (H.222.0 §2.4.3.5); the lift is non-negative and one nominal frame period past the last stamp, using the median of the last five plausible steps capped at one second. A PES with no PTS/DTS is interpolated instead of reusing the previous unit's stamps (`PTS_DTS_flags == '00'` is legal).
- TS AAC `CodecConfig::Aac::channel_count` maps `channel_configuration` through ISO/IEC 14496-3 Table 1.19: configuration 7 reports **8** (it reported 7), and configuration 0 (in-band `program_config_element`, not decoded) reports **0**, meaning "not derivable". `aac_asc::ChannelConfiguration::channel_count() -> Option<u16>` is the shared accessor, now used by both FLV demuxers and the RTP SDP path.
- `Fmp4Demux` and `ProgressiveDemux` normalise AVC/HEVC NAL length prefixes to the crate's 4-byte form and report `lengthSizeMinusOne = 3` (the WebM and FLV demuxers do the same via `annexb::normalise_nal_length_size` and `iter_length_prefixed_nals_with`); before, a 1- or 2-byte-prefixed source produced garbage lengths and a corrupt remux. A length size other than 1, 2 or 4 is an error. `Fmp4Demux` tolerates exactly one thing, a truncated tail (a "does not fit the bytes present" error on the final box, which is how a live capture or interrupted recording ends); a mid-file `BoxSizeUnderflow` now propagates instead of silently truncating the demux. `FlvDemux::unpackage` stops at a truncated final tag and returns every complete tag before it (`FlvDemux::last_walk_was_truncated()` reports it).
- `CencDecryptor::demux` skips a protected track whose original format is not AVC and records it in `Media::skipped`, instead of failing the whole file (a typical CENC asset is `encv` plus `enca`, and protected HEVC could not be demuxed at all). `Decrypt::decrypt` is atomic across the whole `Media`: a missing key on track 2, a sample-count mismatch or a malformed subsample map used to return `Err` after earlier tracks were already decrypted in place.
- `PsDemux` emits one track per `private_stream_1` substream, splits AC-3 by each syncframe's declared length, splits H.264 access units without requiring an AUD, and probes for a MPEG-2 `sequence_header()` before assuming H.264 for `stream_id` 0xE0 to 0xEF. `WebmDemux` unlaces laced blocks (it rejected the file) and no longer loses every Cluster after the first when Clusters are unknown-size (browser `MediaRecorder`, `ffmpeg -f webm -live 1`, OBS). A laced block whose declared lace sizes do not describe its payload is an error.
- `vpcC` boxes whose FullBox version is not 1 are rejected on parse and serialize (the VP binding states v0 "is deprecated" and publishes no v0 syntax; the parser read the v1 layout regardless and re-serialized v0 as v1, so early ffmpeg/libwebm output parsed to wrong bit depth and colour values). Media that used to demux (incorrectly) no longer parses.
- Smooth: `smooth_parse::track_spec_from_quality_level` dispatches on the `QualityLevel`'s `FourCC` (`H264`/`AVC1`, `AACL`/`AACH`, case-insensitive) and returns `Error::UnsupportedCodec` for anything else (a Dolby `EC-3`/`AC-3` level used to be parsed as an AudioSpecificConfig into a garbage AAC track); an empty `CodecPrivateData` on an AAC level synthesises the config from `SamplingRate`/`Channels`.

## Output that changes (regenerate or re-encrypt stored material)

- **H.264 SAMPLE-AES** (`sample_aes::h264_encrypt_nal`/`h264_decrypt_nal`) now chains CBC state across the encrypted blocks of one NAL (IV reset only at each NAL start). It restarted the context at every block, so every block after the first in each slice NAL was wrong; ffmpeg's `hls_sample_aes.c` decodes the chained form 10/10 frames and the old one 0/10. **Any SAMPLE-AES H.264 produced by an earlier version must be re-encrypted.** A NAL's final block is left clear when exactly 16 bytes of the eligible region remain (`bytes_remaining() > 16`, HLS SAMPLE-AES §3.2). New `eac3_encrypt_frame` / `eac3_decrypt_frame` and `ac3::split_eac3_syncframe_ranges` handle multi-syncframe E-AC-3 (IV reset at every syncframe, confirmed against ffmpeg 9/9 and Bento4; a carried IV across an independent plus dependent pair has no independent oracle and is labelled unverified).
- **`IvGen::Counter` under `cbcs` emits 16-byte per-sample IVs** (it emitted 8, a shape Bento4's `mp4decrypt` silently no-ops). Width is now scheme-dependent (8 under `cenc`, 16 under `cbcs`); feed decryptors the matching `tenc.default_per_sample_iv_size`.
- **`CencEncryptor::encrypt` rejects overlapping AES-CTR counter-block ranges under `cenc`** (`Error::InvalidInput`). Under `cenc` the per-sample IV is the 128-bit counter and advances once per 16-byte block, so an `IvGen::Explicit` list `base + i` passed the equality check while sample `i+1`'s first keystream block equalled sample `i`'s second, a two-time pad. Space explicit IVs by at least the preceding sample's protected block count. `cbcs` is exempt. `cenc_ext_x_key` in broadcast-hls now emits `METHOD=SAMPLE-AES-CTR` for `cenc`.
- **The `transmux` CLI's segmented outputs changed shape** (#1080): `-f hls` writes a separate `init.mp4` (the `#EXT-X-MAP` target) and media-only `segN.m4s`, with each `#EXTINF` the real measured duration; `-f dash` writes per-Representation segments with boundaries shared across tracks and no `moov` in a media segment (ISO/IEC 23009-1 §6.3.4.2), and emits `AdaptationSet@id` (`t0`, `t1`, ...); `-f dash --ll` emits a `static` MPD with `mediaPresentationDuration` and **no `MPD/UTCTiming`** unless `--utc-timing-url <URL>` is given (the old build baked a third-party time server into every LL MPD; the flag requires `--ll`). `--segment-duration` is honoured by every segmented format.
- **DASH groups Representations** into one `AdaptationSet` per (kind, `@lang`, codec family), not one per kind, so an ABR client cannot switch between `eng` and `fra` or between AAC and AC-3 (ISO/IEC 23009-1 §5.3.3).
- **LL-HLS parts and LL-DASH chunks carry every track** and stay within the part target. A regular part drained only the anchor video track, leaving all audio for the segment's last part, so a live-edge client had video with no audio until the segment closed. A part now stops before the sample that would exceed `PART-TARGET` (RFC 8216bis §4.4.4.9).
- **`TsMux`** prepends an access unit delimiter to every AVC/HEVC access unit lacking one (H.222.0 §2.14.1, §2.17.1; an IR sample from fMP4, MKV, FLV or RTMP never has one), returns `Error::BufferCapExceeded` for a non-video PES whose length exceeds 65535 (it clamped `PES_packet_length` over a longer payload), no longer anchors the PCR to a sparse `Data` PID (audio is preferred and PCR-only adaptation packets hold the interval within 40 ms), and threads per-PID continuity across segments through `transmux::TsContinuity` (used by `TsHlsPackager` and `StreamingTsHlsSegmenter`, so concatenated segments no longer jump the counter at each boundary). `TsMux` and `ProgressiveMux` take timing from the IR's own `dts`/`pts` on one origin shared by all tracks, so inter-track offsets survive.
- **`ProgressiveMux`** interleaves the `mdat` in about 0.5 s chunks merged in start-time order (it concatenated each track whole, so `faststart` bought nothing for a forward-only reader) and promotes `mvhd`/`tkhd`/`mdhd` to version 1 when a duration does not fit 32 bits (a 10 MHz Smooth-sourced timeline wrapped after 7.2 minutes, 90 kHz after 13.2 hours). The `mdat` header length is derived from the payload, so chunk offsets are no longer 8 bytes early once a 64-bit `largesize` is needed (#1019). `SmoothPackager` writes `trun` durations and `c@t`/`tfxd` in the 10 MHz manifest `TimeScale` (#1022); `HlsPackager` emits one `#EXTINF` covering the presentation span (#1023). `MkvMux` starts a new Cluster when a block's relative timestamp would leave the signed 16-bit range, writes monotonic `CueTime`s, and errors instead of clamping.
- **Audio at 88.2, 96, 176.4 and 192 kHz** keeps its real rate (the 16.16 field tops out at 65535 Hz) through a `srat` box: new `init_segment::SamplingRateBox`, `AudioSampleEntryV1` and `sampling_rate_override`.
- Every serializer writes its reserved and `pre_defined` bytes as zeros (`VisualSampleEntry`, audio entries, `stpp`/`wvtt`, `mvhd`, `tkhd`, `mdhd`, `hdlr`, `smhd`) instead of leaving a reused buffer's contents in them, which a conformance validator rejects. `sidx` now reads and writes its 16-bit `reserved` field before `reference_count` (every conformant `sidx` used to parse with `reference_count == 0`), and `mvhd`/`tkhd` version-1 sizes and offsets are corrected (#1015: `mvhd` v1 is 120 bytes, not 124).

## Added

`CencDecryptor::from_fmp4_bytes` (shares the file buffer; samples are slices of it), `AudioSpecificConfig::effective_sampling_frequency`, `impl Serialize for SampleEntryVariant` (replacing four 17-arm matches), `ll_dash::{UTCTIMING_HTTP_HEAD_2014, UTCTIMING_HTTP_XSDATE_2014, UTCTIMING_HTTP_ISO_2014, UTCTIMING_NTP_2014, UTCTIMING_HTTP_NTP_2014, UTCTIMING_DIRECT_2014}` with `LlDashPackager::with_utc_timing(scheme, value)` and a `pub utc_timing` field, `webm_demux::ns_to_ir_ticks`, `ac3::Ec3SpecificBox::from_es_all`, `annexb::NAL_LENGTH_SIZE_MINUS_ONE`, `frag_offsets::{mdat_ranges, MdatRange, sample_ranges_in, sample_ranges}` (one shared fragment-addressing resolver for `Fmp4Demux` and `CencDecryptor`, §8.8.7/§8.8.8: honours `tfhd.base_data_offset`, a `trun` without `data_offset`, and bounds every range to an `mdat` payload and the file length), `rfc6381_codec_string(&CodecConfig)` (the string `DashPackager` writes into `Representation@codecs`, exposed so an HLS origin can fill `CODECS`, #1089), `smooth::SmoothPackager::package_track_fragment` (one fragment for one track at an explicit smooth-timeline start, for multimux's per-track Smooth output, #1083), `ts_hls::StreamingTsHlsSegmenter::with_start_sequence`, `ac3::split_ac3_syncframes_resyncing` and `split_ac3_syncframe_ranges`, `aac_asc::SamplingFrequencyIndex::table_hz` (one copy of the ISO/IEC 14496-3 Table 1.10 rate table), new `validate_media_segment` checks (`media.mdat.overlap`, `media.tfhd.default-base-is-moof`, `media.sample.non-sync-first` at WARNING, `track.tfhd.unknown-track`; `track.tfdt.discontinuity` now pairs by `tfhd.track_id`), and `TrunSample`/`TrackFragmentHeaderBox` `effective_flags()`.

Preservation fixes that round-trip files the crate used to rewrite: `moof`/`traf` children the crate does not model (`sbgp`, `sgpd`, `subs`, `saiz`, `saio`, `meta`) are kept and a `traf` with no `trun` parses; a `uuid` child keeps its 16-byte `usertype`; `hvc1`/`hev1`/`vvc1` entries keep `colr`, `pasp`, `btrt`, `clli`, `mdcv`, `dvcC`, `dvvC`; `protect_media_segment` counts a `moof`'s opaque children and refuses a `traf` that already carries `senc`/`saiz`/`saio`.

## Fixes

- **Panics and hostile-input loops** (beyond the advisories above): `AnnexBNalIter::next` recursed once per empty NAL, so a run of start codes from any hostile H.264 PES grew the stack until the process aborted, which cannot be caught; AMF0 object nesting recursed without bound (now `Amf0TooDeep`); `read_sei_varint` overflowed `u32`; `AudioSpecificConfig::serialize_into` zeroed the caller's entire buffer; the CLI `--key` panicked on a 32-byte non-ASCII argument.
- **Repackaging**: `Repackage` no longer overflows (panic in debug, wrap in release) interleaving tracks whose timescales have a huge least common multiple (exact `u128` cross-multiply now); `Media::trim` measures its window on one origin so audio no longer plays early by the keyframe-snap distance; the batch TS-HLS packager is O(samples), not O(segments x samples); `splice::concat`/`splice_insert` match tracks by `track_id` independent of document order and cut every track at the same absolute instant.
- **Fragment and progressive layout**: `CencDecryptor` on progressive protected MP4 honours `co64` (the duplicated expander read only `stco`); `stsz.sample_count` is authoritative for progressive layout and `stsc.first_chunk` must be at least 1 and strictly ascending; a final `mdat` cut short by a truncated capture is clamped to the file end as documented; a `senc` with flag `0x000001` (PIFF) is rejected rather than misparsed.
- **FLV/RTMP**: `read_chunks` applies a fmt-3 chunk's inherited timestamp delta and honours Abort Message; `FlvMux::package` returns an error for a composition offset outside the signed 24-bit field and for a zero track timescale, and rescales durations into FLV millisecond timestamps; the FLV demuxers no longer fold a 65 536-wide SPS to width 0; `StreamingFlvDemux::feed` consumes a corrupt config tag instead of re-failing on it for ever, and memmoves its buffer once per call instead of once per tag.
- **Misc codecs and timing**: `nal::access_unit_is_rap` no longer treats a bare SPS as a random-access point (it also requires an I-slice); `AudioSpecificConfig::to_adts_header` no longer emits profile 0 for HE-AAC explicit signalling; `TsDemux` leaves ADTS `crc_check` bytes out of the sample and scales duration by raw data blocks; `rtp_sdp::avc_config_from_sps_pps` fills the High-profile chroma/bit-depth trailer; `klv`, `flac` (`dfLa` block bounds and STREAMINFO-first), `opus` (`dOps` channel-map length) and `colr nclx` parse and serialize reject what they used to misframe.

## Performance (optimization sweep, #1079, #1080, #1081)

Output is byte-identical on the committed fixtures (`tests/sweep_output_golden.rs`, hashes captured pre-sweep) and every claim is backed by an allocation or work counter (`tests/alloc_counts_sweep.rs`), not a timing. Examples: `CencDecryptor` allocates 2.14x of the file size, down to 1.21x (0.21x via `from_fmp4_bytes`); `ProgressiveMux` 4.12x to 2.20x, `MkvMux` 11.45x to 2.93x, `TsMux` 7.70x to 5.40x of output size; `hvcC` parsing bounds pre-allocation by the body length (1 581 000 bytes down to 32 for a hostile header); `Segmenter` no longer rebuilds the `moov` per cut (109 to 18 allocations). Duplicated walkers, scanners and bit readers were consolidated onto single owners (#1141).
