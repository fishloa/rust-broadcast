# multimux 0.19.0

_Released 2026-11-15._

- `scte35-splice` 6 -> 7: `SpliceTime::pts_time` is a validated `broadcast_common::clock33::Clock33`, and `SpliceInsert` carries its flags and times in one `SpliceMode` (see that crate's changelog).

### Changed
- BREAKING: the remaining `f64` seconds in the runtime config are `std::time::Duration`, renamed to drop the now-contradictory `_secs` suffix while keeping every JSON key and unit unchanged through a serde adapter (part of #2731): `Config::target_duration_secs`/`request_timeout_secs`/`concurrency_queue_timeout_secs`/`ingest_connect_timeout_secs`/`ingest_read_timeout_secs` are `Config::target_duration`/`request_timeout`/`concurrency_queue`/`ingest_connect_timeout`/`ingest_read_timeout`, each `#[serde(rename = "<old name>", with = "seconds_duration")]` so a config file written with the old key still parses; the setters are `with_target_duration`/`with_request_timeout`/`with_concurrency_queue_timeout`/`with_ingest_connect_timeout`/`with_ingest_read_timeout` taking a `Duration`; `RouteConfig::target_duration_secs`/`RouteHandle::target_duration_secs()` are `target_duration`/`target_duration()` (`RouteConfig::with_target_duration`); the registry's `InputCtx::target_duration` is a `Duration`; and `TsHlsIdrFallback::bound` takes a `Duration`. A `Duration` cannot be NaN, negative or infinite, so config validation now only rejects a zero or an over-bound value. Migration: `.with_target_duration_secs(4.0)` -> `.with_target_duration(Duration::from_secs(4))`, `.with_request_timeout_secs(30.0)` -> `.with_request_timeout(Duration::from_secs(30))`, `cfg.target_duration_secs` -> `cfg.target_duration`, `handle.target_duration_secs()` -> `handle.target_duration()`.
- BREAKING: `MultimuxError::ConfigInvalid { field: &'static str, reason }` and `DvrError::Config { field: &'static str, reason }` carry a typed `crate::error::ConfigField` enum (one variant per config path, with `name()` returning the dotted path) instead of a `&'static str`, so a caller matches the field rather than the message text. A `broadcast-client` sub-config failure is reported as `ConfigField::RoutesInput` with the sub-field name carried in `reason` (#2739).
- BREAKING: the push transports' string errors are typed (#2734): `RtmpPushError::Connect(String)`/`Protocol(String)` carry `RtmpConnectError` (`Url`/`NotConnected`/`Handshake(io::Error)`) / `RtmpProtocolError` (`NoCarriableTrack`/`Flv`/`Amf`/`Encode(io::Error)`); `RtspPushError::Connect(String)`/`Protocol(String)`/`SessionLost(String)` carry `RtspConnectError` (`Url`/`NoHost`/`Credentials`/`Rtsp`/`NotConnected`) / `RtspProtocolError` (`Status`/`UnexpectedEvent`/`Rtsp`/`Packetise`/`NotTsAligned`) / `SessionLost(rtsp_runtime::Error)`, and `ProtocolFailure::Other(String)` is `Other { reason }`. The dead `MultimuxError::Other(String)` is removed. A caller branches on the typed kind rather than the message text.
- BREAKING: `origin::admin::ReloadSummary` (the `POST /admin/reload` body) is `#[non_exhaustive]`: a name set a reload learns to report later is an additive change for a caller that reads the summary, and the JSON body can grow a key the same way. The type is produced by the server, never by a caller (#2736).
- The catch-up playlist renders each `#EXTINF` from the segment's `Duration` through `broadcast_hls::DecimalSeconds::from_duration` instead of re-validating a converted `f64` with `.expect`, so a production path cannot panic on a non-finite duration. The live tail's segment duration now comes from `hls_runtime::server::ClosedSegment::duration` (a `Duration`) rather than a float round-trip (#2713).
- BREAKING: `config::ReconnectPolicy` is `broadcast_common::backoff::ReconnectPolicy` (`backoff: BackoffSteps` + `max_attempts: Option<NonZeroU32>`) instead of a local `initial_backoff_ms`/`max_backoff_ms` struct, and the origin supervisor's `Backoff` is gone (its reconnect pacing is `broadcast_common::backoff::RetrySchedule` directly). Migration: a JSON `reconnect` object now names `backoff.steps` (a duration list) and `backoff.cap` (a duration) rather than `initial_backoff_ms`/`max_backoff_ms`, and a bounded retry names `max_attempts` as a non-zero number; `ReconnectPolicy::doubling(min, max)` rebuilds the old doubling schedule (#2690).
- Follows the `webrtc-runtime` clock and URL changes (#2697): the WHIP/WHEP servers build their machine's resource URL as a parsed `url::Url` (`webrtc_session::resource_url`; the `Location` is now absolute, `https://whip.invalid/whip/session/<id>` / `https://whep.invalid/whep/session/<id>`), the transport timers and every `now` handed to `MediaTransport`/`apply_ice_ops` are `broadcast_common::stage::Timestamp` on the transport's own clock (`MediaTransport::stamp_of`/`now_at` at the boundary), and the `whip-response-headers` golden pins the absolute `Location`.
- BREAKING: `push::SendMediaError::Mux` carries a typed `push::MuxError` (`Package(transmux::Error)`, `Flv(transmux::FlvError)`, `Transport(Box<dyn Error + Send + Sync>)`, `NoCarriableTrack`) instead of a `String`, so a caller tells a codec mismatch from a muxer refusal without reading the text; `PushTransportEgress::new` takes only the transport (the static "nothing carriable" message is gone; the reason is `MuxError::NoCarriableTrack`), and the private flush outcome's failure is a `MuxError`. The `rtmp::tc_url_for_test`/`rtsp::control_url_for_test` seams return typed errors (`TcUrlError`, `rtsp_runtime::Error`) (#2695).
- BREAKING: media positions in the catch-up/DVR path are typed instead of bare nanoseconds: `dvr::IndexEntry::start` is a `broadcast_common::Timestamp` (was `start_pts_ns: u64`) and `duration` a `Duration` (was `duration_ns: u64`), and `hls_runtime::server::ClosedSegment::start` is a `timed_metadata::MediaTime` (was `start_ns: u64`). The `pN.idx` sidecar keeps its `start_pts_ns`/`duration_ns` whole-nanosecond keys, so an existing sidecar still parses (#2693).
- BREAKING: the `Srt` input's `latency` is a `Duration` (was `latency_ms: Option<u16>`; the JSON key stays `latency_ms` in whole milliseconds), `SrtRoute::with_latency` takes `Option<Duration>` (was `with_latency_ms(Option<u16>)`), and the pushed `srt://` URL's latency is applied as a `Duration` (#2693).
### Removed
- BREAKING: the eight `serve*` entry points (`serve`, `serve_config_file`, `serve_config_file_with_registry`, `serve_config_file_with_registry_on_admin`, `serve_config_file_with_registry_on_admin_prebound`, `serve_with_registry`, `serve_with_registry_on`, `serve_with_registry_on_admin`). The origin has one way in: `Server::new(ServeRequest)` then `.serve().await`. `ServeRequest::new(config)` replaces `serve`/`serve_with_registry(config, ..)` and `ServeRequest::from_json_file(path)?` replaces `serve_config_file`/`serve_config_file_with_registry(path, ..)` (it keeps the `POST /admin/reload` path); `.with_registry(r)` carries what the `_with_registry` variants did. Migration: `multimux::serve(config).await` becomes `multimux::Server::new(multimux::ServeRequest::new(config)).serve().await` (likewise for `multimux::serve_config_file`), so reload support is a property of the request, not a separate function (#2665).
- BREAKING: the pre-bound-listener seams, `serve_with_registry_on`, `serve_with_registry_on_admin`, `serve_config_file_with_registry_on_admin` and `serve_config_file_with_registry_on_admin_prebound`, are setters on the request (`ServeRequest::with_prebound_media`, `with_prebound_listeners`, `with_prebound_binds`), all `test-seams` only. Migration: `serve_with_registry_on(media, config, registry)` becomes `ServeRequest::new(config).with_registry(registry).with_prebound_media(media)`; add `.with_prebound_binds(prebound)` for the file-defined case (#2665).
- BREAKING: the `serve_hyper_util_with_timeout`/`_with_limits`/`_with_accept_source`/`_with_task_gauge` test seams are `test-seams` only, like every other seam in the crate; they were `#[doc(hidden)]` but compiled into a production build (#2665).
- BREAKING: every remaining test-only hook — the WHIP/WHEP harnesses (`serve_for_test*`, `whip_router_for_test`, `whep_router_for_test`, `parse_offer_for_test`, `render_answer_for_test`, `render_whep_answer_for_test`, `restart_fragment_for_test`), `push::rtmp::tc_url_for_test`, `push::rtsp::control_url_for_test`/`push_sdp_for_test`/`push_media_for_test`, `output::dash::format_iso8601_for_test`, `source::dash_pull::parse_iso8601_utc_for_test` and `RouteHandle::first_trunk_for_test` — is reachable only through `crate::test_seam`, behind `test-seams`/`test-hooks`; the retired `multimux::webrtc_ice` module is folded into it. `push::srt::srt_url_outcome_for_test` is gone: `test_seam::parse_srt_url_for_test` returns the typed `(dial address, srt_runtime::SrtUrl)` parse outcome instead of a rendered line (#2696).
### Changed
- Follows the HLS sequence-number types (#2699): a rendered playlist's `msn` and a continuation's `next_media_sequence` are `broadcast_hls::MediaSequence` (read back with `.value()` where a DVR floor needs a number).
- Follows the RTSP config change (#2698): the push output builds its session with `ClientSession::new(RtspClientConfig::default())`, and the RTSP push wire test drives a `ServerSession::new(RtspServerConfig::default().with_session_ids(SessionIdSource::counter(..)))`.
- Follows the pull-client request-shape changes (#2655): the source host reads `Action::HttpRequest::byte_range` as a `broadcast_common::range::ByteSpan` and sends it with `ByteSpan::range_header()`.
- Follows the HLS origin config change (#2661): the LL-HLS/audio/subtitle origins are built with `HlsOriginConfig::new(trunk, target_duration_secs, window_segments)…` and `HlsOrigin::new(config)` instead of `HlsOrigin::builder(…).build()`.
- BREAKING: `config::Config`, `config::ReconnectPolicy`, `config::AdminSpec`, `config::UdpSocketSpec`, `config::SignedUrlKeySpec`, `dvr::DvrConfig`, `push::RtmpTransportConfig`, `push::SrtTransportConfig`, `push::RtspTransportConfig` and `output::whep::WhepAnswerParams` are now `#[non_exhaustive]`; build them with `Default::default()` + `with_*` (or `AdminSpec::new`, `SignedUrlKeySpec::new`, `WhepAnswerParams::new`) instead of struct literals, so a future field is additive (#2664).
- BREAKING: the client host handles `Action::UdpConnect` for the SRT caller (it resolves the peer with `lookup_host`, exactly as before) and `Action::UdpBind { addr: SocketAddr, .. }` for a receive bind (binding the literal `addr`, or the unspecified address of its family when a multicast group is joined). A receive bind is no longer given a host name to resolve. `source::udp::requested_recv_buffer_bytes` and `DEFAULT_RECV_BUFFER_BYTES`'s consumers take/track `NonZeroU32`, following `broadcast_common::net::UdpOptions::recv_buffer_bytes` (#2654 B5).
- BREAKING: `source::TrackInit::clock_rate` is a `Timescale`. A WHIP offer whose H.264 `a=rtpmap` carries no valid clock rate is refused instead of read as 90 kHz, and a push sample for a track with no spec is dropped instead of timed at 1 Hz (#2657).
- BREAKING: `Config::part_target_ms: u32` is `Config::part_target: Duration`, the JSON key and unit are unchanged (`"part_target_ms": 500` still loads and is whole milliseconds), `RouteConfig::part_target_ms`/`with_part_target_ms` are `part_target: Duration`/`with_part_target(Duration)`, `RouteHandle::part_target_ms()` is `part_target() -> Duration`, and the registry's `InputCtx` carries `part_target: Duration`. A zero part target is `ConfigInvalid { field: "part_target" }` (was `part_target_ms`).
- Follows the adapter-name breaking changes in `rtsp-runtime`, `rtmp-runtime`, `srt-runtime`, `smooth-runtime` and `broadcast-client` (#2660): the RTMP input binds with `io::RtmpServerConfig` and builds its sessions from `server::RtmpServerConfig`, the RTSP push connects with `RtspClientConfig::default().with_session(..).with_timeouts(..)`, and the SRT input/push build `io::SrtSocketConfig` explicitly instead of relying on `impl Into`.
- BREAKING: `MultimuxError::Protocol` now carries `phase: Phase` and `kind: ProtocolFailure` (typed status/timeout/source) instead of `phase: &'static str, reason: String`; `Sdp` and `Auth` are now tuple variants `Sdp(#[source] SdpError)` and `Auth(#[source] broadcast_auth::Error)`; `OutputKind::build()`/`build_with_playlist_name()` now return `Result<Arc<dyn Output>, MultimuxError>`; `DvrConfig::validate()`, `DvrRecorder::feed_si`, `poll_and_persist`, `poll_and_persist_inits` now return `DvrError` (#2658).
- BREAKING: `source::udp::UdpBindOptions` is removed in favour of `broadcast_common::net::UdpOptions` (the join now lives in `UdpOptions::join`, one `MulticastInterface` value instead of a free-text `multicast_interface`). Migration: `UdpBindOptions { recv_buffer_bytes, reuse_address, multicast_interface: Some(text), reuse_port }` becomes `UdpOptions::new().with_recv_buffer_bytes(..).with_reuse_address(..).with_reuse_port(..).with_join(MulticastJoin::new(group).with_interface(MulticastInterface::parse(text)?))`. `source::udp::bind_udp(addr, group, opts)` keeps its shape.
- BREAKING: `TsUdpRoute::new(name, addr)` and `RtpUdpRoute::new(name, addr, sdp)` no longer take a `multicast_group`; the group is the route's socket options' join (`with_socket_options(UdpOptions { .. })`). `TsUdpRoute::with_multicast_group`/`RtpUdpRoute::with_multicast_group` are removed; `with_socket_options` now takes `UdpOptions`. Migration: `TsUdpRoute::new(name, addr, Some(group))` becomes `TsUdpRoute::new(name, addr).with_socket_options(UdpOptions::new().with_join(MulticastJoin::new(group.parse()?)))`.
- `routes.input.multicast_interface` accepts a system interface name as well as an IPv4 address or an IPv6 interface index; a value written like an IPv4 address but not one is now a config error at load (`validate`) instead of at the first bind.
- BREAKING: `rtsp-runtime`/`broadcast-auth` error variants are now typed (`TransportParse(TransportParseError)`, `ChallengeParse(HttpAuthError)`); migrated call sites (#2659).
- The HTTP-JSON config keys are unchanged (`recv_buffer_bytes`, `reuse_address`, `reuse_port`, `multicast_interface`).
### Fixed
- A configured multicast interface of the group's other address family is refused when the route is resolved, instead of failing in the bind with a raw OS error (#2663).
### Added
- `source::udp::bind_options`: the `UdpOptions` a route bind asks for (`multicast_group` as the join's group, the crate's default `SO_RCVBUF` filled in), validating the join first.
- `dvb-si` is built with its new `legacy-charsets` feature, so KS X 1001 / GB-2312 / Big5 EIT event names keep decoding (#2635).
- `tower-http` 0.6 to 0.7 (timeout, limit, cors, gzip compression and decompression layers; no behaviour change); `rtsp-types` follows `rtsp-runtime` to 0.2.
### Fixed
- A split-audio rendition's LL-HLS part target is applied to its own rendition: followers carry their rendition index instead of being paired with audio servings by position, so an earlier rendition whose selector matched nothing no longer shifts every later part target one slot (#2637).
- A failed reload that restores a changed route keeps every DASH Period the route still listed: continuing from a route no longer drains its retained programs, so a second continuation from the same route sees them too (#2638).
- Removed a leftover question comment from the end-of-ingest flush path (#2639).


### Removed
- Removed the unused `backon`, `percent-encoding` and `caption-convert` dependencies (reconnect backoff is the crate's own `supervisor::Backoff`) and the unused `sha2` dev-dependency.
