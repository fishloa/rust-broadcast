# st12-1 0.3.1

_Released 2026-10-05._

Patch release: one parser fix (#1117). No API is removed or changed apart from a new variant on the `#[non_exhaustive]` `Error`, so nobody must act; upgrade if you parse LTC codewords from untrusted or noisy sources.

## Fix

- **`LtcFrame::parse` accepted time-address digits that are not BCD (#1117).** Each time-address field (hours, minutes, seconds, frames) is a tens part plus a 4-bit units nibble. A units nibble above 9 is not a legal BCD digit (ST 12-1 section 9.2.1), but it was folded into a plausible decimal value (a units nibble of `0xF` in a frames field still passed the `frames <= 29` check), so `parse(x).to_bytes() != x` for such input: the result no longer corresponded to the original bytes. `parse` now returns the new `Error::InvalidBcdDigit { field, tens, units }`, where `field` is `hours`, `minutes`, `seconds` or `frames` and `units` is the offending nibble `0x0..=0xF`. Input that previously parsed to a silently wrong timecode is now an error.

Callers that match `Error` exhaustively already need a wildcard arm because the enum is `#[non_exhaustive]`.

## Dependencies

`broadcast-common` `9.3` -> `9.4` (see `broadcast-common-9.4.0.md`). No other `Cargo.toml` change.
