# v11.1.0 — 2026-10-13

Lockstep minor. **`dvb-si`: spec-correct reserved bits and no more misframed descriptors.**

## Changed (dvb-si)

- **Reserved bits emitted per the spec.** Twelve ISO/IEC 13818-1 / TS 102 006 descriptors now serialize their reserved bits as `1` where the spec table says so (`video_stream`, `system_clock`, `maximum_bitrate`, `smoothing_buffer`, `std`, `avc_timing_and_hrd`, `svc_extension`, `mvc_extension`, `multiplex_buffer_utilization`, `metadata_pointer`, `metadata` and the SSU selector in `data_broadcast_id`); `j2k_video` stays `0` because its table says so. **Parsing is unchanged and tolerant:** a broadcaster that sends `0` still parses to the same typed fields, and re-serializing normalizes the bits to the spec value. A caller that must preserve non-conformant reserved bits byte-for-byte keeps the original bytes. Evidence: a real-capture and TSDuck survey (`tests/reserved_bits_real_streams.rs`) asserts byte-exact re-serialization; no real stream contradicted the spec. Eight descriptors have TSDuck-only evidence and four have none (spec convention only).
- **Flag/`Option` consistency.** `metadata`, `content_labeling`, `j2k_video` and `supplementary_audio` derive their wire flags from the data at serialize time, so a mismatched flag can no longer write a misframed descriptor.
- **Trailing data tolerated.** `video_depth_range` keeps an over-long hint verbatim and round-trips byte-exact; `protection_message` ignores bytes after the tag loop.
