# rdd29 0.3.0

**Release date:** 2026-08-10

MSRV raised to 1.95.0, and `ZoneId` gains `#[non_exhaustive]`. The MSRV bump
carries no functional or API change; the `ZoneId` change is breaking for any
downstream `match` on it.

## What changed

- MSRV raised to **1.95.0** (issue #949), part of a workspace-wide bump that
  removes the MSRV split `webrtc-runtime`'s optional `media` feature used to
  require. No functional or API change on its own.
- `ZoneId` (`object_definition`) now carries `#[non_exhaustive]` (issue #806's
  non_exhaustive drift-guard audit).
- Added `tests/non_exhaustive_coverage.rs`, a drift guard that keeps
  `#[non_exhaustive]` coverage from silently regressing (issue #806).

## Breaking changes

`ZoneId` is now `#[non_exhaustive]`. Before:

```rust
match zone_id {
    ZoneId::Room => { /* ... */ }
    ZoneId::Loudspeaker => { /* ... */ }
    // exhaustive, compiled without a wildcard arm
}
```

After — a wildcard arm is required:

```rust
match zone_id {
    ZoneId::Room => { /* ... */ }
    ZoneId::Loudspeaker => { /* ... */ }
    _ => { /* ... */ }
}
```

## Migration

Add a wildcard arm to any exhaustive `match` on `ZoneId`. Rebuild with
rustc >= 1.95.0.
