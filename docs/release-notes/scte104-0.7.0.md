# scte104 0.7.0

_Released 2026-11-07._

Breaking-class release (0.6 -> 0.7): the error enum wraps the shared kinds and `InvalidValue`, `ReservedSet` and field-overflow cases carry wire values (#1715); `UnexpectedOpId` and two marker traits are removed.

Version: 0.6.0 -> 0.7.0.

## Breaking changes and migration

What the CHANGELOG records as breaking:

- `Error::InvalidValue { field, reason }` (no value) is replaced. `Error::InvalidValue` now wraps `broadcast_common::error::InvalidValue { field, value, reason }` and is returned for an unknown `time_type`; a serializer value above its field's range returns `Error::FieldOverflow { field, value, max }` (`TAI_seconds` over 48 bits, `messageSize` over 16 bits); the `component_mode`/`injector_component_list` presence mismatch returns `Error::InvalidField { field, reason }`. New variant: `InvalidField`.
- error variants `BufferTooShort`, `OutputBufferTooSmall` now wrap `broadcast_common::error` types (tuple variants); `ReservedSet { field, expected: u16, got: u16 }` is replaced by `ReservedBits(broadcast_common::error::ReservedBits)` (`found` replaces `got`, widened to u64). Hand-written `From` impls removed. `InvalidValue` stays crate-specific (carries no offending value).
- `Error::UnexpectedOpId`: never constructed; the operation data parsers take the body after `opID` dispatch and cannot see the `opID`.
- `SingleOpDef` and `MultiOpDef` marker traits (no impls or bounds anywhere).

### Shared error kinds from `broadcast_common::error`

`broadcast-common` 11 defines the common failure kinds once, as `Copy` structs. This crate's error enum wraps them with `#[error(transparent)] Kind(#[from] broadcast_common::error::Kind)`, so the variants `BufferTooShort` and `OutputBufferTooSmall` (and any other kind named in the list above) changed from struct variants to tuple variants holding the shared struct. The fields are the same, so only the pattern changes, and `From` impls exist, so `?` and `.into()` still build them.

```rust
// before
match err {
    Error::BufferTooShort { need, have, what } => eprintln!("{what}: need {need}, have {have}"),
    _ => {}
}
// after
match err {
    Error::BufferTooShort(e) => eprintln!("{}: need {}, have {}", e.what, e.need, e.have),
    _ => {}
}
```

The display text of these variants now follows the common wording shared by every crate in the wave.

### Renamed and removed items

```text
Error::ReservedSet { field, expected, got }
    -> Error::ReservedBits(e)  // e.field, e.expected, e.found (u64)
Error::InvalidValue { field, reason }
    -> Error::InvalidValue(e)  // e.field, e.value, e.reason
Error::InvalidValue { .. }  // value above the field range
    -> Error::FieldOverflow { field, value, max }
Error::UnexpectedOpId
    -> (removed; never constructed)
```

### Typed errors (#1715)

An unknown `time_type` returns `Error::InvalidValue` with the value; a `TAI_seconds` over 48 bits or `messageSize` over 16 bits returns `Error::FieldOverflow { field, value, max }`; a `component_mode` / `injector_component_list` presence mismatch returns the new `Error::InvalidField { field, reason }`. The `SingleOpDef` and `MultiOpDef` marker traits had no impls or bounds and are removed.

## Added

- `From<broadcast_common::len::BufferTooShort>` and `From<broadcast_common::len::OutputBufferTooSmall>` for the crate error type.

Internal changes with no public effect (shared helpers replacing private copies, README as crate-root docs, `Clone`/`PartialEq`/`Eq` derives on error enums where every field allows it) are listed in the CHANGELOG.

## Dependencies

Workspace sibling requirements move to the new epochs of this wave:

- `broadcast-common` 10 -> 11

These are caret-epoch moves, so a project that names several of these crates must move them together.
