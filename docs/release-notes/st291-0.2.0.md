# st291 0.2.0

**Release date:** 2026-07-11

`st291` parses and serializes SMPTE ST 291-1 ancillary (ANC) data packets.
This release adds a second transport alongside the existing ST 2038
MPEG-2 TS/PES carriage: RFC 8331 / ST 2110-40 ANC data over RTP.

## What's new

- New `rtp` feature (additive, off by default): RFC 8331 RTP transport for
  ST 291-1 ANC data packets, sitting alongside the existing `ts` feature.
- `AncContent` -- shared ST 291-1 ANC-packet content factored out of the
  existing `AncPacket`, compiled unconditionally so enabling one transport
  never pulls in the other.
- `RtpAncPacket` -- per-ANC-packet placement (C/Line_Number/Horizontal_Offset/
  S/StreamNum) wrapping `AncContent`.
- `AncRtpPayload` -- full RFC 8331 payload with `Length`/`ANC_Count`
  cross-validation and reserved-field enforcement; implements Parse/Serialize.
- `AncRtpPayload::parse_rtp_packet` -- convenience composition over
  `rtp_packet::RtpPacket` for a full ANC-over-RTP packet.
- `FieldSense` enum for the 2-bit `F` field, with `name()`/`Display` labels.
- `Error::ReservedNotZero` and `Error::LengthMismatch` for RTP payload
  validation.
- Two new examples (`build_anc_rtp`, `parse_anc_rtp`) and a real fixture.
- Fuzz target now also exercises the RTP payload parsers.

## Migration

No breaking changes to the existing `ts`-feature API. The `rtp` feature is
off by default.
