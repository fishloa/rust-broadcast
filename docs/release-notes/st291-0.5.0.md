# st291 0.5.0

_Released 2026-10-17._

**Epoch-forced major-class release that also adds opt-in ST 291-1 parity validation.** There is no source-level API break of its own: `AncContent::has_valid_parity`, `verify_parity`, `validate` and `AncPacket::validate` (returning a typed `ValidationReport`) are additive, and parsing stays tolerant. The version is `0.5.0` because the crate now builds against `broadcast-common` 10 and `rtp-packet` 0.5 (the workspace epoch-purity rule forbids a bucket spanning two epochs). The committed `anc.bin` / `anc_rtp.bin` fixtures, which turned out to be non-conformant synthetic packets, are regenerated.

## Why this version

- **Proposed version:** 0.4.1 -> **0.5.0** (major-class: 0.x minor-epoch bump).
- **Own API/behaviour change class:** minor (additive parity validation API, `Error::ParityMismatch`; internal clock33 reuse).
- **cargo-semver-checks vs live 0.4.1 (all features):** none flagged. (Lint-based: it misses type changes of existing fields/arguments, so the CHANGELOG BREAKING list is the primary evidence.)
- **Epoch cascade:** epoch cascade from broadcast-common. Siblings it depends on that move epoch in this wave: broadcast-common, rtp-packet.
- **Caret epoch:** 0.4 -> 0.5; every workspace dependent must move with it.

## Breaking changes and migration

No source change is needed for st291's own API. Move every `broadcast-common` requirement to `10` (and `rtp-packet` to `0.5` if you use the `rtp` feature) so one copy of each resolves; `Serialize::to_bytes` was removed in `broadcast-common` 10, so replace `packet.to_bytes()` with `packet.try_to_bytes()?`.

New, opt-in validation (parsing is unchanged and still accepts non-conformant packets, so existing callers see no new errors):

```rust
let report = packet.validate();          // AncPacket::validate -> ValidationReport
if !report.is_valid() {
    // report.did_parity, sdid_parity, data_count_parity,
    // data_count_matches_udw, checksum: one bool per ST 291-1 check
}
content.verify_parity()?;                // Err(Error::ParityMismatch { what, word }) on the first bad word
```

Note for fixture owners: if your tests assert that the old synthetic `anc.bin` / `anc_rtp.bin` bytes round-trip, they were regenerated (Data_Count `0x102`/`0x203`, checksums `0x134`/`0x1AC`; all other bytes unchanged).

## What changed (from CHANGELOG `[Unreleased]`)

#### Added
- Explicit ST 291-1:2011 parity validation, grounded in the vendored standard itself (sections 6.1, 6.2, 6.4, 6.5, 6.7; verified on rendered PDF pp. 9, 12, 17): `AncContent::has_valid_parity`, `AncContent::verify_parity` (`Error::ParityMismatch`), `AncContent::validate` and `AncPacket::validate` returning a typed `ValidationReport` (DID/SDID/Data_Count parity, Data_Count vs UDW count, checksum). Opt-in only; parsing remains tolerant. Spec transcription in `docs/anc_parity_checksum.md`. Tests use Annex C's worked DID/DBN/DC words and hand-computed vectors with flipped-bit cases.
- Finding and fix: the committed `anc.bin`/`anc_rtp.bin` fixtures are synthetic (hand-constructed from ST 2038 Table 2, not real captures) and used to fail ST 291-1 (Data_Count had no parity bits, checksums off by one). They are regenerated with the crate's own `AncContent::with_parity`/`compute_checksum` (`Data_Count` `0x102`/`0x203`, checksums `0x134`/`0x1AC`; all other bytes unchanged) and `tests/fixture_validate.rs` now asserts `is_valid()` on both, with a separate hand-built non-conformant packet providing the bite (it previously pinned the failures, so it could not catch a real defect).

#### Documentation
- README and crate-root docs restructured: what it does / does not, standards-supported table (ST 2038:2021, RFC 8331, ST 2110-40, ST 291-1), feature table, design notes; removed the stale "parity/checksum not validated" claim (explicit `verify_checksum`/`build` helpers exist).

#### Changed (BREAKING: epoch — requires broadcast-common 10)
- Builds against new caret epochs of workspace siblings (`broadcast-common` 9 -> 10, `rtp-packet` 0.4 -> 0.5). A caret-epoch change is major-class for this crate under the epoch-purity rule (`docs/RELEASE-AUDIT.md` §2), whatever its own API diff. `Serialize::to_bytes` was removed (use `try_to_bytes`); consumers must resolve a single `broadcast-common` 10.

#### Changed
- Internal: the 5-byte marker-bit PTS/DTS/`DTS_next_AU` field is encoded/decoded by `broadcast_common::clock33::{pack_marked, pack_marked_with, unpack_marked}` instead of a local copy (each crate keeps its own prefix / marker validation and error variants); no behaviour change (#1208).
