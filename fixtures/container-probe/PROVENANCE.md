# `container-probe` fixtures — provenance

Fixtures for the `container-probe` crate
([design spec](../../docs/superpowers/specs/2026-08-11-container-probe-design.md)).

Every file here is either **real encoder/muxer output** (ffmpeg 8.1.2, own work)
or **derived from a fixture already in this repo**, except one clearly-marked
synthetic. All are MIT OR Apache-2.0, no copyleft, no third-party redistribution.

Regenerate with [`GENERATE.md`](GENERATE.md).

## Real muxer/encoder output

Generated by ffmpeg 8.1.2 from synthetic `lavfi` inputs (`testsrc2`, `sine`).
The *content* is synthetic; the **container framing and codec bitstreams are
real** — produced by real muxers and real encoders, which is what a probe reads.

## Derived from an existing repo fixture

| File | Format probed | Derivation | Licence |
|---|---|---|---|
| `ts_midpacket_phase.ts` | MPEG-2 TS, 188-byte stride, non-zero phase | `fixtures/ts/h264_aac.ts` with its **first 77 bytes removed** — a real capture that began mid-packet. Every byte is real captured data; only the start offset differs. Verified lattice: **stride 188, phase 111** (= 188 − 77), 438 syncs. This is the bite test for phase search; today's implementation fails it outright. | Inherits `fixtures/ts/h264_aac.ts` — own work, MIT OR Apache-2.0 |

## Synthetic — one file, clearly marked

| File | Format probed | Why synthetic | Licence |
|---|---|---|---|
| `ts_204_stride_SYNTHETIC.ts` | MPEG-2 TS, 204-byte stride | **No real 204-stride capture exists in this repo** — all 36 real `.ts` captures scanned are 188-stride, and real 204 (DVB with Reed–Solomon parity, ETSI EN 300 744) is produced only by DVB modulator/capture hardware; ffmpeg cannot generate it. Built from `fixtures/ts/h264_aac.ts`'s **real 188-byte packets** with 16 **zeroed** bytes appended per packet at the RS-parity position. The TS packets are real; the parity bytes are fabricated. This is acceptable **only** because a container probe detects the *stride* and never reads the parity — so the fabricated bytes are outside what the code under test examines. It exercises the 204 branch of the stride lattice; it does **not** prove behaviour against genuine DVB RS-coded data. | Own work — MIT OR Apache-2.0 |

## Known coverage gaps

Recorded rather than left silent, per the design spec's testing rules:

- **Genuine 204-stride DVB capture** — see the synthetic note above. Replace
  `ts_204_stride_SYNTHETIC.ts` with a real capture if one is ever obtained, and
  delete the synthetic.
- **208-byte stride** — supported by the prober's stride set, with no fixture of
  any kind. Untested.
- **Matroska vs WebM DocType discrimination** — covered by the existing
  `fixtures/mkv/` and `fixtures/webm/` corpora rather than by files here.
