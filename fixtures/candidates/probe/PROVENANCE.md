## Synthetic — one file, clearly marked

| File | Format probed | Why synthetic | Licence |
|---|---|---|---|
| `ts-204-stride-synthetic.ts` | MPEG-2 TS, 204-byte stride | **No real 204-stride capture exists in this repo** — all 36 real `.ts` captures scanned are 188-stride, and real 204 (DVB with Reed–Solomon parity, ETSI EN 300 744) is produced only by DVB modulator/capture hardware; ffmpeg cannot generate it. Built from `fixtures/ts/h264-aac.ts`'s **real 188-byte packets** with 16 **zeroed** bytes appended per packet at the RS-parity position. The TS packets are real; the parity bytes are fabricated. This is acceptable **only** because a container probe detects the *stride* and never reads the parity — so the fabricated bytes are outside what the code under test examines. It exercises the 204 branch of the stride lattice; it does **not** prove behaviour against genuine DVB RS-coded data. | Own work — MIT OR Apache-2.0 |

## Known coverage gaps

Recorded rather than left silent, per the design spec's testing rules:

- **Genuine 204-stride DVB capture** — see the synthetic note above. Replace
  `ts-204-stride-synthetic.ts` with a real capture if one is ever obtained, and
  delete the synthetic.
- **208-byte stride** — supported by the prober's stride set, with no fixture of
  any kind. Untested.
- **Matroska vs WebM DocType discrimination** — covered by the existing
  `fixtures/mkv/` corpus rather than by files here.

## Derived — mid-packet TS (real data, shifted start offset)

Removes the first 77 bytes of a real capture, producing a file that begins
mid-packet. Every byte is real captured data; only the start offset differs.
Detects as stride 188, phase 111 (= 188 − 77).

```bash
python3 -c "
d = open('fixtures/ts/h264-aac.ts', 'rb').read()
open('fixtures/ts/ts-midpacket-phase.ts', 'wb').write(d[77:])
"
```

## Synthetic — 204-byte stride

**Read `PROVENANCE.md`'s entry for this file before relying on it.** The TS
packets are real; the 16 appended parity bytes per packet are zeroed, not
genuine Reed–Solomon parity. Valid only because a probe detects the stride and
never reads the parity.

```bash
python3 -c "
d = open('fixtures/ts/h264-aac.ts', 'rb').read()
out = bytearray()
for i in range(len(d) // 188):
    out += d[i*188:(i+1)*188]
    out += b'\x00' * 16          # RS(204,188) parity position — ZEROED
open('fixtures/ts/ts-204-stride-synthetic.ts', 'wb').write(bytes(out))
"
```

## Verifying the lattice of any TS-family fixture

The check used to confirm each stride/phase claim in `PROVENANCE.md`:

```bash
python3 -c "
import sys
d = open(sys.argv[1], 'rb').read()
for stride in (188, 192, 204, 208):
    for phase in range(stride):
        n = 0
        while phase + n*stride < len(d) and d[phase + n*stride] == 0x47:
            n += 1
        if n >= 8:
            print(f'stride={stride} phase={phase} syncs={n}')
            break
" <file>
```
