# Tier 1 box fixtures

Small files written by real tools, each carrying tier 1 boxes the crate types.
`tests/it/tier1_fixtures.rs` asserts their typed values against the tool's own
dump and re-serializes every box byte-exact from the file's bytes;
`tests/it/tier1_boxes.rs` holds the boxes no installed tool writes, assembled
from the clause and labelled as such.

Tools used, with versions:

| Tool | Version |
|---|---|
| `MP4Box` (GPAC) | 26.07-revrelease |
| `ffmpeg` (`ffprobe`) | 8.1.2 |
| `afconvert` (macOS) | 2.0, macOS 27.0.1 |
| `mp4dump` (Bento4) | 1.6.0.641 |

`mp4dump` names a box but does not descend into every one of them, so the
independent dump of a box's *fields* is `MP4Box -disox` (GPAC's XML box dump):
`MP4Box -disox -out dump.xml <file>`.

The source for the MP4Box files is `fixtures/mp4/h264-aac-prog.mp4` (2 s, one
AVC video track and one AAC audio track, written by Lavf); the DASH fixture
starts from a 6 s AVC/AAC file generated by the documented `ffmpeg` command.

## `track-description.mp4`

Carries `trgr` (a `msrc` group), `elng` and `kind`.

```sh
MP4Box -add fixtures/mp4/h264-aac-prog.mp4:tkgp=msrc,1 \
       -lang 2=en-US \
       -kind 2=urn:mpeg:dash:role:2011=main \
       -new fixtures/mp4/boxes/track-description.mp4
```

`mp4dump` prints the three boxes:

```
    [trgr] size=8+16
      [elng] size=8+10
    [trgr] size=8+16
      [kind] size=8+33
```

The audio track's `elng` string is `en-US`; its `kind` is
`urn:mpeg:dash:role:2011` with value `main`; both tracks carry a `msrc` group
with `track_group_id` 1.

## `track-group-ster.mp4`

Carries a `ster` group written by GPAC without the optional-looking trailing
`left_view_flag` word (the box is 16 bytes: header, version/flags and
`track_group_id` only).

```sh
MP4Box -add fixtures/mp4/h264-aac-prog.mp4:tkgp=ster,1 \
       -new fixtures/mp4/boxes/track-group-ster.mp4
```

The crate parses it with `left_view_flag` absent and round-trips the bytes
unchanged; a conformant `ster` with the flag word is covered by the
hand-assembled test.

## `ssix-sidx.mp4`

A single-file DASH presentation whose media segments carry `sidx` followed by
`ssix` (the GPAC `-ssix` option).

```sh
ffmpeg -y -f lavfi -i testsrc=duration=6:size=160x120:rate=25 \
       -f lavfi -i sine=frequency=440:duration=6 \
       -c:v libx264 -g 25 -pix_fmt yuv420p -c:a aac -shortest gen.mp4
MP4Box -dash 1000 -subsegs-per-sidx 1 -ssix -out seg.mpd gen.mp4
```

`mp4dump` prints five `[sidx] size=12+32` / `[ssix] size=8+20` pairs. Each
`ssix` has `subsegment_count` 1 and two ranges; the first segment's ranges are
level 1 / 3236 bytes and level 2 / 12184 bytes.

## `chnl-ipcm.mp4`

Two ISO PCM tracks, written by ffmpeg: track 1 stereo, track 2 5.1. ffmpeg
writes a `chnl` box inside an `ipcm` sample entry for exactly this case (ISO
PCM in MP4); it writes none for `mp4a`, `fLaC`, `Opus` or the QuickTime sound
entries, and GPAC writes one only when it muxes raw PCM as ISOBMFF style
(`-o out.mp4:ase=v1`, or `ase=v0`).

```sh
ffmpeg -y -f lavfi -i "sine=frequency=440:duration=0.15" \
       -f lavfi -i "sine=frequency=660:duration=0.15" \
       -filter_complex \
         "[0:a]aformat=channel_layouts=stereo[a0];[1:a]aformat=channel_layouts=5.1[a1]" \
       -map "[a0]" -map "[a1]" -c:a pcm_s16le -ar 48000 \
       -f mp4 fixtures/mp4/boxes/chnl-ipcm.mp4
```

`mp4dump` does not descend into the `ipcm` entries, so GPAC's XML dump is the
independent one:

```
<ChannelLayoutBox Size="22" Type="chnl" Version="0" Flags="0"
    stream_structure="1" definedLayout="2" omittedChannelsMap="0">
<ChannelLayoutBox Size="20" Type="chnl" Version="0" Flags="0"
    stream_structure="1" definedLayout="0">
  <Speaker position="0"/><Speaker position="1"/><Speaker position="2"/>
  <Speaker position="3"/><Speaker position="8"/><Speaker position="9"/>
```

The two boxes are the clause's two version-0 forms (§12.2.4.2): named layout
with an omitted-channel map, and no named layout with one explicit
`speaker_position` per channel of the sample entry (`channelcount` 6).

ffmpeg's `-f mov` PCM and `-f ipod` AAC outputs carry no `chnl`.

## `tsel.mp4`

A `tsel` (track selection) on track 1, written by MP4Box's `-group-add`.

```sh
MP4Box -add fixtures/mp4/h264-aac-prog.mp4 \
       -group-add switchID=7:criteria="cdec scsz":trackID=1 \
       -new fixtures/mp4/boxes/tsel.mp4
```

`mp4dump` prints `[tsel] size=8+16`, and GPAC's XML dump reads the two fields:

```
<TrackSelectionBox Size="24" Type="tsel" Version="0" Flags="0"
    switchGroup="7">
  <TrackSelectionCriteria value="cdec"/>
  <TrackSelectionCriteria value="scsz"/>
```

The second track joins no switch group (`-group-add` was given `trackID=1`
only), so its `tsel` is absent.

## `loudness.m4a`

Apple's encoder's loudness declaration: a `ludt` under the audio track's
`udta` holding one `tlou`, written by `afconvert --soundcheck-generate` when it
re-encodes a committed source.

```sh
afconvert -f m4af -d aac --soundcheck-generate \
    fixtures/mp4/h264-aac-prog.mp4 fixtures/mp4/boxes/loudness.m4a
```

`--anchor-generate` on an `m4af` output refuses to run without
`--soundcheck-generate`, and with it `afconvert` crashes (exit 139), so no
`alou` is produced here.

`mp4dump` prints `[ludt] size=8+27`. GPAC does not decode either box and prints
the `tlou` payload verbatim:

```
<UnknownBox Size="35" Type="ludt" ...>
  <UnknownBox Size="27" Type="tlou" ... data="0x010000000100000044F44E2302018F23049000">
```

The field values asserted by the test come from an independent bit-level read
of that payload (§12.2.7.2, version 1): one entry, `EQ_set_ID` 0,
`downmix_ID` 0, `DRC_set_ID` 0, `bs_sample_peak_level` 1103,
`bs_true_peak_level` 1102, `measurement_system_for_TP` 2,
`reliability_for_TP` 3, and two measurements: method 1 / value 143 /
system 2 / reliability 3, then method 4 / value 144 / system 0 /
reliability 0.

`reliability_for_TP` 3 is "measured and accurate" (§12.2.7.3). As a content
cross-check, `ffmpeg -i fixtures/mp4/boxes/loudness.m4a -af ebur128=peak=true`
independently measures integrated loudness -21.8 LUFS and true peak -14.5 dBFS
for the same file; Apple's peak meter reads 2.7 dB lower than ffmpeg's for this
content, so the test asserts the file's raw ISO/IEC 23003-4 fields, not a dB
value.

## Every other MP4-family file in the fixture trees

Round 1 claimed only the four boxes above were available from real files. Every
committed `.mp4`/`.mov`/`.m4a`/`.m4v`/`.3gp`/`.m4s` under `fixtures/` and
`private/fixtures/` (245 files) was walked with `isobmff::BoxIter`, descending
into the audio sample entries by their 28-byte tail so a `chnl` inside `ipcm`
is reachable. The only tier 1 boxes any of them carry are:
`elng`/`kind`/`trgr` (`track-description.mp4`, `track-group-ster.mp4`),
`ssix` (`ssix-sidx.mp4`), `chnl` (`chnl-ipcm.mp4`), `tsel` (`tsel.mp4`),
`ludt`/`tlou` (`loudness.m4a`), and an `elng` in
`private/fixtures/video/dolby-vision/iphone18promax-dv-p8.4-2160p30-7s.mp4`.

## Boxes no installed tool produced

These stay hand-assembled from the clause in `tests/it/tier1_boxes.rs`:
`dmix`, `alou`, `labl`, `stvi`, `leva`, `pdin`, `trep`, `csgp`, `stdp`, `padb`,
`stsg`.

What was tried, per box:

| Box | Tried |
|---|---|
| `dmix` | `MP4Box -h all`, `gpac -hx`, `gpac -h mp4mx`, `gpac -h mp4mx:x`, `gpac -h dash` (`downmix`, `dmix`): no switch. `gpac ...:ase=v1`/`ase=v0` on 5.1 PCM, AAC, AC-3, FLAC and Opus sources, and `ase=v1qt` on 5.1 WAV: no `dmix` in any output. |
| `alou` | `afconvert --anchor-generate` (refused, then crashed); `--soundcheck-generate` writes `tlou` only; `MP4Box` re-mux keeps `tlou` and adds none. |
| `labl` | `MP4Box -h all` (`labl`, `label`), `gpac -h mp4mx` (`udta`, `labl`): no switch. `-udta`/`-tags` write other user-data boxes. |
| `stvi` | `MP4Box -h all` (`stvi`, `stereo`): only `-hero-eye`, which writes a hero-eye box, not `stvi`. ffmpeg has no MP4 stereo-mode writer. |
| `leva` | `MP4Box -dash 1000 -ssix`, `-profile onDemand`, `-sample-groups-traf`, `-frag`; `gpac ... :ssix=1`, `:subs_sidx=1`, `ase=v1`. `-ssix` is the only index switch; `leva` assigns levels to scalable/tiled tracks and no installed tool authors one. |
| `pdin` | `MP4Box -h all`, `gpac -h mp4mx` (`pdin`, `progressive`): no switch. |
| `trep` | `MP4Box -h all` (`trep`, `prop`), `gpac -h mp4mx` (`trep`): no switch. |
| `csgp` | `MP4Box -h all`/`gpac -h mp4mx` (`compact`, `csgp`, `sgpd`); `-add ...:roll=5`, `:proll=5`, `:audio_roll=5`, `-frag`, `-sample-groups-traf`, `gpac :#grp_roll=5`: every run writes `sgpd`+`sbgp`, never `csgp`. |
| `stdp` | `MP4Box -h all` (`stdp`, `degradation`), `gpac -h mp4mx`: no switch. |
| `padb` | `MP4Box -h all` (`padb`, `padding`), `gpac -h mp4mx`: no switch. |
| `stsg` | `MP4Box -h all` (`stsg`, `sub-track`), `gpac -h mp4mx`: no switch. |

All 15 tool invocations of that sweep completed, and a four-CC scan of every
output found no tier 1 box other than the `ludt`/`tlou` MP4Box carried through
from an `afconvert` file.
