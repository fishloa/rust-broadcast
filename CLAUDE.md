# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Rust workspace of DVB (Digital Video Broadcasting) protocol parsers + builders, published to crates.io:

- **broadcast-core** — the frozen wire-format contract the wire crates build on: the symmetric `Parse<'a>` / `Serialize` traits (`traits`, re-exported at the root), checked field-width helpers (`len`), MSB-first bit I/O (`bits`), the shared error kinds (`error`), typed reserved-bit fields (`reserved`), the media `timescale` codec (with `timescale!`), the container-independent `cenc::CencScheme` scheme identity and the big-endian wire field readers (`wire`, the one home for the `read_uN`/`be_uN`/`*_at` family), plus the `impl_spec_display!` macro. `#![no_std]` + `alloc` on every target, with no non-optional dependency (only optional `serde`). Its public API is **meant to be frozen**: the `core_api_pin` guard fails on any un-reviewed addition, removal or rename. Unpublished; it reaches `1.0` before the owner calls the release.
- **broadcast-common** — shared foundations above the frozen `broadcast-core` contract: the `stage` contract (`Stage`: `feed`/`poll`/`finish`/`demand`, the incremental contract every workspace muxer, segmenter and protection pass implements), CRC-32/MPEG-2, the `bcd`/`time`/`hex` codecs, and `clock33` (33-bit PTS/DTS wrap arithmetic plus the 27 MHz PCR clock: `PCR_WRAP_27MHZ`, `pcr_from_parts`/`pcr_split`, wrap-safe `pcr_forward_distance`/`pcr_signed_distance`, and the 5-byte marker-bit timestamp codec `unpack_marked`/`pack_marked` - the one home for that arithmetic, guarded by `workspace-guards`' `clock33` table), `parity` (odd-parity protected byte shared by CEA-608 and teletext: `has_odd_parity`/`set_odd_parity`/`strip_parity`), and `xml` (feature `xml`): the one bounded quick-xml tree reader (limits on depth/attributes/size, DOCTYPE refused) shared by the XML-reading crates. It depends on `broadcast-core` for the `Parse`/`Serialize` contract, error kinds, field-width helpers, bit I/O, byte-level wire field readers, timescale and CENC scheme identity, and re-exports none of them. Everything else depends on it; versioned independently of the DVB lockstep.
- **broadcast-codec** — the codec seam: raw frame vocabulary (`CodecId`, `CodecParameters`, `Packet`, `AudioFrame`/`VideoFrame` with private fields and checked constructors, `Frame`, `CodecError`) plus the object-safe sans-IO `Decoder`/`Encoder` traits (`send`/`receive`/`finish`/`reset`) an outside codec library plugs into, and the provider registry the application builds: `CodecProvider` (name, `info`, `CodecDescriptor` list, `make_decoder`/`make_encoder`, and an opt-in `probe`), `CodecDescriptor` (with `profiles`, the codec profiles (`CodecProfile`) an implementation handles; a stated list excludes it from streams of any other profile, an empty one states nothing), `CodecProfile` (the typed variant key a stream, an encoder request and a descriptor share, with the `h264/high10` text form, and no profile identifier number in this crate), `EncoderConfig` (typed settings plus ordered provider options, an unknown key refused and never ignored), `Registry` (`with`/`prefer`/`fallback`/`select_with`, `list`/`providers`/`inventory`/`profiles`/`candidates`/`candidates_for`/`rejected_for`/`decoder`/`encoder`/`trimmed_decoder`), `CodecParameters::profile`, `CodecParameters::initial_padding`/`trailing_padding` (the container's gapless trim, audio-only, with `PaddingError`), `Packet`/`AudioFrame` per-packet `trim_start`/`trim_end`, `TrimStage` (the one trim application, with `CodecDescriptor::applies_trim` saying whether a decoder already did it), `ProfileError`/`ProfileRejection`, `ProviderInfo` (adapter and library version, the library's own licence), `Availability`/`Probe` (whether an implementation opens here), `InventoryEntry` and `render_inventory` (the run-time inventory, one line per entry and a whole-table renderer), `Preference` for one or both directions, optionally scoped to one profile, with a `FromStr`/`Display` text form (`h264/high10=libav`) and `parse_preferences` for a comma-separated list, and `Fallback::{Strict, NextCandidate}`. A format `CodecId` does not name is preferred and listed through the `other:<8 hex digits>` text form. The registry never probes unless the inventory is asked to, because opening a hardware codec has a cost. No static registry and no link-time self-registration (the `inventory`/`ctor`/`linkme` crates are banned): a registry is a value, so `transmux` or any other crate names no adapter. It holds no codec; the spike that proves the traits against symphonia lives outside the workspace in `spikes/` and reaches its decoder through a `Registry`. The API is 0.x and expected to change. `no_std`+`alloc`, depends only on `broadcast-core`; independently versioned.
- **broadcast-bitstream** — codec bitstream parsers and stream-format conversion below the muxing hub, so a consumer that only splits or classifies video need not take `transmux`. This first version is facts-only (a recorded exception in `docs/CRATE-ACCEPTANCE.md`): the exp-Golomb/RBSP reader on top of `broadcast_core::bits` (`bitreader`, `rbsp`), NAL classification with the crate's own `NalCodec`/`AvcNalUnitType`/`HevcNalUnitType`, key-frame/IRAP/RAP detection, the SEI walk and ATSC A/53 caption extraction (`nal`), Annex B and length-prefixed NAL iteration and conversion (`annexb`), the incremental `AccessUnitSplitter` whose open-NAL bound is the caller's (`au`), and the sequence parameter set layer (`sps`): `decode_avc_sps`/`decode_hevc_sps`/`decode_vvc_sps` with profile/tier/level, dimensions, chroma, bit depth and VUI timing, `decode_avc_vui_timing`/`decode_hevc_vui_timing`/`decode_hevc_vps_timing`, `decode_avc_reorder_depth`/`decode_avc_slice_sps`/`decode_hevc_interlace_sps`, `decode_ptl`/`is_high_profile`, and `decode_avc_display_facts`/`decode_hevc_display_facts` returning the public `SpsDisplayFacts` (private fields, accessors). The coded picture facts ship beside it in `facts` (`AspectRatioIdc`, `SampleAspectRatio`, `PictureRect`, `VideoFormat`, `ColourPrimaries`, `TransferCharacteristics`, `MatrixCoefficients`, `ColourDescription`, `VideoSignalType`, `ActiveFormatDescription`, `BarData`, `EXTENDED_SAR_IDC`: every one `#[non_exhaustive]`, private fields, accessors, spec label enums with `name()` + `Display`), and the per-codec strings in `rfc6381` (`rfc6381_avc1`/`hvc1`/`vvc1`, following their codec's feature, plus the ungated `rfc6381_mp4a`). The H.264 slice-header layer (`slice_header`, `h264`: `AvcSliceHeader`, `AvcSlicePps`, `AvcPicture`, `AvcFieldInfo`, the `AvcParamSets` cache, `decode_avc_slice_pps`, `parse_avc_slice_header`, `parse_slice`), the per-access-unit interlace facts (`interlace`: `VideoScan`, `PicStruct`, `SourceScanType`, `PictureFacts`, and the public `avc_facts`/`hevc_facts`), the HDR10+ ST 2094-40 model with its parser/serializer and builders (`hdr10plus`, `hevc`), the HDR10 static metadata with its SEI codec and `mdcv`/`clli` glue (`hdr`, `hevc` + `isobmff`), and the ISOBMFF configuration glue (`nalu_ext`, `codec_config_ext`, `avc_config_from_sps_pps`, all behind `isobmff`) ship beside them. The audio parsers follow in a later PR. `no_std`+`alloc`, depends only on `broadcast-core`, `thiserror` and `memchr`, optional `serde` and `isobmff` (the box-newtype glue and the HDR10 static metadata type); `h264`/`hevc`/`vvc` (all default) gate the per-codec NAL enums, SPS decoders, slice headers and HDR code. Its `Error` carries the shared kinds plus `OutputBufferTooSmall` and, behind `isobmff`, the box layer's error. `transmux` deletes the moved modules and imports them from here (no re-export). Independently versioned, unpublished.
- **dvb-si** — the big one: ETSI EN 300 468 Service Information + MPEG-2 PSI. All 29 allocated table_ids, descriptors, DSM-CC data carousel, Annex A text decoding. TS packet / section reassembly lives in `mpeg-ts` (used internally via the `ts` feature).
- **mpeg-ts** — generic MPEG-2 TS framing (ITU-T H.222.0 / ISO/IEC 13818-1): TS packet, adaptation field, PCR, PSI section reassembly + packetisation, resync. `no_std`. Independently versioned.
- **container-probe** — media container-format detection over a byte prefix (issue #960): MPEG-2 TS (a stride×phase lattice search across 188/192/204/208, so M2TS and mid-packet captures are found — the fixed-offset check in `transmux::cli::detect_container` this replaces missed both), ISOBMFF, Matroska/WebM, MPEG-PS, FLV, MXF, WAV, Ogg, ASF, and the ADTS/MP3/AnnexB elementary streams. **Every prober always runs and scores its evidence** (`CERTAIN`/`STRONG`/`STRUCTURAL`/`LATTICE_*`/`HEURISTIC`); the highest wins and a near-tie reports `Ambiguous` rather than silently picking, so the verdict never depends on declaration order. Scoring is structural, not magic-byte: a lane needs 50% sync *coverage* (a CENC MP4 aligned three `0x47`s by chance and was confidently misidentified without it) and an elementary stream needs a *frame-length chain* (one TS fixture carries 18 239 MP3 syncwords — 34× the real MP3 file). `Insufficient` ("read more") and `Unknown` ("stop") are distinct and load-bearing — `need_at_least` always exceeds the bytes *examined* (`min(len, budget)`, not `len`) and grows geometrically when no structural need can be named, so the documented caller loop converges in O(log n) reads rather than crawling; `DEFAULT_BUDGET` is public because a caller must feed the buffer length back as the budget for that loop to terminate. Needs no new spec transcription — every constant is reused from a sibling crate that round-trips real fixtures, pinned by a dev-dep drift guard. `no_std`+`alloc`, depends only on `broadcast-core`; independently versioned.

Field order and encoded width are the file's, so `serialize(parse(bytes)) == bytes` for real files and an untyped element round-trips as `Unknown`. `no_std`+`alloc`, depends only on `broadcast-core` and `broadcast-common`; `reader::Reader` is the sans-IO reader (`step`/`supply`, one Cluster header plus one Block header, unknown-size `Segment`/`Cluster` boundaries by sibling id, per-laced-frame byte ranges, `Info`/`Tracks`/`Cues`, Cues-driven `seek_to` with a cue-less Cluster index, permissive warnings), `writer::Writer` emits the EBML header, unknown-size `Segment`, `SeekHead`, `Info`, `Tracks`, Clusters by caller span/video keyframe/`i16` range, `Cues` and the `Info.Duration` patch as `Write::Append`/`Write::At` values, and `driver` (feature `std`) answers the reader's demands over `Read + Seek` and `Read` (retaining a header tail so a forward-only source never seeks back). `transmux`'s `MatroskaDemux` and its `MkvMuxStage` are the reader's and writer's first consumers; no EBML element ID is spelled outside this crate. Unpublished until `release-broadcast-matroska.yml` (tag `broadcast-matroska-v*`) runs; independently versioned.

and the still-image item layer, read and written: `item` (ISO/IEC 14496-12:2026 §8.11/§8.15: `iloc`, `iinf`/`infe`, `pitm`, `iref` with typed reference boxes, `iprp`/`ipco`/`ipma`, `idat`, `ipro`, `grpl`/`EntityToGroupBox`, `brnd`, `hdlp`), `image` (ISO/IEC 23008-12:2017 clause 6 with its 2020 corrigendum, and AVIF v1.2.0: `ispe`/`pixi`/`rloc`/`auxC`/`irot`/`lsel`/`imir`, the `grid`/`iovl`/`iden` bodies, `a1op`/`a1lx` and the still-image brands; `pasp`/`colr`/`clap`/`hvcC`/`avcC`/`av1C`/`mdcv`/`clli` are the crate's existing types), `item_reader` (sans-IO `ItemReader`: asks for top-level headers, the file-level `meta` and the tiny derived-item bodies, yields `StillImage` with brands, primary item, every item's type/name/hidden flag/protection/properties/references/resolved data ranges and entity groups, plus image size/rotation/mirroring/thumbnails/auxiliary images/grid tiles/overlay layers/Exif/XMP convenience, and a byte-exact `reemit_plan`), and `item_writer` (`ItemWriter` builds a file from typed parts and chooses the `iloc` widths and offsets). `reader` is the sans-IO state machine (`step`/`supply`, `Step::{Need, Tracks, Metadata, Fragment, Sample, Warning, Done}`, `TrackCursor` over the raw tables, `seek_to` through `stss`/`sidx`/`mfra`, `Mode::Permissive`); - **transmux-py** (`bindings/transmux-py/`) — PyO3/maturin Python bindings over the **published** transmux: `demux_ts(bytes)->dict` exposing that version's `Media`/`Track`/`Sample` IR (codec identity/RFC 6381 string, timescale, opaque coded sample bytes) for ML/analysis front-ends (docs/IDEAS.md item #7). The library itself no longer has a whole-input type; this binding cannot move before a transmux release. Hand-converts Rust structs to `PyDict`s field-by-field (transmux's pipeline IR carries no `serde::Serialize`, unlike dvb-si-py's json round-trip). NOT a workspace member (own MSRV); consumes published transmux by version; abi3 wheels to PyPI via its own workflow.

MSRV is **1.95.0** (workspace `rust-version`, inherited by every member via `rust-version.workspace = true`); the committed `Cargo.lock` pins MSRV-compatible deps — always build/test with `--locked`.

## Workflow: GitHub issues drive the work

Work in this repo is tracked as GitHub issues and lands via PRs to `main`. Use the `gh` CLI.

1. **Pick up work from an issue.** `gh issue list` to see open work; `gh issue view <n>` for the spec/acceptance criteria. If you're asked to do something non-trivial that has no issue, create one first (`gh issue create`) so the work is tracked.
2. **Branch per issue** off `main`, named for the work (e.g. `complete-descriptors`, `fix-tot-crc`).
3. **Commit style** follows the existing history: `feat(carousel): …`, `fix(text): …`, `docs(dvb-si): …`, or a plain scoped summary. Imperative, specific, references the spec section when relevant.
4. **Open a PR** with `gh pr create`, body referencing the issue (`Closes #n`). CI must pass before merge:
   - tests on the pinned MSRV 1.95.0 only (there is no stable test lane; a pinned newer-stable clippy canary is non-blocking) — the all-features suite runs under nextest with the `[profile.ci]` Cargo profile; the no-default-features lane is the `cargo build --workspace --no-default-features` gate, a per-crate `cargo check --tests` of every member (`tools/check-bare-features.sh`, so feature unification cannot hide a break; a crate declaring `no_std` is also checked with no features at all, so its test modules compile against `alloc` alone or are gated on `std`; and every optional feature of multimux is built by itself, so a stale import or an item left dead when one feature is off cannot hide behind `--all-features`), and a bare *run* of only the code that differs without default features (the serde-off dvb-si/dvb-t2mi registries, and the doctests of the feature-gated crates) — it no longer re-runs the whole suite
   - markdown-only PRs (nothing but non-README `.md`, see `tools/ci_changes.py`) skip every job except `lint`, `docs` and the cheap prep jobs; skipped jobs still report, so a required check is satisfied
   - fuzz targets all build on every PR and each runs for a 10 s smoke budget (4 shards); the 60 s budget and the full-length soak tests (`RUST_BROADCAST_SOAK=1`) run in `.github/workflows/nightly.yml` (daily + `workflow_dispatch`)
   - `cargo fmt --all --check`
   - clippy `-D warnings` on all targets
   - doc build with `RUSTDOCFLAGS="-D warnings"`
5. **Releases are tag-driven and CI-only.** Bump all **five** lockstep crate versions together (`dvb-si`, `dvb-t2mi`, `dvb-bbframe`, `dvb-conformance`, `dvb-tools`), merge, then push a `v<version>` tag — `release.yml` gates (tests, clippy, tag==version check) and publishes to crates.io in dependency order (`dvb-bbframe` first). **`broadcast-common` is NOT in the lockstep** — it versions on its own API changes and ships from its own `broadcast-common-v*` tag (`release-broadcast-common.yml`). If a wave moves it too, publish `broadcast-common-v<x>` FIRST and let it go live before the `v<y>` tag. `dvb-stream`, `scte35-splice`, `isobmff` and the other independent crates release on their own cadence or not at all. **Never `cargo publish` from a workstation.**

Run its **per-release checklist** each tag (CHANGELOG → release note → README coverage → crate-root `//!` → Cargo.toml + docs.rs metadata sweep → GitHub Release → post-publish verify docs.rs built green). This is enforced like the gate suite.
6b. **Every NEW crate clears** [`docs/CRATE-ACCEPTANCE.md`](docs/CRATE-ACCEPTANCE.md) — the consolidated new-crate hard bar (round-trip invariant, no raw-byte API, real-fixture biting tests, verified-source/no-fabrication discipline, 6-gate suite, #204 labels, fuzz, >=2 examples, full RELEASE-DOCS). A **living standard**: tighten it whenever a new failure mode appears.

Companion to the doc standard above; [`AUDIT-LEDGER.md`](docs/AUDIT-LEDGER.md) records which PDF→md fidelity audits are already done.

## Workflow: the delegated-engineering loop

Token-heavy authoring is delegated to DeepSeek (via the `delegate` skill → headless `opencode`); Claude stays the orchestrator, auditor, and release engineer. **Claude never marks a story done on the delegate's say-so** — only on its own fresh gate evidence.

**Claude owns (does NOT delegate):** story ordering (by dependency then value-for-effort), version semantics (patch = fixes only, minor = additive API, major = breaking; lockstep across the five lockstep crates, with `broadcast-common` versioned independently). **Changing which caret-epoch of a workspace sibling a crate builds against is a major-class change in that crate** — minor for 0.x, major for >=1.0 — because a caret bucket spanning two epochs breaks consumers of BOTH the new and the old line (#858). Every published bucket stays epoch-pure, release bundling (batch related additive stories into one minor; ship breaking/urgent work standalone), and the correctness of every CHANGELOG, `docs/release-notes/vX.Y.Z.md`, README coverage table, module spec-citation, and example/doctest.

**Per-story loop:**

1. **Scope** — read the issue's acceptance criteria and the cited `docs/` transcription. Resolve any design ambiguity *before* delegating (the delegate sees only the brief, none of this context).
2. **Baseline** — branch `story/<n>-<slug>` off `main`; commit any in-flight working state first, so the delegate's `git diff` is cleanly attributable.
   - **Prep the gate's inputs BEFORE delegating** (spec/parser work): transcribe the spec syntax tables into the private repo at `private/specs-verified/<family>/<crate>/` (never into the public tree), AND commit a **real fixture** (extract from an existing capture — e.g. scan committed `.ts` for the signature — pull a TSDuck stream, or use spec test vectors). Inline hand-made bytes only test the happy path; real data carries the reserved bits / mixed stream_ids / real layouts that expose bugs. No spec md + no real fixture = do not delegate yet. Fixture homes: public `fixtures/` (permissive, with PROVENANCE) or `private/fixtures/<topic>/` (private repo, PROVENANCE, LFS >50 MB) — a brief must NEVER tell a delegate a fixture is "local-only", "gitignored" or "on this machine", and tests load fixtures only through `test_fixtures`.
3. **Delegate** — write a self-contained brief (exact files, decided behaviour/signatures, the project conventions that apply, the exact gate commands, and "fix until all pass before finishing"; boundaries: touch only <scope>, do not commit). Run in the background. The brief's exit gate must be **ungameable** and include a **real-fixture run** (parse + byte-exact round-trip the committed fixture) — a plain round-trip test is gameable by raw-passthrough serialize, and a green inline suite is not "done". Pass these gates in round ONE, never bolt them on after burning a round.
4. **Audit** — judge by `git diff` + running the **full gate suite yourself** (see Commands), never by the delegate's stdout (often empty on success) or its claims. Then check line-by-line against every AC and the hard invariants (symmetric serialize + round-trip test, no magic numbers outside `#[cfg(test)]`, spec citation in the module doc, `--no-default-features` builds, feature-gating). If a delegated test doesn't *bite*, reject or rewrite it — Claude owns verification.
5. **Drive fixes** — feed concrete findings back via `opencode run --continue` (same session keeps context). After 2 failed fix cycles on the same point, take over and finish it directly.
6. **Repeat 4–5** until every gate is green *and* every AC is met, on Claude's own run.
7. **Ship** — update CHANGELOG/release-note/README/examples; branch→PR (`Closes #n`)→CI green→merge; then the lockstep version bump + `v<version>` tag (per the tag-driven release rule above). Verify all five lockstep crates went live (plus `broadcast-common` and any other independent crates in the same release).

**Continuous improvement:** treat this loop as living. When a brief pattern, gate ordering, or audit check repeatedly saves (or costs) time, refine this section and say so in the turn. Recurring delegate failure modes belong in the brief template, not rediscovered each story.

## Architecture

### The Parse/Serialize contract (broadcast-core/src/traits.rs)

Every wire structure in every crate implements the same symmetric pair:

- `Parse<'a>` — `parse(&'a [u8]) -> Result<Self>`, borrowing from the input (zero-copy: parsed structs hold `&'a [u8]` slices and carry `<'a>` lifetimes).
- `Serialize` — `serialized_len()` + `serialize_into(&mut [u8])`.

Every parser has a symmetric serializer and a **round-trip test** (parse → serialize → byte-identical, and serialize → parse → equal). This symmetry is a hard project invariant.

### dvb-si layout

- `tables/` — one file per table (pat, pmt, sdt, eit, nit, …). Tables expose typed header fields; descriptor loops are borrowed `&[u8]` slices the caller walks with the descriptor parsers.
- `descriptors/` — one file per descriptor tag. Each module exports a `TAG` const, length consts, a `XxxDescriptor<'a>` struct, and the Parse/Serialize impls. `descriptors/any.rs` defines `AnyDescriptor` + `parse_loop` (the lazy descriptor-loop walker); `descriptors/registry.rs` adds `DescriptorRegistry` for private tags.
- `carousel/` — DSM-CC DSI/DII/DDB messages + `ModuleReassembler`, layered on `tables/dsmcc.rs` section framing.
- `text/` — EN 300 468 Annex A string decoding. `DvbText<'a>` wraps raw wire bytes and decodes on demand (`.decode()`/`Display`/serde); `LangCode` is the 3-byte language/country newtype. Serde serializes both as decoded strings; `DvbText`-bearing structs are serialize-only.
- `demux.rs` (feature `ts`) — `SiDemux`: PID-filtered, version-gated, PAT-following section pump. Feed 188-byte TS packets, get a `SectionEvent` per *changed* section; `event.table_section()` gives an `AnyTableSection`. `section.rs`/`ts.rs` provide the underlying TS packet handling and `SectionReassembler`.
- Features: `jiff` (MJD+BCD → `jiff::Timestamp`, BCD offsets → `jiff::SignedDuration`, the `epg` module), `ts` and `legacy-charsets` (KS X 1001 / GB-2312 / Big5 text via `encoding_rs`; off → `DvbText::try_decode` returns `Error::CharsetNotEnabled`) are on by default, `serde` is opt-in (as in every crate); everything must also build `--no-default-features`.

### Trait-driven dispatch (the `*Def` trait + `declare_*!` macro pattern)

Each crate's unified dispatch enum — `dvb_si` `AnyTableSection`/`AnyDescriptor`,
`dvb_t2mi` `AnyPayload` — is generated from a single declarative list (the
`declare_tables!` / `declare_descriptors!` / `declare_payloads!` macro). One line
per type produces the enum variant, the `From<T>` impl, the dispatcher arm, and a
**drift test** that pins each table_id/tag/packet_type literal to the type's
`TableDef`/`DescriptorDef`/`PayloadDef` trait const (`TABLE_ID_RANGES`/`TAG`/
`PACKET_TYPE` + a SCREAMING_SNAKE `NAME`). The list is the single source of truth,
so the dispatcher can never silently drift from the implemented set. To add a
type: implement the module + the `*Def` trait, then add one line to the macro
invocation — the integration completeness test walks the generated set
automatically.

The runnable analyzer CLI (the `dvb-tools` binary crate — `dump` / `services` /
`epg` / `pids` / `t2mi` subcommands) wires the pump → dispatch → decode story
together. All CLIs follow the workspace **CLI standard** ([`docs/CLI-STANDARD.md`](docs/CLI-STANDARD.md)):
`clap` derive, named flags (no bare positional magic numbers), auto
`--help`/`--version`. `ci-probe` (the `dvb-ci-runtime` CAM tool) follows the same
standard.

### Spec grounding (the project's defining discipline)

- Vendored spec PDFs (ETSI/ISO/ITU-T/SCTE/ATSC/DVB) + non-redistributable test media live in the **private git submodule `private/`** (repo `rust-broadcast-private`) — PDFs at `private/specs/*.pdf`, fixtures at `private/fixtures/<topic>/` (the layout rule, topic list and golden placement are in `docs/FIXTURES.md`; each topic carries a `PROVENANCE.md`; no file over 50 MB and no Git LFS: the 187/352 MB France TNT / Hot Bird captures are kept as deterministic excerpts — `*-si-audio.ts`/`*-si.ts` (whole capture, video dropped; for SI/EIT/audio tests only) and `*-video-head-6-mb.ts`/`*-video-w30-mb-10-mb.ts` (video intact; for demux/PPS/TR 101 290 tests) — made by `tools/make-fixture-excerpts.py`, source SHA-256 in `private/fixtures/ts/PROVENANCE.md`). **There is no "local-only" fixture tier**: a capture that is not redistributable, has an unclear licence, or was live-captured goes in the private repo, never in an untracked directory; tests read only `fixtures/` and `private/fixtures/` (the tsduck-test files they use are mirrored under `private/fixtures/suites/tsduck/`); `tools/fetch-test-streams.sh` fetches the big source captures (`russia-t2mi-scte35`, 4.9 GB; the full France TNT / Hot Bird captures) only to regenerate the private excerpts, never for a test. Tests never hand-build fixture paths — they go through `test_fixtures`. Run `git submodule update --init private` to fetch (maintainers only; public/CI clones skip it and dependent tests skip cleanly). The public tree holds **no spec material at all**: RFC/IETF/W3C/ID3 texts, curated rule files, manifests, and every crate's spec transcriptions, notes, clause maps and registries (`enums/**/*.toml`, `allocations.tsv`, …) live in the private repo, and there is no free-licence exception (RFCs and W3C included). Syntax tables are machine-extracted into reviewable markdown under `private/specs-verified/dvb/` by `tools/dvb-si-audit/` (deterministic pdfplumber pipeline — see its README to regenerate). **ALL spec material lives ONLY in the private repo** (`private/specs-verified/<family>/<owner>/`). The public tree keeps code, tests, examples, READMEs, CHANGELOGs, release notes, design docs about our own code. Tests and tools that need spec text or registries load them at runtime through `test_fixtures::spec`/`spec_string` (or the `private/` checkout) and skip loudly when private is absent (`SKIP_PRIVATE_FIXTURES=1` or no checkout; a missing entry in a present checkout, or `REQUIRE_PRIVATE_FIXTURES=1` without a checkout, is a hard failure) — never `include_str!` a spec file. **How to cite:** code and docs cite the private path directly (`private/specs/<file>` for PDFs and texts, `private/specs-verified/<family>/<owner>/<file>.md` for transcriptions) plus the clause or table; there is no map. Never paste standards text, or own-words spec notes, into a public file.
- **Every layout is cited**: module doc comments name the spec, section, and tag/table_id (e.g. `//! Network Name Descriptor — ETSI EN 300 468 §6.2.28 (tag 0x40)`). When implementing or changing a layout, read the corresponding transcription under `private/specs-verified/dvb/` first and cite it.
- **No magic numbers** outside `#[cfg(test)]`: every numeric literal other than `0` and `1` is a named constant or enum, enforced by the `magic_numbers` guard.
- **Lexical guards live in ONE crate, `workspace-guards`, not in per-crate test files.** Each guard family (`non_exhaustive`, `label`, `truncation`, `clock33`, `magic_numbers`, `one_box_home`, the three de-hand-roll shapes, `secret_debug`, `panic_idioms`, `serialize_mask`, `no_dom`, `lint_suppressions`, `bounded_input`) is one module under `workspace-guards/tests/guards/` with a per-crate data table (`*_data.rs`): the crate name plus its own SKIP list / allowlist / pinned expected-enum set, every entry carrying its reason. **A new crate adds a line to each table that applies to it; it does not copy a test file.** Each table has an `EXEMPT` list or a documented scope, and a `table_covers_every_workspace_member` test fails if a workspace member is in neither, so a new crate cannot silently skip the guards. The de-hand-roll tripwire (spec §5: `"HTTP/1.`, `"\r\n\r\n"`, `find("://")`, `strip_prefix("<scheme>://")`, SDP `"a=`/`"m=`/`"v=0` building, `civil_from_days`/`days_from_civil`, a base64 alphabet literal, `thread::sleep`/`sleep(` in non-test async code) has three scanner shapes in `handroll_data.rs`: shape 1 (`broadcast-common`, `broadcast-auth`, `scte35-splice`, `timed-metadata`, `transmux`), shape 2 with pattern+line-pinned allowlist (`dvb-ci-runtime`, `media-doctor`, `media-plane`) and shape 3 with a needle list plus per-crate `extra` needles (`hls-runtime`, `srt-runtime`, `webrtc-runtime`, `broadcast-client`, `dash-runtime`, `dvb-stream`, `rtmp-runtime`). Shape 3 and every crate that keeps its own guard share one lexer, `workspace_guards::scan::non_test_source` (a dev-dependency, never a copy). `multimux` (pinned line ranges, dash-pull clock guard) and `rtsp-runtime` (header-tokeniser and char-iteration checks) keep their own `tests/it/no_handroll_guard.rs` for those extra checks only (`multimux` also `multimux/tests/it/harness_guard.rs`). `panic_idioms` bans `.unwrap()`/`.expect(`/`panic!`/`unreachable!`/`todo!`/`unimplemented!` in non-test code of the parse/serialize/convert crates in its table; `serialize_mask` bans a single-field `& MASK` / bare `<<` in a serializer (use `fit_mask`), with line-pinned reasoned allowlists; `no_dom` bans an XML tree type, an entity literal or a hand-written escaper in the crates that touch XML (`dvb-mabr`, `media-doctor`, `multimux`, `transmux`, `ttml-subtitle`). `bounded_input` bans `fs::read`/`fs::read_to_string`/`read_to_end`/`read_to_string` (and their `tokio::fs` forms), the whole-input `transmux::Media`/`transmux::Track` IR, the deleted `broadcast_common::mux` paths and the dev-only `test_harness` in every member's non-test `src/` and `examples/` (plus `demo/` and `tools/differential-sweep/`), with only the body of `broadcast-common/src/bounded.rs` allowlisted. `one_box_home` bans an ISO BMFF box-type four-CC byte literal (or its `[u8; 4]` byte-char form) and a local re-declaration of a `isobmff::box_types` header size/sentinel in every crate except `isobmff`, with `container-probe`'s own mini-walk allowlisted line by line (it must depend only on broadcast-common at runtime; its dev-only drift tests pin it to `isobmff`). `magic_numbers` bans any numeric literal other than `0` and `1` in production code outside a `const`/`static` definition, an enum discriminant, a spec-code table row or arm, and test code (the `#[cfg(test)]` items, test-only module files, `tests.rs`/`*_tests.rs`/`testutil`/`test_support` and `src/tests/`), with a line-pinned reasoned allowlist; it also flags a constant whose name encodes its value (`BIT3_SHIFT`, `BYTE_2_MASK`). These three are scoped to their table (a `table_names_are_workspace_members` test catches a rename), not to every member. The `spec_drift` tests stay per crate (they compare the crate's own enums against the private TOML mirrors) and share only the parser, `test_fixtures::parse_spec_entries`. `clock33` bans `abs_diff` and any literal 2^33 (`1 << 33`, `0x2_0000_0000`, `8_589_934_592`) outside `#[cfg(test)]` so 33-bit PTS/DTS/`pts_time` wrap arithmetic stays in `broadcast_common::clock33` (line-pinned, reasoned allowlist; lexical, not a proof); its table is `transmux`, `ssai-runtime`, `playout-runtime`, `timed-metadata`, `scte35-splice`, `compliance-probe`, `media-doctor`, `dvb-si`, `dvb-conformance`, `dvb-tools`, `buffering-runtime` and `ts-fix` (the Green_Access_Unit / Quality_Access_Unit marker-coded 33-bit timestamps go through `broadcast_common::clock33::{unpack_marked, pack_marked}`). `dvb-si` keeps its own `workspace-guards/tests/guards/truncation.rs` (a different detector scoped to `descriptors/`/`tables/`/`carousel/`); `transmux`'s lexical half is a `truncation` table entry and its `tests/it/serializer_length_truncation.rs` keeps only the behavioural box-range tests that need the crate's types. Run one family with `cargo test -p workspace-guards --test guards <family>::`. A tripwire is lexical, not a proof — a renamed helper evades it, so code review is the real control (see `docs/CRATE-ACCEPTANCE.md`).
- Every field in a section's syntax appears in the parsed struct (spec fidelity).
- Fixture tests (`dvb-si/tests/`) validate against real broadcast captures; round-trip and serde round-trip tests are required for new types.

### API conventions

Every public API follows [`docs/API-CONVENTIONS.md`](docs/API-CONVENTIONS.md) (time types, typed ids, config shape, typed errors, surface rules). Read it before adding or changing a public API; a change that settles a new convention updates it in the same PR.

### Error conventions

Structured `thiserror` errors with context: `BufferTooShort { need, have, what }`, `InvalidDescriptor { tag, reason }`, etc. Parsers validate the tag byte and length before slicing; serializers check `OutputBufferTooSmall` first. Reserved-bit policy varies by crate and is documented at the crate root (e.g. dvb-t2mi rejects non-zero RFU bits except individual addressing).

### Spec/field-enum label convention (every public enum — #204)

Every public spec/field enum across all crates exposes a uniform label pair:

- **`pub fn name(&self) -> &'static str`** — inherent method, hand-written
  `match` arms (labels live in source, next to the variant docs; the spec token
  for known variants, `"reserved"` for the reserved/unknown arm).
- **`Display`** — generated by `broadcast_core::impl_spec_display!`, a label-free
  macro that delegates to `name()`. `impl_spec_display!(Ty)` makes `Display ==
  name()`; `impl_spec_display!(Ty, Reserved, …)` renders each named byte-bearing
  catch-all as `"{name}(0x{:02X})"` so `Display` stays lossless.

Labels are NEVER put in the macro — only in `name()`. The `label` guard in
`workspace-guards` scans each crate's `src/` and fails CI if any public
`pub enum` (minus the crate's documented SKIP list in
`workspace-guards/tests/guards/label_data.rs`: errors, `Any*`/tag dispatch enums,
section-kind discriminants, data-carrying ADTs) lacks a `Display`. So a **new
spec/field enum must get `name()` + `impl_spec_display!(...)`**, or be added to
that crate's SKIP entry if it is genuinely not a label.

### Adding a descriptor/table (the recurring task)

Follow an existing implemented module (e.g. `descriptors/network_name.rs`) exactly: spec-cited module doc → `TAG`/length consts → borrowed struct with `#[cfg_attr(feature = "serde", …)]` (+ `serde(borrow)` on slices) → `Parse` with tag + length validation → symmetric `Serialize` → unit tests in-module + round-trip coverage. All 115 `src/descriptors/` and 31 `src/tables/` files now carry real types — no doc-only stub modules remain (the `complete-descriptors` push finished); this section documents the pattern for the next new descriptor/table, not a backlog. Serializers must write every length and count through the shared checked helper (`descriptors::write_descriptor_header` for the outer tag+length, `broadcast_core::len::fit_u8`/`fit_u16`/`fit_bits` for everything else) — never with `as u8`/`as u16` or a bitmask, which silently wraps an over-range value into a misframed descriptor (#1129).
